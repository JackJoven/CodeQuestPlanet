# PRD v0.6：全学段 AI 开发能力课程体系

## 1. 版本目标

本版本把前面讨论的长期愿景沉淀为一套“全学段课程天梯”，用于回答三个问题：

1. 如果未来要覆盖更宽年龄段，每个学段到底学什么。
2. 哪些能力应该在学生阶段重点训练，哪些真实开发能力只需要了解或后置。
3. 当前 10-14 岁游戏编程 MVP 如何向后续 AI 协同开发能力自然衔接，而不是做成一个孤立课程。

本版本不是要求当前产品一次性做完全学段，而是给产品和课程长期迭代提供路线图。

当前开发仍以 `10-14 岁 / 6 课 MVP / Phaser 游戏编程 / 自研规则平台 / AI 伴学` 为第一验证目标。

## 2. 与已有 PRD 的关系

| 版本 | 关系 |
|---|---|
| v0.1 | 仍成立：第一版不做全学段覆盖，先验证 10-14 岁学生自学游戏编程闭环。 |
| v0.2 | 仍成立：6 课 MVP 是全学段体系里的“主学段第一模块”。 |
| v0.3 | 仍成立：评价体系继续使用作品、过程、AI 协作、展示表达作为核心证据。 |
| v0.4 | 仍成立：第 1、2 关重设计属于 MVP 课程体验优化。 |
| v0.5 | 仍成立：自学引导增强是“少老师/无老师”模式的关键产品能力。 |

本版本新增的是长期课程架构，不直接扩大当前 MVP 开发范围。

## 3. 核心判断

### 3.1 最终目标需要分层

“用 AI 工具完成真实软件、游戏、产品开发”可以作为最终远景，但不应该直接成为低龄学生的近期目标。

更合理的分层是：

| 学段 | 合理目标 |
|---|---|
| 6-8 岁 | 对创作产生兴趣，知道游戏/动画由规则驱动。 |
| 8-10 岁 | 能用可视化规则表达事件、条件、变量和循环。 |
| 10-14 岁 | 能做出可玩的 2D 游戏，理解核心编程概念，并学会基础 AI 协作。 |
| 14-17 岁 | 能用代码和 AI 做真实小应用/小游戏，开始理解工程流程。 |
| 17 岁以上/成人 | 能完成较完整的软件/游戏/AI 产品开发，理解部署、数据、安全、评测和迭代。 |

### 3.2 学生阶段不追求“全栈工程师”

很多真实产品能力很重要，但对学生早期太远：

| 能力 | 学生阶段处理方式 |
|---|---|
| 复杂后端架构 | 先了解请求、数据保存和接口概念，后置深入。 |
| 数据库设计 | 先理解“数据表/记录/保存”，不讲索引、事务、分库等。 |
| 云部署和 DevOps | 先体验发布作品链接，后置 CI/CD、监控、回滚。 |
| AI Agent/RAG/评测 | 高中后或进阶阶段再系统学习，早期只体验 AI 伴学和提示。 |
| 安全攻防 | 早期讲账号隐私和版权，后期讲注入、权限、提示注入等。 |
| 竞赛算法 | 主线只学算法思维，竞赛算法作为选修路线。 |

### 3.3 不再以死记语法为主线

AI 时代仍然需要学编程，但重点应从“背固定语句”转向：

- 能把目标拆成规则。
- 能读懂代码大意。
- 能判断 AI 生成的代码是否符合目标。
- 能运行、测试、调试和验证。
- 能维护一个逐步变复杂的作品。
- 能表达自己的设计意图和取舍。

语法仍然要学，但应该在作品里按需出现，而不是脱离场景死背。

## 4. 全学段能力模型

平台长期培养 10 类能力。

| 能力 | 说明 | 何时重点培养 |
|---|---|---|
| 创作兴趣 | 愿意做自己的动画、游戏和工具 | 6-8 岁开始 |
| 规则表达 | 用“当/如果/就”描述逻辑 | 6-10 岁重点 |
| 编程概念 | 事件、变量、条件、循环、函数、状态、对象 | 8-14 岁重点 |
| 代码识读 | 能看懂伪代码和基础真实代码 | 10-14 岁开始 |
| 调试验证 | 能复现问题、猜测原因、验证修复 | 10-14 岁重点 |
| AI 协作 | 会描述目标、现象、限制和验证结果 | 10 岁以上持续 |
| 算法思维 | 搜索、排序、路径、状态机、复杂度直觉 | 10 岁以上渐进 |
| 工程习惯 | Git、版本、模块、测试、文档、复盘 | 14 岁以上重点 |
| 产品思维 | 用户、体验、反馈、迭代、展示 | 10 岁以上渐进 |
| AI 产品开发 | AI API、Agent、RAG、评测、安全、部署 | 17 岁以上重点 |

## 5. 总体课程结构

长期课程建议分为 5 个学段、约 `108 节核心课`，另设算法、竞赛、3D、AI 产品等选修课。

| 阶段 | 年龄 | 名称 | 核心课时 | 主要产出 |
|---|---:|---|---:|---|
| L0 | 6-8 | AI 创作启蒙 | 12 节 | 互动故事/小动画 |
| L1 | 8-10 | 规则编程入门 | 16 节 | 闯关小游戏作品集 |
| L2 | 10-14 | AI 游戏编程主线 | 24 节 | 可展示 2D 游戏 |
| L3 | 14-17 | 真实应用与游戏开发 | 32 节 | 可发布小产品/小游戏 |
| L4 | 17+/成人 | AI 原生开发进阶 | 24 节 | 可上线 AI 工具或游戏产品 |

当前 MVP 对应 L2 的第 1-6 节。

## 6. L0：AI 创作启蒙

目标年龄：6-8 岁。

建议课时：12 节，每节 35-45 分钟。

核心目标：

- 激发兴趣，不强调“学代码”。
- 建立“角色、动作、规则、结果”的直觉。
- 让孩子知道 AI 可以陪我想故事、做角色、给提示，但不是替我创作。

不急着学：

- 真实语法。
- 复杂变量。
- 抽象算法。
- 文件、项目、工程结构。

AI 角色：

- 故事伙伴。
- 角色命名助手。
- 提示教练。
- 不直接完成作品。

### 6.1 L0 课程表

| 课次 | 主题 | 学什么 | 作品/任务 |
|---|---|---|---|
| L0-01 | 我的第一个会动角色 | 角色、舞台、动作 | 让一个角色走到星星旁边 |
| L0-02 | 按一下就发生 | 事件、按钮、触发 | 点击按钮让角色变表情 |
| L0-03 | 会说话的角色 | 顺序、台词、等待 | 做一段两句对话 |
| L0-04 | 找到宝藏 | 目标、胜利反馈 | 角色碰到宝藏后庆祝 |
| L0-05 | 小怪兽来了 | 规则、结果 | 碰到怪兽会后退 |
| L0-06 | 选择一条路 | 简单条件 | 选左路/右路出现不同结局 |
| L0-07 | 重复跳舞 | 重复动作 | 让角色循环跳舞 3 次 |
| L0-08 | 我的小游戏按钮 | 输入和反馈 | 点按钮加一颗星 |
| L0-09 | 让 AI 帮我想角色 | AI 辅助创意 | 让 AI 给 3 个角色名字，学生选一个 |
| L0-10 | 发现哪里坏了 | 初级调试 | 找出角色为什么没动 |
| L0-11 | 我的小故事关卡 | 综合规则 | 做一个有开始和结尾的互动故事 |
| L0-12 | 小小创作者展示 | 表达展示 | 给家长演示并说出 2 条规则 |

### 6.2 L0 阶段评价

通过标准：

- 能说出作品里的角色和目标。
- 能理解“我做了一个规则，所以画面发生变化”。
- 能在提示下完成一个互动作品。

家长可见成果：

```text
孩子已经不是只看动画，而是能让角色根据自己的规则行动。
```

## 7. L1：规则编程入门

目标年龄：8-10 岁。

建议课时：16 节，每节 45-60 分钟。

核心目标：

- 以自研规则编辑器为主，不依赖 Scratch。
- 从“玩游戏”过渡到“改规则”。
- 理解事件、变量、条件、循环、碰撞的基础意义。

不急着学：

- 大量真实代码输入。
- 复杂函数封装。
- 后端、数据库、部署。
- 竞赛算法。

AI 角色：

- 任务向导。
- 概念解释员。
- 小提示教练。

### 7.1 L1 课程表

| 课次 | 主题 | 学什么 | 作品/任务 |
|---|---|---|---|
| L1-01 | 游戏是由规则组成的 | 规则、对象、动作 | 拆解一个小游戏的 3 条规则 |
| L1-02 | 当按键发生 | 事件、输入 | 让角色左右移动 |
| L1-03 | 坐标让角色换位置 | x/y 坐标 | 把角色送到目标点 |
| L1-04 | 变量是游戏记忆 | 分数变量 | 吃 3 个金币加分 |
| L1-05 | 屏幕显示来自变量 | UI 显示 | 让屏幕分数同步变化 |
| L1-06 | 如果碰到了就发生 | 条件、碰撞 | 碰到宝石加分，碰到怪物扣血 |
| L1-07 | 重复出现的东西 | 循环、定时 | 金币每隔几秒出现 |
| L1-08 | 随机让游戏不一样 | 随机位置 | 让宝物随机出现 |
| L1-09 | 生命值和失败 | 状态、失败条件 | 血量为 0 游戏结束 |
| L1-10 | 胜利条件 | 目标判断 | 分数达到 10 通关 |
| L1-11 | 找 bug 小侦探 | 观察、猜测、验证 | 修复一个分数不变的关卡 |
| L1-12 | 让 AI 给提示 | AI 提问格式 | 描述“目标/现象/猜测” |
| L1-13 | 改数值改变手感 | 参数、平衡 | 调整速度、分数、时间 |
| L1-14 | 做一关自己的挑战 | 关卡设计 | 自己摆放金币和障碍 |
| L1-15 | 作品打磨 | 反馈、难度 | 给作品加标题、提示和胜负反馈 |
| L1-16 | 规则作品展 | 展示表达 | 展示作品并讲清 3 条规则 |

### 7.2 L1 阶段评价

通过标准：

- 能用“当/如果/就”说出至少 3 条游戏规则。
- 能解释分数、血量或倒计时中的一个变量。
- 能在 AI 提示下修复一个简单 bug。

家长可见成果：

```text
孩子能把游戏玩法拆成规则，并能修改规则让游戏产生不同结果。
```

## 8. L2：AI 游戏编程主线

目标年龄：10-14 岁。

建议课时：24 节，每节 60-90 分钟。

核心目标：

- 做出完整 2D 游戏。
- 理解核心编程概念。
- 从规则编辑器过渡到伪代码和简单真实代码。
- 学会基础 AI 协作：描述目标、描述现象、限制帮助、运行验证。

不急着学：

- 完整全栈开发。
- 复杂框架生态。
- 大型 3D 游戏。
- 生产级后端。
- 深度 AI Agent 系统。

AI 角色：

- 伴学教练。
- 调试伙伴。
- 代码翻译员。
- 复盘追问者。

### 8.1 L2 模块结构

| 模块 | 课时 | 目标 |
|---|---:|---|
| M1：控制与基础状态 | 6 节 | 对应当前 MVP，验证游戏编程学习闭环。 |
| M2：关卡系统与游戏手感 | 6 节 | 从能玩到好玩，加入地图、节奏、难度。 |
| M3：代码过渡与 AI 协作 | 6 节 | 学会读代码、改代码、和 AI 一起调试。 |
| M4：毕业作品与展示 | 6 节 | 完成一个可展示的原创小游戏。 |

### 8.2 L2 课程表

| 课次 | 主题 | 学什么 | 作品/任务 |
|---|---|---|---|
| L2-01 | 控制诊断场 | 事件、坐标、速度 | 修复角色移动，并解释输入到移动的链路 |
| L2-02 | 分数侦探局 | 变量、UI 同步、状态 | 修复分数变量和屏幕显示 |
| L2-03 | 碰撞与结果 | 条件、碰撞、状态变化 | 子弹命中/吃金币/碰怪物产生结果 |
| L2-04 | 自动生成系统 | 循环、定时器、随机 | 自动生成敌人、金币或机关 |
| L2-05 | 设计一个技能 | 函数、参数、冷却 | 做强化子弹、冲刺或二段跳 |
| L2-06 | 第一款小游戏 | 综合规则、复盘 | 完成 MVP 毕业小游戏 |
| L2-07 | 关卡地图怎么设计 | 地图、目标路线 | 设计一张有开始和终点的关卡 |
| L2-08 | 游戏手感调校 | 速度、加速度、反馈 | 调整移动、跳跃或射击手感 |
| L2-09 | 敌人行为 | 状态机、简单 AI | 敌人巡逻、追踪或发射 |
| L2-10 | 道具系统 | 数据、效果、持续时间 | 做加速、护盾、回血或双倍分数 |
| L2-11 | 难度曲线 | 数值、节奏、平衡 | 让游戏从简单逐渐变难 |
| L2-12 | 小型关卡包 | 作品结构 | 做 2-3 个连续关卡 |
| L2-13 | 看懂规则背后的代码 | 伪代码、真实代码结构 | 把一条规则翻译成代码 |
| L2-14 | 修改一小段真实代码 | 变量赋值、条件语句 | 改分数、速度或胜利条件 |
| L2-15 | AI 调试三句话 | 目标、现象、猜测 | 用固定模板向 AI 求助 |
| L2-16 | AI 答案可靠吗 | 验证、测试用例 | 检查 AI 建议是否真的修好 |
| L2-17 | 版本保存和回滚 | Git 概念、作品版本 | 保存一个稳定版本，再做实验版 |
| L2-18 | 代码不只是能跑 | 可读性、命名、注释 | 整理规则命名和作品说明 |
| L2-19 | 毕业项目立项 | 需求、范围、路线选择 | 写作品目标和最小可玩版本 |
| L2-20 | 核心玩法制作 | 主循环、核心规则 | 做出 1 分钟可玩的核心玩法 |
| L2-21 | 加入个性化机制 | 创意、技能、道具 | 加一个原创机制 |
| L2-22 | 测试和修 bug | 调试、边界情况 | 找出并修复 3 个问题 |
| L2-23 | 展示页和家长报告 | 表达、作品包装 | 生成作品说明和规则透视 |
| L2-24 | 毕业展示 | 复盘、演示、AI 协作 | 展示作品并讲清 AI 如何帮助 |

### 8.3 当前 MVP 的位置

当前产品只需要先做好 L2-01 到 L2-06。

原因：

- 这 6 课已经能验证学生是否愿意学。
- 能验证自研规则平台、代码透视眼、AI 伴学是否成立。
- 能产生第一批家长可见作品。
- 不会因为全学段目标过大而拖慢第一版交付。

## 9. L3：真实应用与游戏开发

目标年龄：14-17 岁。

建议课时：32 节，每节 90 分钟左右，适合一学年或两个学期。

核心目标：

- 从平台规则编辑器过渡到真实代码项目。
- 学会用 AI 辅助写代码，但必须自己读懂、测试和维护。
- 掌握 Web、小型后端、游戏项目、版本管理和产品迭代的基础。

不急着学：

- 高并发架构。
- 大型微服务。
- 复杂云原生体系。
- 深度机器学习训练。
- 企业级安全合规。

AI 角色：

- 编程搭档。
- 代码解释员。
- 测试生成助手。
- 代码审查伙伴。

### 9.1 L3 课程表

| 课次 | 主题 | 学什么 | 作品/任务 |
|---|---|---|---|
| L3-01 | 从规则到代码项目 | 项目结构、入口文件 | 打开并运行一个真实小游戏项目 |
| L3-02 | JavaScript/TypeScript 基础 | 变量、函数、对象 | 用代码改游戏数值和规则 |
| L3-03 | 事件和页面交互 | DOM/Canvas 事件 | 做一个可点击的小工具 |
| L3-04 | 模块化代码 | import/export、职责拆分 | 把游戏逻辑拆成模块 |
| L3-05 | Git 入门 | commit、branch、diff | 保存一次功能开发版本 |
| L3-06 | AI 辅助读代码 | 代码摘要、调用链 | 让 AI 解释一段代码并验证 |
| L3-07 | 游戏循环和渲染 | update、draw、帧率 | 做一个 Canvas 小游戏循环 |
| L3-08 | 物理和碰撞 | 矩形碰撞、速度 | 做一个弹球或躲避游戏 |
| L3-09 | 状态机 | 菜单、游戏中、结束 | 给游戏加入状态切换 |
| L3-10 | 资源和音效 | 图片、音效、加载 | 给游戏加入素材和反馈 |
| L3-11 | 关卡数据化 | JSON 配置 | 用数据生成关卡 |
| L3-12 | 游戏项目一：可玩原型 | 最小可玩版本 | 完成一个 2D 小游戏原型 |
| L3-13 | Web 应用基础 | 组件、状态、表单 | 做一个任务清单或作品库 |
| L3-14 | 前端路由和页面 | 多页面结构 | 做作品列表、详情、编辑页 |
| L3-15 | 本地存储 | localStorage、JSON | 保存用户作品数据 |

| L3-17 | 轻后端入门 | Node/API Route | 写一个保存作品的接口 |

| L3-22 | AI 生成代码要审查 | 代码审查、风险 | 找出 AI 代码里的一个问题 |

| L3-26 | 用户体验 | 流程、反馈、可用性 | 改善一个页面或游戏菜单 |
| L3-27 | 数据和反馈 | 埋点概念、问卷 | 收集 3 个试玩反馈 |
| L3-28 | 迭代计划 | 版本、优先级 | 排定下一版功能 |
| L3-29 | 综合项目立项 | 范围、技术选型 | 选择游戏或应用项目 |
| L3-30 | 综合项目开发 | 工程协作 | 完成主要功能 |
| L3-31 | 综合项目测试发布 | 测试、修复、部署 | 发布可试玩/可使用版本 |
| L3-32 | 项目答辩 | 展示、复盘、代码讲解 | 向家长/同学展示项目 |

### 9.2 L3 阶段评价

通过标准：

- 能运行和修改一个真实代码项目。
- 能使用 Git 保存版本。
- 能让 AI 辅助理解或生成代码，并能审查和测试。
- 能发布一个可访问的小作品。

家长可见成果：

```text
孩子已经从“做游戏关卡”进入“做真实项目”，能用代码、AI 和版本管理完成一个可发布作品。
```

## 10. L4：AI 原生开发进阶

目标年龄：17 岁以上/成人/高阶学生。

建议课时：24 节核心课，每节 90-120 分钟；可加 12 节选修项目。

核心目标：

- 掌握 AI 时代真实软件开发闭环。
- 能做 AI 工具、AI 游戏助手、学习助手或创作平台原型。
- 理解架构、数据、评测、安全、成本和上线运营。

这一阶段才把“用 AI 工具完成真实软件/游戏/产品开发”作为正式目标。

AI 角色：

- 需求澄清伙伴。
- 代码生成搭档。
- 架构讨论伙伴。
- 测试和评测助手。
- 文档和运营助手。

### 10.1 L4 课程表

| 课次 | 主题 | 学什么 | 作品/任务 |
|---|---|---|---|
| L4-01 | AI 原生开发方式 | 人机分工、上下文、验证 | 建立个人 AI 开发工作流 |
| L4-02 | 需求到任务拆解 | PRD、用户故事、验收标准 | 写一个可开发的小 PRD |
| L4-03 | 技术选型 | 前端、后端、数据库、AI API | 为项目选择技术栈 |
| L4-04 | 项目脚手架 | 初始化、目录、规范 | 创建一个可运行项目 |
| L4-05 | 代码生成与审查 | Prompt、diff、review | 让 AI 实现小功能并审查 |
| L4-06 | 测试驱动开发 | 单测、集成测试、回归 | 为关键逻辑补测试 |
| L4-07 | 前端产品化 | 状态、表单、错误提示 | 做一个可用页面 |
| L4-08 | 后端 API | REST/RPC、校验、错误码 | 写项目核心接口 |
| L4-09 | 数据库设计基础 | schema、关系、迁移 | 设计并读写数据 |
| L4-10 | 认证和权限 | session、token、角色 | 做基础登录和权限 |
| L4-11 | AI API 基础 | 模型、消息、工具调用 | 接入一个 AI 对话或助手能力 |
| L4-12 | Prompt 工程 | 结构化提示、上下文压缩 | 让 AI 稳定完成一个任务 |
| L4-13 | RAG 入门 | 向量、检索、引用 | 做一个基于资料问答的小助手 |
| L4-14 | Agent 入门 | 工具、计划、执行、边界 | 做一个受控任务助手 |
| L4-15 | AI 评测 | 样例集、正确率、人工复核 | 建立 20 条评测用例 |
| L4-16 | AI 安全 | 提示注入、隐私、越权 | 给 AI 功能加基本防护 |
| L4-17 | 部署和环境 | 环境变量、构建、发布 | 上线一个可访问版本 |
| L4-18 | 日志和监控 | 错误日志、使用数据 | 能定位线上问题 |
| L4-19 | 成本意识 | token、缓存、限流 | 估算一次功能调用成本 |
| L4-20 | 产品反馈 | 用户访谈、数据分析 | 收集并整理真实反馈 |
| L4-21 | 版本迭代 | roadmap、优先级、回滚 | 发布 v0.2 改进版 |
| L4-22 | 团队协作 | issue、PR、review | 模拟多人协作流程 |
| L4-23 | 项目打磨 | 体验、稳定性、文档 | 完成上线前检查 |
| L4-24 | 产品 Demo Day | 演示、复盘、下一步 | 展示一个 AI 产品或游戏工具 |

### 10.2 L4 可选进阶方向

| 方向 | 建议课时 | 内容 |
|---|---:|---|
| AI 游戏工具 | 12 节 | 关卡生成、NPC 对话、剧情助手、自动测试。 |
| 竞赛算法/CS 基础 | 24-48 节 | 数据结构、图论、动态规划、复杂度证明。 |
| 3D 游戏开发 | 24 节 | Godot/Unity、3D 空间、物理、相机、资源管线。 |
| AI 应用工程 | 24 节 | RAG、Agent、多模态、评测、部署和安全。 |
| 创业产品营 | 12 节 | 真实用户、商业模式、增长、数据分析。 |

## 11. 算法学习怎么放

算法仍然要学，但不应在低龄主线里变成刷题中心。

### 11.1 主线算法素养

| 年龄 | 算法内容 | 游戏化场景 |
|---|---|---|
| 8-10 | 顺序、重复、条件 | 角色行动、金币刷新、胜负判断 |
| 10-14 | 搜索、排序、状态机、路径直觉 | 敌人行为、背包道具、排行榜、寻路 |
| 14-17 | 数据结构、复杂度、简单图算法 | 地图、任务系统、关卡生成、性能优化 |
| 17+ | 更系统算法或竞赛算法 | 作为选修或专业方向 |

### 11.2 竞赛算法定位

竞赛算法不作为全员主线。

适合作为：

- 对数学和挑战感兴趣学生的选修路线。
- 高中阶段的深入方向。
- 想走计算机专业或竞赛路线学生的加强课程。

不适合作为：

- 6-10 岁启蒙主线。
- 游戏创作 MVP 的核心卖点。
- 家长判断编程学习效果的唯一标准。

## 12. 需要砍掉或后置的内容

### 12.1 低龄阶段砍掉

| 内容 | 原因 |
|---|---|
| 背语法表 | 容易破坏兴趣，AI 时代收益低。 |
| 大量控制台练习 | 与游戏创作目标脱节。 |
| 复杂数学算法 | 抽象过早，挫败感强。 |
| 完整 IDE 工程配置 | 技术摩擦大于学习价值。 |
| 开放式 AI 代写 | 容易让学生绕过思考。 |

### 12.2 10-14 岁阶段后置

| 内容 | 后置到 |
|---|---|
| 登录系统、权限系统 | L3/L4 |
| 数据库建模 | L3/L4 |
| 云部署和域名 | L3/L4 |
| 复杂测试框架 | L3/L4 |
| AI Agent/RAG | L4 |
| 复杂框架生态 | L3/L4 |

### 12.3 不能砍掉的底层能力

| 能力 | 为什么不能砍 |
|---|---|
| 逻辑拆解 | AI 也需要人说清目标和边界。 |
| 代码识读 | 不会读就无法判断 AI 生成内容。 |
| 调试验证 | AI 会错，学生必须会验证。 |
| 版本意识 | 项目越真实，越需要保存和回滚。 |
| 作品表达 | 家长和学生都需要看到成果。 |

## 13. AI 协作权限分级

为了避免 AI 代做，平台应按学段逐步开放 AI 能力。

| 阶段 | AI 可以做 | AI 不应做 |
|---|---|---|
| L0 | 给创意选项、解释现象 | 直接生成完整作品 |
| L1 | 给提示、解释规则 | 直接替学生修完所有规则 |
| L2 | 分级调试、代码透视、复盘追问 | 一键完成毕业作品 |
| L3 | 生成小段代码、解释项目、辅助测试 | 不经审查直接合并大量代码 |
| L4 | 参与架构、实现、测试、文档 | 绕过安全、评测和人工确认 |

## 14. 平台能力如何支撑全学段

自研平台是核心资产，长期应沉淀 7 个能力。

| 平台能力 | 支撑阶段 |
|---|---|
| 规则 DSL | L0-L2，降低入门门槛。 |
| 游戏运行器 | L0-L2，提供即时反馈。 |
| 代码透视眼 | L1-L3，连接规则和真实代码。 |
| AI 伴学系统 | L0-L4，按阶段控制帮助深度。 |
| 作品档案 | L0-L4，形成长期成长记录。 |
| 评价报告 | L1-L4，让家长看到学习效果。 |
| 项目开发工作台 | L3-L4，从课程平台过渡到真实开发。 |

第一阶段只需要做好：

- L2-01 到 L2-06。
- 规则 DSL 的最小闭环。
- AI 伴学 mock 或轻量真实接入。
- 本地保存和阶段报告。

不要为了全学段提前做复杂后端和大型后台。

## 15. 阶段性作品与评价

| 阶段 | 阶段作品 | 评价重点 |
|---|---|---|
| L0 | 互动故事/小动画 | 是否理解角色、动作、规则和结果。 |
| L1 | 闯关小游戏作品集 | 是否能说清当/如果/就和变量。 |
| L2 | 可展示 2D 游戏 | 是否能组合事件、变量、碰撞、循环、函数，并与 AI 协作。 |
| L3 | 可发布小应用/小游戏 | 是否能读写代码、使用 Git、测试、发布和收集反馈。 |
| L4 | AI 产品或游戏工具 | 是否能完成需求、架构、AI 接入、评测、安全和迭代。 |

评价延续 v0.3 的原则：

- 作品优先。
- 过程可见。
- 概念显性。
- AI 协作可解释。
- 家长可读。

## 16. 推荐落地路线

### 16.1 当前阶段

继续聚焦：

```text
10-14 岁
6 课 MVP
自研规则平台
Phaser 游戏运行器
AI 伴学
作品展示和家长报告
```

目标不是证明全年龄段可行，而是证明核心学习闭环可行。

### 16.2 MVP 验证通过后

优先扩展 L2：

```text
6 课 -> 12 课 -> 24 课
```

扩展顺序：

1. 先把第 1-6 课做到体验扎实。
2. 再加第 7-12 课，强化关卡、手感、敌人、道具、难度。
3. 再加第 13-18 课，强化代码过渡和 AI 协作。
4. 最后加第 19-24 课，形成完整毕业项目。

### 16.3 第二增长方向

L2 稳定后，再二选一：

| 方向 | 适合情况 |
|---|---|
| 向下做 L1 | 如果用户主要来自低龄儿童和家长启蒙需求。 |
| 向上做 L3 | 如果用户主要来自初高中学生，希望做真实项目。 |

不建议 L1、L3、L4 同时开工。

## 17. 关键风险

| 风险 | 表现 | 对策 |
|---|---|---|
| 全学段太大 | 产品方向发散，MVP 做不完 | 把 v0.6 当路线图，不改变当前 MVP 范围。 |
| 目标过高 | 家长误以为低龄阶段就能做真实产品 | 每阶段明确学习目标和非目标。 |
| AI 代做 | 学生不思考，只复制答案 | 分级提示、复盘追问、运行验证。 |
| 语法过轻 | 学生到了真实代码阶段断层 | L2 开始加入代码透视，L3 系统过渡到真实代码。 |
| 算法过重 | 创作兴趣被刷题替代 | 主线学算法素养，竞赛算法做选修。 |
| 平台过早复杂 | 后端和后台拖慢验证 | 先本地保存和轻后端，后续替换数据层。 |

## 18. 本版本结论

全学段可以做，但不能从第一天就做成全学段产品。

更稳的策略是：

```text
先把 10-14 岁游戏编程主线做深
-> 验证自研平台和 AI 伴学是否成立
-> 扩展成 24 课主线课程
-> 再向下接启蒙，向上接真实开发
-> 最终形成 AI 时代的创作型编程学习通道
```

一句话定位：

> 这不是一门让孩子背语法的课，而是一条从“我想做一个游戏”走向“我能用 AI 和代码做出真实作品”的成长路线。
