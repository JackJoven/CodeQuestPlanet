# PRD v0.8：L0-L2 课程表二次修订

## 1. 本次修订解决什么问题

`v0.7` 已经把前三学段做成了一条连续成长路线，但还存在三个明显问题：

1. `L1` 和 `L2` 的边界不够锋利，概念重复感偏强。
2. 单节课任务颗粒度偏薄，难以真实支撑 `45-60 分钟` 或 `60-90 分钟` 的课堂时长。
3. 课表里依赖了“自研规则编辑器”这个能力，但产品当前并没有一个真正能让学生拼规则、试错、调试的学习工具。

本版本目标不是推翻 `v0.7`，而是把它修成一版更能落地的课程表。

## 2. 本版本的关键修正

### 2.1 不再使用“自研规则编辑器”这个模糊说法

在 `L1` 里，先不用“自研规则编辑器”这种容易误导的表述，统一改成：

```text
规则实验台
```

它至少应该包含 5 个能力：

1. 看到当前场景里有哪些对象和目标。
2. 自己选择或拼装 `当 / 如果 / 就` 规则。
3. 同时管理多条规则，而不是只有一条标准答案。
4. 运行后能看到变量、状态、碰撞、计时等变化。
5. 允许学生拼错、漏掉、顺序不对，再通过运行结果调试。

在没有这 5 个能力前，课表不能假设学生真的在“写规则”，只能说学生在“规则实验台里完成规则任务”。

### 2.2 单节课不再等于单个概念说明

从本版本开始，一节课必须至少包含：

- 观察或试玩
- 第一版尝试
- 运行验证
- 修改或扩展
- 复盘或展示

否则这节课只能算“概念演示”，不能算完整课时。

### 2.3 每个模块都要有作品出口

为了避免课程一直在讲概念，本版本要求：

- `L0` 每 4 节有一个“小场景/小玩具/小展示”出口。
- `L1` 每 4 节有一个“模块挑战关/模块小游戏”出口。
- `L2` 每 6 节有一个“原型/vertical slice/项目节点”出口。

### 2.4 重新拉开 L1 和 L2 的边界

| 学段 | 核心定位 | 不再做什么 |
|---|---|---|
| L1 | 用规则实验台做单屏小游戏，学会规则表达、状态变化和调试 | 不提前进入完整项目、代码阅读和大型系统设计 |
| L2 | 做玩法原型、系统设计、代码过渡和毕业项目 | 不再重复用“事件/变量/碰撞/循环”当作主线卖点 |

一句话说：

```text
L1 是“我会用规则做小游戏”
L2 是“我会把小游戏做成作品，并开始懂代码和项目”
```

## 3. 课时支撑结构

### 3.1 L0 单节课建议结构（35-45 分钟）

1. 情境引入与目标说明：`5 分钟`
2. 第一轮操作或创作：`10 分钟`
3. 第二轮变化或扩展：`10 分钟`
4. AI 创意/命名/修补小问题：`5-8 分钟`
5. 展示与复盘：`5-8 分钟`

### 3.2 L1 单节课建议结构（45-60 分钟）

1. 试玩或观察问题：`5-8 分钟`
2. 拆对象、目标和规则：`8-10 分钟`
3. 第一版规则搭建：`10-12 分钟`
4. 运行验证与 debug：`10 分钟`
5. 扩展挑战或参数变化：`8-12 分钟`
6. 作品记录与复盘：`5-8 分钟`

### 3.3 L2 单节课建议结构（60-90 分钟）

1. 玩法分析或目标拆解：`10 分钟`
2. 第一版原型或系统实现：`15-20 分钟`
3. 运行测试与调试：`15 分钟`
4. 扩展挑战或体验调校：`10-15 分钟`
5. AI 协作/代码阅读/验证：`10-15 分钟`
6. 记录、展示与复盘：`10 分钟`

## 4. 三学段修订版总览

| 阶段 | 年龄 | 核心定位 | 阶段作品 |
|---|---:|---|---|
| L0 | 6-8 | 让作品回应我，让世界发生变化 | 互动故事 / 小动画 / 小玩具 |
| L1 | 8-10 | 用规则实验台做单屏小游戏 | 规则小游戏作品集 |
| L2 | 10-14 | 做玩法原型、系统设计、代码过渡和毕业项目 | 可展示原创 2D 游戏 |

## 5. L0：AI 创作启蒙

目标年龄：6-8 岁。  
建议课时：12 节，每节 35-45 分钟。

### 5.1 学段目标

- 建立“我一操作，作品就会回应我”的创作直觉。
- 理解动作、反馈、选择、重复和计数这些最基础的规则感。
- 让 AI 成为创意伙伴，而不是代做工具。

### 5.2 模块结构

| 模块 | 课时 | 模块出口 |
|---|---:|---|
| M1：动作与回应 | 4 节 | 会回应的小场景 |
| M2：变化与选择 | 4 节 | 会变化的小玩具 |
| M3：创意与展示 | 4 节 | 互动故事与创作者展示 |

### 5.3 L0 课程表

| 课次 | 主题 | 学什么 | 作品/任务 |
|---|---|---|---|
| L0-01 | 让角色动起来 | 角色、动作、舞台 | 让主角从起点走到目标 |
| L0-02 | 点一下就会回应 | 点击、事件、反馈 | 做一个会发光或变表情的按钮 |
| L0-03 | 让角色按顺序表演 | 顺序、等待、节奏 | 做一段三步小动画 |
| L0-04 | 模块挑战：会回应的小场景 | 动作和反馈组合 | 做一个点一下就有完整回应的小场景 |
| L0-05 | 碰到就有结果 | 接触、结果、反馈 | 碰到星星后庆祝或得分 |
| L0-06 | 选左还是选右 | 选择、分支 | 做两个不同结局 |
| L0-07 | 重复和计数让世界变化 | 重复、计数、显示直觉 | 收集 3 颗星并显示数量 |
| L0-08 | 模块挑战：会变化的小玩具 | 选择、重复、计数组合 | 做一个会不断变化的小玩具 |
| L0-09 | 让 AI 帮我想角色和场景 | AI 创意协作、选择、改写 | 做角色卡和场景草图 |
| L0-10 | 找到坏掉的一步 | 观察、猜测、修复 | 修好一个少了动作的小作品 |
| L0-11 | 我的互动故事 | 角色、分支、规则组合 | 做一个有开头中间结尾的互动故事 |
| L0-12 | 小小创作者展 | 表达、复盘、展示 | 向家长讲清 3 条作品规则 |

## 6. L1：规则游戏入门

目标年龄：8-10 岁。  
建议课时：16 节，每节 45-60 分钟。

### 6.1 学段目标

- 从“让作品回应我”进入“我会用规则实验台搭小游戏”。
- 理解对象、事件、变量、条件、循环、状态这些规则语言。
- 从单个互动效果，过渡到单屏小游戏、模块挑战和原创关卡。

### 6.2 模块结构

| 模块 | 课时 | 模块出口 |
|---|---:|---|
| M1：单条规则到单屏互动 | 4 节 | 单规则挑战关 |
| M2：游戏会记住和判断 | 4 节 | 带状态的小关卡 |
| M3：系统会自动运行 | 4 节 | 30 秒规则小游戏 |
| M4：调试、AI 与原创关卡 | 4 节 | 原创挑战关与规则作品展 |

### 6.3 L1 课程表

| 课次 | 主题 | 学什么 | 作品/任务 |
|---|---|---|---|
| L1-01 | 游戏由对象、目标和规则组成 | 对象、目标、规则 | 拆解一个单屏小游戏的 3 个对象和 1 个目标 |
| L1-02 | 当按键发生 | 事件、输入 | 让角色移动到目标区 |
| L1-03 | 碰到就有结果 | 碰撞、结果 | 碰到奖励加分或碰到障碍后退 |
| L1-04 | 模块挑战：做一个单规则挑战关 | 事件、碰撞、目标 | 做一个“拿到宝物就通关”的单屏关 |
| L1-05 | 分数和倒计时是游戏记忆 | 变量、计数、时间 | 做一个分数或倒计时系统 |
| L1-06 | 屏幕显示为什么会变 | UI 同步、数值显示 | 做一个会同步变化的面板 |
| L1-07 | 如果满足条件就能过、开或扣 | 条件、状态、判断 | 做一个有钥匙/血量/开门条件的小关卡 |
| L1-08 | 模块挑战：做一个会记住状态的小关 | 变量、条件、状态 | 做一个带分数或钥匙状态的单屏关 |
| L1-09 | 让系统自己生成东西 | 循环、定时 | 每隔几秒生成目标或障碍 |
| L1-10 | 随机让每局都不一样 | 随机、位置变化 | 让道具或障碍随机出现 |
| L1-11 | 胜利、失败和难度 | 目标判断、失败条件、难度 | 做一个有胜利失败且会逐渐变难的挑战 |
| L1-12 | 模块挑战：做一个 30 秒规则小游戏 | 系统组合、节奏 | 做一个能玩 30 秒的收集或躲避小游戏 |
| L1-13 | 找 bug 的三步法 | 观察、猜测、验证 | 修复一个规则错误并记录过程 |
| L1-14 | 让 AI 帮我定位问题 | AI 提问、限制条件、验证 | 完成一次有效求助并验证建议 |
| L1-15 | 设计我的原创挑战关 | 规则组合、关卡设计、反馈 | 做一个原创单屏挑战关 |
| L1-16 | 规则作品展 | 展示、讲解、反馈 | 展示并讲清核心规则与调试过程 |

### 6.4 L1 出口标准

- 能用“当/如果/就”讲清至少 3 条小游戏规则。
- 能完成一个 30 秒可玩的单屏规则小游戏。
- 能在 AI 提示下定位并修复一个简单规则问题，并说清修复过程。

## 7. L2：AI 游戏创作进阶

目标年龄：10-14 岁。  
建议课时：24 节，每节 60-90 分钟。

### 7.1 学段目标

- 从单屏规则小游戏升级到玩法原型、系统设计和毕业项目。
- 不再以“事件、变量、碰撞、循环”本身为卖点，而是以“玩法循环、系统节奏、代码过渡、项目表达”为主线。
- 开始从规则实验台过渡到伪代码、真实代码和 AI 协作。

### 7.2 模块结构

| 模块 | 课时 | 模块出口 |
|---|---:|---|
| M1：玩法循环与原型 | 6 节 | 30 秒可玩玩法原型 |
| M2：关卡与系统设计 | 6 节 | 双关卡试玩版 |
| M3：代码过渡与 AI 协作 | 6 节 | 代码标注、改动和验证记录 |
| M4：毕业项目与展示 | 6 节 | 可展示毕业作品 |

### 7.3 L2 课程表

| 课次 | 主题 | 学什么 | 作品/任务 |
|---|---|---|---|
| L2-01 | 核心玩法循环 | 玩家动作、目标、失败回路 | 画出并做出“做什么 -> 得到什么 -> 为什么继续玩” |
| L2-02 | 风险与奖励回路 | 风险、奖励、决策 | 让玩家在安全与收益间做选择 |
| L2-03 | 资源和策略 | 能量、弹药、冷却、货币 | 加入一个会限制策略的资源系统 |
| L2-04 | 敌人压力与场景节奏 | 压力、波次、节奏 | 让场景出现有节奏的危险或机会 |
| L2-05 | 技能与特殊机制 | 技能、参数、差异化 | 设计一个让玩法变得不同的机制 |
| L2-06 | 模块原型：30 秒可玩玩法 | 核心循环整合 | 做一个 30 秒可玩的玩法原型 |
| L2-07 | 关卡空间与路线 | 地图、路径、节奏 | 设计一张有路线选择的关卡 |
| L2-08 | 手感调校工作坊 | 加速度、跳跃曲线、反馈 | 调到自己喜欢的操作手感 |
| L2-09 | 敌人和机关联动 | 简单 AI、机关、状态切换 | 做巡逻敌人或开关机关组合 |
| L2-10 | 道具与数值系统 | 数据、效果叠加、持续时间 | 加入护盾、加速或双倍分系统 |
| L2-11 | 难度曲线与波次 | 节奏、波次、平衡 | 让作品前后半段难度递进 |
| L2-12 | 模块作品：双关卡试玩版 | 关卡结构、系统组合 | 做一个双关卡试玩 vertical slice |
| L2-13 | 用流程图讲清玩法系统 | 流程图、状态图、系统拆解 | 把玩法拆成一张系统图 |
| L2-14 | 把规则翻成伪代码 | 规则到步骤 | 把一套玩法写成伪代码 |
| L2-15 | 读懂一段真实代码 | 变量、条件、函数、对象 | 标出代码和玩法的对应关系 |
| L2-16 | 改一个真实功能片段 | 参数、条件、函数调用 | 改一段真实代码并验证结果 |
| L2-17 | 和 AI 一起拆问题 | 目标、现象、约束 | 完成一次有效 AI 调试对话 |
| L2-18 | 验证 AI，而不是盲信 AI | 测试、反例、复现 | 检查 AI 建议是否真的修好 |
| L2-19 | 毕业项目选题与范围 | 用户、主题、MVP | 选一个 4-6 节可完成的项目 |
| L2-20 | 纸面原型与任务拆解 | 流程、界面草图、任务拆解 | 画出玩法流程并拆 5-8 个任务 |
| L2-21 | 核心玩法开发 | 主循环、关键系统 | 做出 1 分钟可玩的核心玩法 |
| L2-22 | 扩展内容与调试 | 关卡、音效、道具、修 bug | 补足完整体验并修关键问题 |
| L2-23 | 展示页、说明和试玩反馈 | 文档、包装、反馈 | 准备作品介绍并收集试玩意见 |
| L2-24 | Demo Day | 展示、复盘、AI 协作 | 演示作品并讲清设计选择 |

### 7.4 L2 出口标准

- 能完成一个有核心玩法、系统节奏和展示说明的原创 2D 游戏。
- 能把玩法系统画成流程图或翻成伪代码，并读懂一小段真实代码。
- 能和 AI 协作拆问题、验证建议，而不是直接照抄答案。

## 8. 本版本结论

`v0.8` 的核心不是再堆课程标题，而是把课表从“概念清单”修成“真实可上课的模块结构”。

一句话总结：

```text
L0：让作品回应我
-> L1：我会用规则实验台做单屏小游戏
-> L2：我会做玩法原型、系统设计、代码过渡和毕业项目
```

这才是前三学段更稳的成长路径。
