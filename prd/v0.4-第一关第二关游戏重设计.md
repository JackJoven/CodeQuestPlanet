# PRD v0.4：第一关与第二关游戏重设计

## 1. 版本目标

本版本基于 `v0.3 学习效果评价与作品展示体系`，重新设计第 1 关和第 2 关，让它们不只是“能玩”，而是形成清晰的学习证据：

- 第 1 关证明学生理解 `事件 -> 坐标变化 -> 角色移动`。
- 第 2 关证明学生理解 `变量 -> 分数变化 -> UI 显示`。
- 两关共同构成阶段 1：`控制与状态`。

核心改动：

```text
第 1 关：从“简单移动到终点”升级为“控制校准任务”
第 2 关：从“讲变量”升级为“修复分数系统任务”
```

## 2. 阶段 1 总目标

阶段 1 覆盖：

- 第 1 关：控制我的角色。
- 第 2 关：让分数动起来。

阶段目标：

> 学生能控制角色，并能让游戏状态发生可见变化。家长能看到孩子已经理解“按键是事件，分数是变量”。

阶段成果：

| 路线 | 成果 |
|---|---|
| 射击路线 | 学生能控制飞船穿过校准门，并收集能量晶核加分 |
| 平台路线 | 学生能控制角色移动/跳跃，并收集金币加分 |

## 3. 第 1 关设计：控制校准场

### 3.1 关卡名称

```text
第 1 关：控制校准场
```

学生视角文案：

```text
角色醒来了，但控制系统还没接上。
你要把“按键事件”连接到“移动动作”，让角色通过校准目标。
```

### 3.2 学习目标

| 目标 | 学生表现 |
|---|---|
| 理解事件 | 能说出“按键会触发一条规则” |
| 理解坐标 | 能观察 x/y 数字随移动变化 |
| 理解速度 | 能知道速度影响移动快慢 |
| 理解验证 | 能运行游戏确认规则是否生效 |

### 3.3 关卡玩法

第 1 关采用“坏掉的控制系统”。

初始状态：

- 角色在起点。
- 目标在远处。
- 学生按键后角色不动。
- 游戏提示学生观察问题。

学生要做：

1. 尝试按键，发现角色不动。
2. 猜测原因：输入事件没有连接移动动作。
3. 点击或编辑规则：`当按下方向键，如果角色没有被锁定，就改变角色坐标`。
4. 运行验证。
5. 到达目标。
6. 完成复盘问题。

### 3.4 两条路线表现

| 路线 | 玩法表现 | 目标 |
|---|---|---|
| 射击路线 | 控制飞船穿过能量门 | 进入右侧蓝色能量门 |
| 平台路线 | 控制角色移动和跳跃 | 到达终点旗帜 |

### 3.5 规则设计

中文规则：

```text
当 玩家按下方向键
如果 角色没有被锁定
就 根据按键方向改变角色坐标
```

伪代码：

```text
当按键被按下:
    如果 player.locked 是 false:
        direction = 读取按键方向
        player.x = player.x + direction.x * speed
        player.y = player.y + direction.y * speed
```

Python 透视：

```python
speed = 6

if key_pressed("left"):
    player.x -= speed
if key_pressed("right"):
    player.x += speed
if key_pressed("up"):
    player.y -= speed
if key_pressed("down"):
    player.y += speed
```

平台路线增加跳跃透视：

```python
if key_pressed("jump") and player.on_ground:
    player.vy = -jump_power
```

### 3.6 过关检测

| 检测项 | 标准 |
|---|---|
| 观察问题 | 学生至少尝试过一次输入 |
| 启用规则 | 移动规则已启用 |
| 状态变化 | x 或 y 坐标发生变化 |
| 达成目标 | 角色进入目标区域 |
| 复盘出口 | 学生能选择或填写“按键是事件，坐标变化让角色移动” |

### 3.7 家长可见成果

阶段报告话术：

```text
孩子完成了第 1 关“控制校准场”。
他先观察到角色按键后不动，再通过启用输入规则修复问题。
这说明孩子理解了“事件”：按键会触发动作；也理解了“坐标”：位置数字变化会让角色移动。
```

## 4. 第 2 关设计：分数晶核

### 4.1 关卡名称

```text
第 2 关：分数晶核
```

学生视角文案：

```text
角色已经能动了，但分数系统坏了。
你能收集晶核/金币，可是分数没有变化。
你要修好 score 变量，让游戏记住你的成果。
```

### 4.2 学习目标

| 目标 | 学生表现 |
|---|---|
| 理解变量 | 能说出 score 是记录分数的盒子 |
| 理解变量更新 | 能解释 `score += 1` 或 `score += 10` |
| 理解 UI 显示 | 知道屏幕分数来自 score |
| 理解状态变化 | 收集物从未收集变成已收集 |

### 4.3 关卡玩法

第 2 关采用“坏掉的计分系统”。

初始状态：

- 角色已经可以移动。
- 场景里有 3 个收集物。
- 学生碰到收集物后，收集物会有反馈，但分数不增加。
- 平台提示：“你收到了反馈，但 score 没有变。”

学生要做：

1. 移动角色收集第一个晶核/金币。
2. 观察分数仍然是 0。
3. 猜测原因：score 变量没有更新。
4. 启用计分规则：`当玩家碰到收集物，如果收集物未收集，就分数 + 1 并隐藏收集物`。
5. 继续收集所有目标。
6. 完成复盘问题。

### 4.4 两条路线表现

| 路线 | 玩法表现 | 目标 |
|---|---|---|
| 射击路线 | 飞船收集能量晶核 | 收集 3 个晶核，分数达到 30 |
| 平台路线 | 角色收集金币 | 收集 3 枚金币，分数达到 3 |

说明：

第 2 关暂不引入“子弹命中敌人加分”，避免把第 3 关的碰撞战斗提前。此处用收集物讲清楚变量和 UI，战斗加分放到第 3 关。

### 4.5 规则设计

中文规则：

```text
当 玩家碰到 收集物
如果 收集物还没有被收集
就 分数增加
并且 隐藏这个收集物
```

伪代码：

```text
当玩家碰到收集物:
    如果 item.collected 是 false:
        score = score + item.value
        item.collected = true
        隐藏 item
```

Python 透视：

```python
if player.collides_with(item):
    if item.collected == False:
        score += item.value
        item.collected = True
        item.hide()
```

### 4.6 过关检测

| 检测项 | 标准 |
|---|---|
| 观察问题 | 学生收集过一个物品且分数未变化 |
| 启用规则 | 计分规则已启用 |
| 变量变化 | score 大于 0 |
| UI 同步 | 屏幕分数与 score 一致 |
| 完成目标 | 收集全部 3 个目标 |
| 复盘出口 | 学生能指出 score 是变量 |

### 4.7 家长可见成果

阶段报告话术：

```text
孩子完成了第 2 关“分数晶核”。
他发现收集物品后分数没有变化，并修复了 score 变量更新规则。
这说明孩子理解了“变量”：score 像一个会变化的盒子，用来记录游戏分数；屏幕上的分数来自这个变量。
```

## 6. 原型实现要求

当前静态原型需要增加：

| 功能 | 要求 |
|---|---|
| 关卡切换 | 支持第 1 关和第 2 关 |
| 关卡文案 | Hero、任务、进度根据关卡变化 |
| 第 2 关分数 | 显示 score、目标、收集进度 |
| 收集物 | 射击路线显示晶核，平台路线显示金币 |
| 计分规则 | 第 2 关按钮从“修复控制规则”变成“修复计分规则” |
| 代码透视 | 根据关卡显示移动代码或计分代码 |
| AI 提示 | 根据关卡回答“为什么动不了”或“为什么分数没变” |
| 评价出口 | 第 1 关复盘事件，第 2 关复盘变量 |

## 7. 暂不做

第 1-2 关暂不做：

- 子弹射击。
- 敌人战斗。
- 生命值。
- 自动生成。
- 函数/技能。
- 真实 AI Gateway。
- 云端报告。

这些留给后续关卡。

## 8. 设计结论

第 1 关和第 2 关要一起构成一个完整的入门证明：

```text
第 1 关证明：我能控制角色，因为我理解事件和坐标。
第 2 关证明：我能让游戏记住结果，因为我理解变量和分数。
```

家长看到的不是“孩子玩了两关”，而是：

```text
孩子已经能修复游戏规则，并能解释按键为什么能移动、分数为什么会变化。
```
