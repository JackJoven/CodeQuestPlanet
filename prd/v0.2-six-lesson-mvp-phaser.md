# PRD v0.2：6 课 MVP 与 Phaser 技术方案

## 1. 版本目标

本版本聚焦第一阶段 MVP：

> 用 `Phaser + Web 平台 + 自研规则 DSL + AI 伴学` 做出 6 节可自学课程，验证学生是否能在少老师或无老师情况下完成第一个小游戏作品。

这不是完整平台版本，而是一个可试玩、可学习、可验证的产品闭环。

## 2. MVP 范围

### 2.1 目标用户

核心用户：`10-14 岁` 学生。

适合：

- 喜欢游戏但没有系统学过编程。
- 学过 Scratch，但对 Python 或文字代码没兴趣。
- 用过 AI，但不知道如何让 AI 帮自己做项目。

### 2.2 课程范围

第一版只做 `6 课`：

| 课次 | 主题 | 核心概念 | 射击路线 | 平台跳跃路线 |
|---|---|---|---|---|
| 第 1 课 | 控制我的角色 | 事件、坐标、速度 | 移动飞船 | 移动角色、跳跃 |
| 第 2 课 | 让分数动起来 | 变量、UI 显示 | 击中敌人加分 | 吃金币加分 |
| 第 3 课 | 碰撞与结果 | 条件、碰撞、状态 | 子弹命中敌人 | 玩家碰怪物/金币 |
| 第 4 课 | 自动出现的敌人 | 循环、定时器、随机 | 自动生成敌机 | 刷新金币/机关 |
| 第 5 课 | 设计一个技能 | 函数、参数、冷却 | 强化子弹 | 二段跳/冲刺 |
| 第 6 课 | 我的第一款小游戏 | 综合项目、复盘 | 一关射击挑战 | 一关平台挑战 |

### 2.3 游戏类型

MVP 只开放：

- `射击类`
- `平台跳跃类`

不做：

- 塔防
- RPG
- 跑酷
- 解谜
- 3D 沙盒

这些留到 v0.3 或 v1.x。

## 3. 技术栈

### 3.1 推荐技术栈

```text
前端应用：Next.js / React
语言：TypeScript
游戏运行器：Phaser
规则系统：自研 JSON Rule DSL
状态管理：Zustand 或轻量自研 store
样式：CSS Modules / Tailwind / 自定义 CSS 均可
AI：后端 AI Gateway，MVP 可先 mock
后端：MVP 可先无后端或极轻后端
数据库：后续 PostgreSQL / Supabase
资源存储：后续 S3 / R2 / OSS
```

### 3.2 为什么选 Phaser

第一版选 Phaser 的原因：

| 原因 | 说明 |
|---|---|
| 适合 2D 网页游戏 | 射击、平台跳跃、跑酷、塔防都能覆盖 |
| 学生无需安装 | 浏览器打开即可学 |
| 开发速度快 | 输入、场景、碰撞、动画、物理能力现成 |
| 方便平台化 | 可以嵌入 React 页面，与规则编辑器和 AI 面板并列 |
| 适合 MVP | 比 Godot/Unity Web 更轻，比纯 Pixi 自研更快 |

### 3.3 技术边界

Phaser 负责：

- 游戏画布
- 角色移动
- 碰撞检测
- 动画和粒子
- 关卡运行
- 即时反馈

React/Next.js 负责：

- 课程页面
- 任务地图
- 规则编辑器
- AI 伴学面板
- 代码透视眼
- 学习进度 UI
- 作品保存入口

Rule DSL 负责：

- 描述学生编辑的规则
- 驱动 Phaser 游戏运行
- 生成中文规则
- 生成伪代码
- 生成 Python/JavaScript 代码透视
- 给 AI 提供结构化上下文
- 给自动过关检测提供依据

## 4. 架构设计

### 4.1 前端核心结构

```text
App
├─ LessonShell
│  ├─ MissionMap

│  ├─ RuleEditor
│  ├─ CodeLens
│  ├─ AICoachPanel
│  └─ ReflectionPanel
├─ RuleEngine
├─ GameRuntimeAdapter
├─ LessonStore
└─ ProjectStore
```

### 4.2 数据流

```text
学生编辑规则
-> 生成 Rule DSL
-> Rule Engine 校验
-> Phaser Runtime 执行
-> 游戏状态变化
-> 自动过关检测
-> CodeLens 生成代码
-> AI Coach 读取上下文
-> 学生复盘与保存
```

```json
    "type": "equals",

  },

    "type": "move_by_input",
```


## 5. 后端策略

### 5.1 为什么第一阶段不做重后端

MVP 最大风险不是账号、数据库或后台能不能做，而是学习闭环是否成立：

```text
选择游戏类型
-> 修复规则
-> 运行反馈
-> 代码透视
-> AI 提示
-> 完成作品
```

所以第一阶段优先验证前端交互、课程任务、规则系统和 AI 伴学流程。

### 5.2 MVP 后端取舍

| 功能 | MVP 处理方式 |
|---|---|
| 用户账号 | 本地游客 ID，可后续接账号 |
| 课程配置 | 前端 JSON 文件 |
| 学习进度 | localStorage |
| 作品保存 | localStorage + 导出 JSON |
| AI 伴学 | 先 mock，后续接 AI Gateway |
| 家长报告 | 前端静态生成，后续云端保存 |
| 管理后台 | 暂不做 |

### 5.3 必须预留的后端接口

虽然第一阶段可先无后端，但前端要按未来 API 设计：

```text
GET    /api/lessons
GET    /api/lessons/:lessonId
POST   /api/progress
GET    /api/projects/:projectId
POST   /api/projects
PUT    /api/projects/:projectId
POST   /api/ai/hint
POST   /api/ai/explain
POST   /api/ai/debug
POST   /api/reports/generate
```

后续接后端时，替换 persistence adapter 即可。

## 6. AI 伴学设计

### 6.1 AI 不是自由聊天框

AI 入口采用结构化按钮：

- 我看不懂
- 我运行失败了
- 给我一个提示
- 解释这段代码
- 帮我找 bug
- 我想加一个新功能
- 我来复盘

### 6.2 AI 提示分级

| 级别 | 行为 | 示例 |
|---|---|---|
| 1 级 | 只给方向 | 先检查有没有事件 |
| 2 级 | 指出模块 | 问题可能在碰撞规则 |
| 3 级 | 给伪代码 | 如果子弹碰到敌人，就加分 |
| 4 级 | 给小段代码 | `score += 1` |
| 5 级 | 复盘追问 | 为什么这里要用变量？ |

MVP 默认只开放 1-3 级，避免 AI 代做。

### 6.3 AI 上下文

AI Gateway 或 mock AI 每次需要读取：

- 当前课程
- 当前路线
- 当前概念
- 当前规则 DSL
- 游戏运行状态
- 错误/失败现象
- 学生已尝试次数
- 当前允许提示等级

### 6.4 AI 协作能力目标

学生要学会 5 个动作：

| 能力 | 表现 |
|---|---|
| 描述目标 | 我想让角色按键移动 |
| 描述现象 | 我按了键，但角色没有动 |
| 猜测原因 | 可能没有连接输入事件 |
| 限定请求 | 请给提示，不要直接给答案 |
| 验证结果 | 我运行后看到坐标变化了 |

## 7. 6 课详细 PRD

### 第 1 课：控制我的角色

目标：

- 学生理解“按键是事件”。
- 学生理解“坐标变化会让角色移动”。
- 学生完成第一条规则修复。

核心任务：

```text
坏掉的游戏：按键无效。
学生猜测：输入事件没有连接移动动作。
学生修复：启用“当按键按下，就改变角色坐标”。
学生验证：角色到达目标点。
```

路线差异：

| 路线 | 任务 |
|---|---|
| 射击 | 控制飞船穿过能量门 |
| 平台跳跃 | 控制角色移动并跳到终点 |

过关检测：

- 规则已启用。
- 玩家坐标发生变化。
- 玩家到达目标区域。
- 学生完成复盘。

### 第 2 课：让分数动起来

目标：

- 学生理解变量是“会变化的盒子”。
- 学生理解 UI 显示来自变量。

核心任务：

```text
坏掉的游戏：吃金币/击中敌人后分数不变。
学生修复：让 score 增加，并同步显示。
```

路线差异：

| 路线 | 任务 |
|---|---|
| 射击 | 击中敌人后 `score += 10` |
| 平台跳跃 | 吃金币后 `score += 1` |

过关检测：

- 分数变量发生变化。
- UI 分数同步更新。
- 学生能解释 `score` 是变量。

### 第 3 课：碰撞与结果

目标：

- 学生理解碰撞是游戏互动的核心事件。
- 学生理解条件判断决定结果。

核心任务：

```text
坏掉的游戏：对象碰到了，但没有后果。
学生修复：如果发生碰撞，就触发加分、扣血或消灭。
```

路线差异：

| 路线 | 任务 |
|---|---|
| 射击 | 子弹碰到敌人后，敌人消失并加分 |
| 平台跳跃 | 玩家碰金币加分，碰怪物扣血 |

过关检测：

- 碰撞事件被触发。
- 对应对象状态变化。
- 分数或血量变化。

### 第 4 课：自动出现的敌人

目标：

- 学生理解循环、定时器和随机。
- 学生理解系统可以自动运行。

核心任务：

```text
坏掉的游戏：敌人/金币只出现一次。
学生修复：每隔一段时间自动生成对象。
```

路线差异：

| 路线 | 任务 |
|---|---|
| 射击 | 每隔 2 秒生成敌机 |
| 平台跳跃 | 定时刷新金币或启动机关 |

过关检测：

- 一段时间内生成多个对象。
- 生成位置有随机变化。
- 学生能解释“重复发生”的规则。

### 第 5 课：设计一个技能

目标：

- 学生理解函数是“打包的一组动作”。
- 学生理解参数可以调整技能效果。
- 学生理解冷却时间是一种状态控制。

核心任务：

```text
学生设计一个可触发技能。
技能由多个动作组成。
技能有参数和冷却限制。
```

路线差异：

| 路线 | 任务 |
|---|---|
| 射击 | 强化子弹、散射、激光 |
| 平台跳跃 | 二段跳、冲刺、护盾 |

过关检测：

- 技能可以触发。
- 技能产生可见效果。
- 技能不能无限连续释放。
- 学生能解释函数和参数。

### 第 6 课：我的第一款小游戏

目标：

- 学生综合使用前 5 课知识。
- 学生完成一个可玩的小游戏。
- 学生完成 AI 协作复盘。

最低作品要求：

- 有可控制角色。
- 有分数或血量。
- 有敌人/金币/障碍物。
- 有胜利或失败条件。
- 有至少一个自定义技能。
- 能展示一条规则和对应代码。
- 能说明 AI 帮了什么，自己如何验证。

毕业展示问题：

```text
我的游戏规则是什么？
我最重要的一条规则是什么？
它对应哪段代码？
我问了 AI 什么？
AI 的建议我怎么检查？
```

## 10. 关键风险

| 风险 | 表现 | 对策 |
|---|---|---|
| 太像普通小游戏 | 家长看不出学习价值 | 强化代码透视、复盘、家长报告 |
| 太像语法课 | 学生兴趣下降 | 每课先玩坏游戏，再引出概念 |
| AI 代做 | 学生依赖答案 | 分级提示，限制完整代码 |
| 规则编辑器太复杂 | 学生不知道怎么改 | P0 只开放有限规则模板 |
| Phaser 与 React 状态混乱 | UI 和游戏状态不同步 | 用 Rule DSL 和 Runtime Adapter 隔离 |
| 后端过早变重 | 拖慢验证速度 | MVP 使用本地保存和 mock AI |

## 11. 开发里程碑

### M1：第 1 课可玩原型

- 完成射击/平台两条路线。
- 完成移动规则。
- 完成代码透视。
- 完成 AI mock。

### M2：规则 DSL 与第 2-3 课

- 抽象 Rule DSL。
- 支持变量、分数、碰撞。
- 完成自动过关检测。

### M3：第 4-5 课

- 支持定时器、随机、对象生成。
- 支持函数/技能/冷却。

### M4：第 6 课毕业作品

- 支持作品保存。
- 支持作品展示。
- 支持学生复盘。

### M5：最小后端

- AI Gateway。
- 云端保存。
- 进度同步。
- 简单家长报告。

## 12. 当前结论

第一版不追求完整教育平台，而是验证一个关键假设：

> 学生是否能通过 Phaser 驱动的游戏任务、自研规则编辑器、代码透视眼和 AI 伴学，在 6 节课内完成第一个小游戏，并理解基础编程概念。

如果成立，再进入 v0.3：真实 AI Gateway、云端作品保存和第 2 批课程。
