# PRD v0.3：学习效果评价与作品展示体系

## 1. 版本目标

本版本补齐平台的评价体系，解决三个关键问题：

1. 学生最后到底要达到什么效果。
2. 学习过程中如何阶段性证明学生在进步。
3. 家长如何直观看到孩子不是在“玩游戏”，而是在学习编程、训练 AI 协作、完成作品。

本版本不改变 v0.2 的 6 课 MVP 技术路线，仍基于：

```text
Next.js / React
TypeScript
Phaser
自研 Rule DSL
代码透视眼
AI 伴学
本地保存优先，后续接后端
```

本版本新增的是：

- 学习目标定义。
- 阶段性评价标准。
- 最终毕业评价标准。
- 家长可见成果。
- 学生作品展示机制。
- 评价数据结构。
- 产品内评价流程。

## 2. 最终培养目标

课程最终不以“学生背会多少语法”为目标，而以“学生能否完成一次真实创作闭环”为目标。

### 2.1 毕业画像

完成 6 课 MVP 后，理想学生应该能做到：

| 能力 | 毕业表现 |
|---|---|
| 游戏规则理解 | 能说清楚自己的游戏由哪些规则组成 |
| 编程概念理解 | 能解释事件、变量、条件、循环、函数、碰撞的作用 |
| 规则编辑能力 | 能用“当/如果/就”表达一个游戏逻辑 |
| 代码识读能力 | 能看懂规则对应的伪代码或简单 Python 代码 |
| 调试能力 | 看到游戏异常后，能猜测问题属于输入、变量、碰撞、循环还是状态 |
| AI 协作能力 | 能向 AI 描述目标、现象和猜测，并验证 AI 建议 |
| 作品创作能力 | 能完成一个有开始、过程、目标、反馈和胜负条件的小游戏 |
| 表达展示能力 | 能向家长或同学演示作品，并讲清关键规则 |

### 2.2 一句话毕业标准

> 学生能独立完成一个可玩的 2D 小游戏，能解释至少 3 条关键规则及其代码对应关系，并能说明 AI 在哪里帮了他、他如何验证 AI 的建议。

## 3. 评价原则

评价体系遵循 5 个原则：

| 原则 | 说明 |
|---|---|
| 作品优先 | 以学生真实作品作为最重要证据 |
| 过程可见 | 不只看结果，还看尝试、修改、调试和 AI 使用过程 |
| 概念显性 | 每个作品必须绑定明确编程概念 |
| 表达验证 | 学生能讲清楚，才算真正理解 |
| 家长可读 | 报告要用家长听得懂的话解释学习价值 |

不采用单一考试分数作为核心评价。

## 4. 能力评价模型

平台采用 `6 维能力雷达图` 评价学生成长。

| 能力维度 | 评价重点 |
|---|---|
| 游戏规则力 | 是否能把玩法拆成规则 |
| 编程逻辑力 | 是否理解事件、变量、条件、循环、函数 |
| 调试修复力 | 是否能发现问题、猜测原因、验证结果 |
| AI 协作力 | 是否会正确向 AI 提问并检查答案 |
| 创意表达力 | 是否有自己的主题、数值、关卡或技能设计 |
| 作品完成力 | 是否能做出完整、可玩、可展示的小游戏 |

### 4.1 评分等级

每个维度使用 4 级评价：

| 等级 | 名称 | 解释 |
|---|---|---|
| 1 | 初识 | 需要大量提示，能跟着完成 |
| 2 | 入门 | 能完成基础任务，但解释不够清晰 |
| 3 | 掌握 | 能独立完成任务，并能解释核心逻辑 |
| 4 | 创造 | 能迁移到新玩法，做出自己的设计 |

MVP 阶段不建议用百分制，避免家长误以为这是传统考试。

## 5. 阶段性评价设计

6 课 MVP 分成 3 个阶段，每 2 课一个阶段评价。

```text
阶段 1：控制与状态
阶段 2：互动与系统
阶段 3：技能与作品
```

## 5.1 阶段 1：控制与状态

覆盖课程：

- 第 1 课：控制我的角色。
- 第 2 课：让分数动起来。

核心目标：

让学生理解“游戏对象会根据事件改变状态”。

### 评价内容

| 评价项 | 通过标准 |
|---|---|
| 输入事件 | 学生能解释“按键触发移动” |
| 坐标变化 | 学生知道 x/y 变化会影响位置 |
| 变量概念 | 学生能解释 score 是会变化的分数盒子 |
| UI 显示 | 学生知道屏幕分数来自变量 |
| 基础 AI 提问 | 学生能描述“我按了键但角色没动”这类现象 |

### 阶段作品

学生完成一个小作品：

| 路线 | 阶段作品 |
|---|---|
| 射击路线 | 能移动飞船，并击中目标加分 |
| 平台路线 | 能移动角色，并吃金币加分 |

### 家长看到的成果

家长报告不要写：

```text
学习了事件和变量。
```

应该写：

```text
孩子已经能让角色根据按键移动，并让分数在游戏中变化。
这说明他理解了“事件”和“变量”：按键是事件，分数是变量。
```

## 5.2 阶段 2：互动与系统

覆盖课程：

- 第 3 课：碰撞与结果。
- 第 4 课：自动出现的敌人。

核心目标：

让学生理解“游戏不是单个动作，而是多个系统持续互动”。

### 评价内容

| 评价项 | 通过标准 |
|---|---|
| 碰撞检测 | 学生能解释为什么碰到后会加分、扣血或消失 |
| 条件判断 | 学生能用“如果……就……”描述规则 |
| 循环/定时 | 学生能解释敌人为什么会不断出现 |
| 随机 | 学生知道随机让游戏每次不完全一样 |
| 调试猜测 | 学生能判断问题可能出在碰撞、变量或生成规则 |

### 阶段作品

学生完成一个有互动系统的小作品：

| 路线 | 阶段作品 |
|---|---|
| 射击路线 | 自动出现敌人，子弹命中后加分 |
| 平台路线 | 金币/机关刷新，角色碰撞后产生结果 |

### 家长看到的成果

```text
孩子已经能设计“如果子弹碰到敌人，就让敌人消失并加分”的规则。
这对应编程里的条件判断、碰撞检测和变量更新。
```

## 5.3 阶段 3：技能与作品

覆盖课程：

- 第 5 课：设计一个技能。
- 第 6 课：我的第一款小游戏。

核心目标：

让学生理解“复杂游戏可以由多个可复用的模块组成”。

### 评价内容

| 评价项 | 通过标准 |
|---|---|
| 函数意识 | 学生能解释技能是一组打包动作 |
| 参数意识 | 学生能调整速度、伤害、冷却等参数 |
| 冷却/状态 | 学生能理解技能不能无限释放 |
| 综合设计 | 学生能把移动、得分、碰撞、生成、技能组合起来 |
| AI 协作复盘 | 学生能说出 AI 帮了什么，自己如何验证 |

### 阶段作品

学生完成一个毕业小游戏：

| 路线 | 作品方向 |
|---|---|
| 射击路线 | 一关带敌人生成、得分和技能的射击挑战 |
| 平台路线 | 一关带金币、怪物、技能和通关目标的平台挑战 |

## 6. 最终评价标准

最终评价由 4 部分组成：

```text
作品评价 40%
概念理解 25%
AI 协作 20%
展示表达 15%
```

MVP 界面中不一定显示百分比，但内部评价可以按这个权重计算。

## 6.1 作品评价

占比：40%

| 评价项 | 1 初识 | 2 入门 | 3 掌握 | 4 创造 |
|---|---|---|---|---|
| 可玩性 | 只能运行片段 | 有基本操作 | 有完整目标和反馈 | 有明显玩法设计 |
| 完整性 | 缺少胜负 | 有部分流程 | 有开始、过程、胜负 | 有关卡节奏或难度设计 |
| 规则数量 | 1-2 条规则 | 3-4 条规则 | 5 条以上关键规则 | 规则之间有组合关系 |
| 个性化 | 基本模板 | 改了数值或素材 | 改了机制 | 有原创玩法或技能 |

最低通过要求：

- 游戏能运行。
- 有可控制角色。
- 有分数或血量。
- 有至少一种互动对象。
- 有胜利或失败条件。

## 6.2 概念理解

占比：25%

学生需要解释至少 3 个概念。

必选概念：

- 事件。
- 变量。
- 条件。

可选概念：

- 循环。
- 碰撞。
- 函数。
- 参数。
- 状态。

评价方式：

| 问题 | 评价目的 |
|---|---|
| 你的游戏里哪个地方用了变量？ | 看学生是否理解状态记录 |
| 哪条规则用了“如果……就……”？ | 看学生是否理解条件判断 |
| 哪个对象会自动出现？为什么？ | 看学生是否理解循环/定时 |
| 你的技能为什么算一个函数？ | 看学生是否理解封装 |

## 6.3 AI 协作

占比：20%

AI 协作不是看学生问了多少次 AI，而是看他是否正确使用 AI。

| 评价项 | 通过标准 |
|---|---|
| 描述目标 | 能说清“我想实现什么” |
| 描述现象 | 能说清“现在发生了什么” |
| 猜测原因 | 能先给出自己的判断 |
| 限定帮助 | 能要求 AI 给提示，而不是直接答案 |
| 验证建议 | 能运行并判断 AI 建议是否有效 |

学生最终展示中必须回答：

```text
我问了 AI 什么？
AI 给了我什么建议？
我怎么验证这个建议是对的？
```

## 6.4 展示表达

占比：15%

学生要做 2-3 分钟作品展示。

展示结构：

```text
1. 我的游戏叫什么？
2. 玩家要做什么？
3. 游戏里最重要的 3 条规则是什么？
4. 其中一条规则对应哪段代码？
5. 我遇到过什么 bug？我是怎么修好的？
6. AI 帮了我什么？我自己做了什么判断？
```

评价标准：

| 等级 | 表现 |
|---|---|
| 初识 | 能试玩，但讲不清规则 |
| 入门 | 能讲基本玩法 |
| 掌握 | 能讲清规则和代码对应关系 |
| 创造 | 能讲清设计选择和改进方向 |

## 7. 家长可见成果

家长最需要看到 4 类证据：

1. 孩子的作品。
2. 孩子的关键规则。
3. 孩子理解的编程概念。
4. 孩子如何使用 AI。

## 7.1 家长报告结构

每个阶段生成一份简短报告，最终生成完整报告。

报告建议结构：

```text
孩子本阶段完成了什么作品
作品里包含哪些游戏规则
这些规则对应哪些编程概念
孩子在哪些地方进行了自主修改
孩子如何使用 AI 解决问题
下一阶段建议提升什么
```

## 7.2 阶段报告示例

```text
阶段 1：控制与状态

孩子完成了一个能移动角色并记录分数的小游戏。
他已经理解：
1. 按键会触发事件。
2. 角色坐标变化会让角色移动。
3. score 是记录分数的变量。

在 AI 协作中，孩子能够描述“我按键后角色没有动”的现象，并根据提示找到输入规则没有启用的问题。
```

## 7.3 最终报告示例

```text
孩子完成了作品《星际能量门挑战》。

作品包含：
1. 玩家移动。
2. 敌人自动生成。
3. 子弹命中敌人加分。
4. 技能释放和冷却。
5. 胜利目标和失败条件。

对应编程概念：
事件、变量、条件、循环、碰撞、函数、状态。

AI 协作表现：
孩子不是直接让 AI 做完整作品，而是先描述目标和现象，再让 AI 给提示，并通过运行游戏验证建议是否正确。
```

## 8. 学生作品展示机制

## 8.1 展示页内容

每个毕业作品生成一个展示页。

展示页包含：

- 游戏标题。
- 学生昵称或匿名名。
- 可试玩游戏。
- 游戏说明。
- 关键规则列表。
- 一条代码透视。
- 学习概念标签。
- AI 协作记录摘要。
- 学生复盘。

示例：

```text
作品：星际能量门挑战
标签：事件、变量、碰撞、循环、函数

关键规则：
当 子弹 碰到 敌人
如果 敌人生命值 > 0
就 敌人生命值 - 1，并且 分数 + 10

代码透视：
if bullet.collides_with(enemy):
    enemy.hp -= 1
    score += 10
```

## 8.2 展示会流程

最终展示会可以在线上或线下进行。

建议流程：

| 环节 | 时间 | 内容 |
|---|---|---|
| 开场 | 5 分钟 | 说明课程目标和评价方式 |
| 学生展示 | 每人 2-3 分钟 | 试玩作品并讲规则 |
| 家长试玩 | 10-15 分钟 | 家长打开作品链接试玩 |
| AI 协作分享 | 每人 1 分钟 | 讲一次 AI 帮助案例 |
| 颁发证书 | 5 分钟 | 根据能力维度给成长证书 |

## 8.3 证书设计

证书不要只写“完成课程”。

建议写：

```text
AI 游戏编程创作者 · 入门认证

已完成：
事件与输入
变量与分数
条件与碰撞
循环与生成
函数与技能
AI 协作调试
独立小游戏作品
```

同时附带能力雷达图。

## 9. 平台内评价流程

每课结束后自动收集：

- 是否完成过关检测。
- 使用了哪些规则。
- 对应哪些编程概念。
- AI 提示使用次数。
- 是否完成复盘问题。
- 是否保存了作品版本。

每 2 课生成阶段评价。

第 6 课生成最终评价。

```text
课内数据
-> 阶段评价
-> 毕业作品
-> 学生展示
-> 家长报告
-> 成长证书
```

## 11. MVP 实现优先级

### P0：必须做

- 每课过关检测。
- 每课 1 个复盘问题。
- 第 2、4、6 课生成阶段成果卡。
- 第 6 课作品展示页。
- 最终能力雷达图。
- 家长可读的最终报告。

### P1：建议尽快做

- AI 自动生成阶段评语。
- 学生作品分享链接。
- 家长试玩入口。
- 证书下载。
- 学生学习过程时间线。

### P2：后续做

- 老师点评。
- 同学互评。
- 作品社区。
- 多版本作品对比。
- 长期学习档案。

## 12. 对 6 课 MVP 的调整

在 v0.2 的基础上，每课增加一个评价出口：

| 课次 | 新增评价出口 |
|---|---|
| 第 1 课 | 学生解释“按键为什么能让角色移动” |
| 第 2 课 | 学生指出哪个变量记录分数 |
| 第 3 课 | 学生讲清一条“如果碰到就……”规则 |
| 第 4 课 | 学生解释敌人为什么会不断出现 |
| 第 5 课 | 学生解释技能为什么像函数 |
| 第 6 课 | 学生完成作品展示和 AI 协作复盘 |

## 13. 最重要的产品效果

这个平台最后要让家长看到：

```text
孩子不是在玩游戏。
孩子是在拆解游戏规则。
孩子能把规则变成代码。
孩子能使用 AI 解决问题。
孩子能完成并展示自己的作品。
```

让学生感受到：

```text
我不只是玩家。
我是规则设计者。
我是游戏创造者。
我能指挥 AI 帮我完成想法。
```

让产品形成壁垒：

```text
学习过程数据
规则 DSL
作品档案
AI 协作记录
能力评价体系
家长可见成果
```
