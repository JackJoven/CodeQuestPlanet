## Question

第 13–16 课各自的地图任务、起始代码缺口、可用 Python 语法与游戏函数、典型误解、迁移挑战和能力门具体是什么，怎样保证四课在操作与认知上真正不同？

## Comments

### Resolution — 2026-08-11

四课采用同一套运行语言，但用不同的核心问题、地图拓扑、学习工具与能力门形成递进。主任务地图固定、迁移地图受控变化，避免随机地图破坏学习证据的可比较性。

| 课次 | 核心能力 | 主任务与地图 | 问题式起始程序 | 独特学习工具 | 迁移与能力门 |
|---|---|---|---|---|---|
| 13 条件启动器 | 用简单 `if` 根据布尔传感器决定是否执行动作 | 直线维修桥；危险格位于信标前，学生必须只在危险格前开启护盾 | 判断对象误写成 `is_blocked_ahead()`，导致遇到危险格仍未开盾 | 条件透镜同步显示传感器值、`True/False`、代码块执行或跳过 | 在危险格位置改变的新直线图中独立写出简单 `if`；说明条件何时为真、为什么开盾 |
| 14 安全逻辑门 | 用 `and`、`or`、`not` 组合布尔条件 | 有岔路、障碍和危险格的安全控制站；不同检查点需要组合安全规则 | 某条规则把 `and` 错写成 `or`，造成不必要动作或进入危险路线 | 安全控制台实时显示各子条件和最终组合结果，并允许先预测再执行 | 在表面布局改变的控制站中独立修正并写出组合规则；三个运算符分别在有意义的判断中通过，不靠冗余条件凑结构 |
| 15 循环信标 | 用 `while` 根据不断变化的停止条件控制未知次数重复 | 直线信号走廊；信标与中继站距离不写入程序，两个目标分段到达 | 第一段循环遗漏 `not` 或检查错目标，导致零次执行、走过信标或不能停止 | 循环监视器逐轮显示条件结果、轮次、当前位置，并在动作上限前识别潜在死循环 | 在信标和中继站距离不同的固定迁移图中不改循环结构完成任务；解释循环为什么会停止 |
| 16 能源搜救 | 综合组织 `if` 与 `while`，不增加新语法 | 多段搜救图；依次采集两座信标、通过危险区、到中继站上传，各段距离与第 15 课不同 | 只保留任务注释、必要转向位置或最小代码框架，不提供完整控制结构 | 能源搜救档案汇总目标状态、执行轨迹、剩余能量和学生解释 | 使用至少一个有意义的 `if` 和一个有意义的 `while` 完成全部状态目标；允许多种解法，独立通过且说明两个停止条件与开盾条件 |

统一游戏 API 使用英文 `snake_case`，并优先返回布尔值，避免把拼写字符串当成本阶段的主要困难：

- 动作：`move()`、`turn_left()`、`turn_right()`、`shield()`、`collect()`、`upload()`。
- 布尔传感器：`is_hazard_ahead()`、`is_blocked_ahead()`、`is_path_clear()`、`shield_is_active()`、`at_beacon()`、`at_relay()`。
- 数值状态：`energy_remaining()`；数值只用于必要的比较，不提前引入变量建模。
- 第 13–16 课语法边界：函数调用、缩进、注释、`if`、`and`、`or`、`not`、`while` 和简单比较。变量与自定义函数从第 17 课以后引入；本阶段不加入 `for`、列表、递归或任意 Python 库。

英文代码同时承担编程与英语学习：第 13 课中新关键字和函数首次出现时直接显示中文短释义，第 14 课只为新词和首次使用显示，第 15 课主要通过悬停查询，第 16 课默认收起为可选词汇帮助。中文释义不进入可执行代码，也不产生中文函数别名。

共同验收规则为：世界任务结果正确、抽象语法结构真实满足本课核心能力、没有依赖强提示，并能在受控迁移图中再次完成。系统不以代码文本和参考答案完全相同作为成功条件。
