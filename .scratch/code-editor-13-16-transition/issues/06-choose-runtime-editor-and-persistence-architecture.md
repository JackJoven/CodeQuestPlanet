## Question

在现有单页浏览器实现中，怎样可靠地解析教学型 Python、定位错误、逐步驱动 3D 世界、保存代码版本，并为以后扩展到第 17–48 课保留清晰边界？

## Comments

### Runtime spike — 2026-08-11

已制作独立的离线运行验证页和可复用运行核心，尚未改动正式第 13 课：

- 固定并本地托管 Skulpt 1.2.0；学生代码不依赖 CDN 或服务器执行。
- 独立运行核心先使用 Skulpt 解析真实 Python，再以允许语法与游戏函数白名单收紧教学边界；不使用字符串替换冒充解释器。
- 学生源代码经行号追踪后产生确定性的世界事件，3D 层只消费事件，不拥有另一份隐藏程序。
- 语法错误在世界行动前反馈；语法正确的运行错误会保留并回放失败前事件，在原始错误行停下。越过终点或朝通道外移动会产生明确的跌落事件，未开盾进入危险格会移动到危险格后停止。
- 游戏 API 调用具有固定预算；错误 `while` 会终止并定位到停止条件，页面不会继续生成无限动作。
- 自动测试已覆盖正确任务、语法错误、危险格运行错误、不会停止的循环、走过终点、侧向越界和禁止导入七种情况，全部通过。
- 静态构建、脚本语法和界面规则检查通过；新资源已进入离线构建产物。

浏览器自动化受本地 `file://` 安全限制；用户随后已在本地人工运行并确认错误回放、危险格停机和跌落效果可用。

### Resolution — 2026-08-11

- 第 13 课正式采用本地托管的 Skulpt 1.2.0 与可复用事件运行核心；学生 Python 是唯一执行源。
- 编辑器先采用轻量原生文本编辑区，加行号、活动行、Tab 缩进和原始行错误定位。当前阶段不引入 CodeMirror，以减少首个黄金课原型的界面与依赖复杂度；后续若需要补全、折叠或更复杂的语法高亮，可替换编辑器外壳而不改变运行协议。
- 3D 世界只消费运行器产生的确定性事件。语法错误不启动世界；运行错误回放至失败点；危险、走过终点与侧向越界拥有独立失败事件和动画。
- 草稿、运行次数、最近错误和最近成功源代码自动保存在本机。登录状态下，课程完成记录同时携带成功 Python、运行次数和验证时间进入既有云端进度 JSON；失败草稿不上传。
- 正式第 13 课已经接入原课程页：前 12 课保留指令卡，第 13 课切换为真实 Python 编辑与运行界面。自动测试覆盖 7 类运行结果，静态构建与界面规则检查通过。
