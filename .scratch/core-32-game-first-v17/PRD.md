# CodeQuestPlanet PRD v1.7：32 课游戏化递进课程

**Status:** lessons 1–32 game-first implementation complete locally / automated and browser QA passed / classroom validation pending
**日期：**2026-09-16
**对象：**10–14 岁零基础或有图形化编程经验的学生
**范围：**共同核心 32 节标准课的难度曲线、学生界面、地图规格、学习证据与迁移规则
**替代关系：**取代 v1.6 中“第 13 课突然切换为代码编辑器”的呈现方案；保留 v1.6 的知识顺序与已验证运行能力

## 1. 产品决定

32 节课始终是一款“通过编程改变世界”的游戏。代码是学生逐步理解和掌握的表达方式，不是第 13 课突然替换游戏的另一套产品。

本版作出六项不可回退的决定：

1. **统一学习外壳。** 第 1–32 课都使用“短目标 → 可操作任务 → 真实运行 → 调试证据 → 换图迁移”的闭环，不把后半段降级成长代码讲义或填空题。
2. **难度必须单调递进。** 后一阶段通过增加决策、状态交互、约束、反例和迁移跨度变难，不以增加文字、机械步数或陌生语法制造难度。
3. **游戏世界始终是主舞台。** 地图、角色、对象状态与执行轨迹占据主要视觉区域；Python 先作为学生搭建结果的可检查表达，再逐步开放局部编辑和混合创作。
4. **地图不能越做越小。** 后续课程可以有局部实验，但标准课主任务和迁移任务必须保持足够的空间尺度、路线选择和视觉信息量。
5. **碰巧通关不算学会。** 世界结果、本课结构的真实执行、修复前后证据和独立迁移必须共同通过。
6. **术语和执行反馈必须统一。** 默认角色名为 `Nova`，只在教学解释中写作 `Nova（诺瓦）`；收集物统一称“宝石”，伤害地形统一称“尖刺”。循环、条件和复合指令必须让学生看见每一步，不允许世界直接闪到最终状态。

AI 只用于解释语法、提示观察方向或提供与核心能力无关的脚手架。AI 不替学生决定条件、停止规则、数据结构、对象协作或测试方案。

## 2. 成功目标与非目标

### 2.1 成功目标

- 学生愿意继续进入下一课，并能说出“这一课多了什么新挑战”。
- 第 13 课以后仍能在不先读长篇代码的情况下开始尝试。
- 每一课只引入一个核心能力，但至少在三种情境中使用：构造、修复、迁移。
- 后期课程的地图视觉面积、可交互对象数和状态反馈不低于前期。
- 教师能从证据中区分：碰巧成功、使用强提示完成、独立掌握。

### 2.2 非目标

- 不追求让学生尽早手打更多 Python。
- 不把更长路线、更多重复点击或更多题目数量当作难度。
- 不把完整 IDE、任意 Python、类定义和开放式聊天设为前 32 课必需能力。
- 不为统一页面而强迫每课使用完全相同的小部件；统一的是学习闭环与证据，不是皮肤复制。

## 3. 难度设计模型

每课难度由五个维度组成。新课至少增加其中一个维度，同时保持其他维度可控：

| 维度 | 初级表现 | 后期表现 | 禁止的伪难度 |
|---|---|---|---|
| 决策数量 | 选择动作顺序 | 选择规则、数据和对象职责 | 仅增加点击次数 |
| 状态交互 | 位置与朝向 | 能量、尖刺、库存、占位、身份共同影响结果 | 用长文字描述但世界不呈现 |
| 约束数量 | 到达并采集 | 顺序、资源、时机、接口与测试同时成立 | 只缩短倒计时 |
| 迁移距离 | 改变目标距离 | 改变输入形态、对象数量或共享状态 | 只换颜色和美术 |
| 证据深度 | 成功轨迹 | 反例、版本差异、跨场景不变量 | 只检查关键字或最终坐标 |

### 3.1 四阶段递进

| 阶段 | 课次 | 学生主要操作 | 新增难度来源 | 代码呈现 |
|---|---:|---|---|---|
| 路线与执行 | 1–8 | 指令卡、地图规划、轨迹调试 | 顺序、朝向、坐标、子目标、规则设计 | 可展开查看对应 Python |
| 结构与复用 | 9–12 | 函数块、调用块、循环体与边界 | 定义/调用分离、状态约定、重复单元 | 与结构块同步显示 Python |
| 控制与状态 | 13–16 | 条件卡、布尔规则台、状态循环、综合任务 | 分支真假、多条件反例、未知次数 | 生成代码默认可见；局部结构可编辑 |
| 数据与协作 | 17–32 | 状态面板、参数槽、数据地图、对象任务板 | 数据依赖、集合变化、多对象时机、系统验证 | 逐步开放混合编辑；世界仍为主舞台 |

### 3.2 难度验收

任一后续课若出现以下情况，不得进入发布：

- 主任务比前置课更少决策，且没有新增状态关系或迁移要求。
- 正确答案可以不使用本课结构，仅靠固定步数碰巧完成。
- 所谓迁移只换主题文字、颜色或装饰物。
- 失败只显示“运行失败”，没有可观察的状态或首次偏离证据。
- 地图主任务退化为三行细条，且没有被更丰富的状态工具或第二场景补足。

## 4. 统一的标准课体验

每节约 60 分钟，允许学校拆成两次 40–45 分钟课时。学生首屏只看到必要信息：

1. 一句话任务；
2. 一条本课规则；
3. 足够大的可玩地图和当前状态；
4. 本课特有的构造工具；
5. 运行、单步、复位。

标准课至少包含三个挑战单元：

- **构造：**学生用本课能力完成一个主任务；允许观察提示。
- **修复：**先真实运行一个与本课能力有关的坏方案，再判断根因并修复；保存前后版本。
- **迁移：**改变有效条件，学生不得依赖强提示；用同一原理而不是照抄同一路线。

代码不是独立的“看代码页”。学生在游戏区搭建规则时，旁边同步生成规范 Python；点击一条结构可定位对应代码。第 17 课以后可逐步编辑局部表达式，编辑结果必须反向影响同一执行模型。若无法保证双向一致，则只保留一种执行权并明确标注，不能出现两份互相矛盾的程序。

### 4.1 全局语言与反馈规范

- 游戏内默认显示 `Nova`；首次介绍、知识讲解或名字含义解释可显示 `Nova（诺瓦）`，不得回退到其他人物名或用“无人机”代替角色名。
- 学生可收集对象统一称“宝石”，公开 Python API 使用 `gem`（例如 `at_gem()`），不得再向学生显示 `beacon`。伤害地形统一称“尖刺”，3D 世界用一簇灰色尖刺呈现，俯视图同时使用灰色与“刺”字，不能只靠颜色区分。
- 复合指令的拆解说明放在指令列表上方的独立区域，按执行顺序解释子步骤；出现 `while`、`gem`、`hazard`、`sensor`、`relay` 等不常用英文时，在该区域给出简短中文翻译，不把长解释塞进指令按钮。
- 指令卡生成区只展示规范 Python，不出现 JavaScript 风格花括号或行尾分号；多行结构必须保留缩进。
- `for`、`while` 等循环在自动运行与单步运行中都按一次循环体一步步推进。每一次移动都要有独立位置变化和动画时间，最后再显示条件变为 `FALSE`，禁止在一次执行拍中直接跳到终点。
- 学习证据使用可访问的收起/展开控件，默认收起；点击“看学习证据”时主动展开并聚焦，避免完成任务后整页突然变长。

## 5. 地图与视觉规格

### 5.1 最小可玩尺寸

| 任务类型 | 主任务最低规格 | 迁移任务最低规格 | 必要信息量 |
|---|---:|---:|---|
| 单路线教学 | 9×5 格 | 9×5 格 | 起点、目标、至少一个影响路线或状态的元素 |
| 条件/循环 | 10×6 格 | 10×6 格 | 状态源、目标、至少两个可比较区域 |
| 数据/对象 | 11×7 格 | 12×8 格 | 至少 3 个数据或对象节点，状态在世界中可见 |
| 阶段作品 | 12×8 格或多场景 | 12×8 格或多场景 | 至少两条可行策略或三类相互作用状态 |

边界空白也计入网格时，可通行区不得小于总面积的 35%。局部 3 行微实验可以出现在构造前，但不能单独承担整节标准课。

### 5.2 地图放大规则

- 课程说明中的俯视图桌面端宽度目标 560–680px；移动端使用容器全宽。
- 3D 区域根据可通行区域而不是整个空白外框计算镜头适配，角色和关键对象不得缩成无法辨认的小点。
- 后期增加的是拓扑、状态与角色关系，不是把相同直线拉得更长。
- 尖刺、目标、中继站、对象身份和共享占位必须有不同的颜色、形状或文字标记，不能只靠颜色区分。

## 6. 第 13–16 课控制能力段

### 第 13 课｜看到尖刺再行动

**核心能力：**让 `if` 根据传感器真假控制动作是否发生。

- 构造：在 11×7 地图选择检测对象，把 `if 前方尖刺 → 开盾` 放进实际路线；执行证据显示读取值、真假和是否执行。
- 修复：给出检测“岩石”的坏规则。学生先运行并在尖刺处失败，再判断“检测对象选错”，改成尖刺并重跑。
- 迁移：尖刺出现在更早、更晚或完全不出现的位置。无尖刺版本必须留下 `FALSE → 跳过` 证据，防止学生把 if 当成永远执行的动作。
- 概念有效解：世界成功、检测对象为尖刺、条件在有效位置真实执行；有尖刺时为真，无尖刺时为假。

### 第 14 课｜写一条安全规则

**核心能力：**用布尔组合表达所有安全约束必须同时满足。

- 构造：组合“前方可通行 AND 能量充足 AND NOT 尖刺”，实时看到三个真假值和最终的前进/右转结果。
- 修复：坏规则使用 OR；岩石前得到 `F · T · T` 却错误前进。学生根据反例判断 OR 漏洞并改为 AND。
- 迁移：分别出现岩石、尖刺和低能量。三张图改变失败来源，但安全规则不变。
- 概念有效解：世界成功、AND 与 NOT 尖刺真实参与运行，至少一个风险状态使规则转向。

### 第 15 课｜不数步，也能到达

**核心能力：**用当前状态决定循环何时停止。

- 构造：把固定数量的前进改成 `while 还没到宝石 → 前进`，观察条件从真变假。
- 修复：固定两步在一张图碰巧成功，但概念判定失败；学生说明固定步数不能迁移，再用 while 修复。
- 迁移：距离依次为 0、1、6。距离为 0 时循环体必须执行 0 次，直接采集；这是停止条件是否正确的关键边界反例。
- 概念有效解：world 成功、while 真实执行，循环次数与状态变化吻合；只用多个 move 不通过能力门。

### 第 16 课｜自动救援程序

**核心能力：**在陌生任务中组合函数、条件、布尔规则和状态循环。

- 不引入新语法；提供三张 12×8 任务图：无尖刺短路、单尖刺绕行、低能量补给。
- 学生先选择规则职责，再组合已有模块；模块可展开检查，但不能用整条参考答案一键插入。
- 修复案例只破坏一个模块约定，要求从调用前后状态定位。
- 能力门分别检查复用、条件、停止和独立迁移，不能用总分互相抵消。

## 8. 第 17–32 课实施约束

后续每课立项时必须提交一张“难度卡”，包括：前置能力、新增决策、有效反例、地图规格、概念有效解、迁移变化和不增加的内容。没有难度卡不得直接复制上一课模板。

- 17–20：每个变量、参数或返回值都必须改变世界状态或路线选择，不做只在控制台打印数字的练习。
- 21–24：列表和字典必须驱动多个目标；改变数据后程序仍可运行，不能把数据写成装饰文本。
- 25–28：二维地图和对象状态需在表格、卡片和 3D 世界之间同步高亮。
- 29–30：协作难度来自共享状态与时机；等待必须推进时间，并在占位真正释放后才允许通过。
- 31–32：学生需要提交作者解、至少一个反例和一个独立变式；作品规模不能掩盖单项能力缺口。

## 9. 学习证据与判定

每课证据至少保存：

- 构造任务的有效运行轨迹；
- 修复前原始失败、学生诊断、修复差异与成功重跑；
- 迁移任务的版本键、输入状态、提示使用情况与运行结果；
- 本课核心结构的执行事件，例如条件真假、循环次数、返回值使用或对象交接；
- 一条简短解释。自由文本只记为已提交，由教师或后续模型评阅，不自动判为理解正确。

“已完成”允许使用强提示；“已掌握”要求构造完成、修复证据完整、等价迁移独立通过。世界到达终点但核心结构未执行，只能显示“结果正确，概念证据不足”。

## 10. 数据迁移与版本

- 课程 ID `course-01` 至 `course-32` 保持不变。
- v1.6 以前的完成记录保留为历史证据，不自动授予 v1.7 能力门。
- 13–32 课使用 v1.7 证据结构：控制课记录条件选择、布尔连接、循环次数和决策轨迹；数据与协作课记录规则选择、状态流、修复前后版本和迁移结果。
- 旧 Python 草稿保留在版本档案中，但 13–32 课默认进入游戏化任务，不自动打开整页编辑器。
- 16–32 课使用第 6 版游戏化学习记录；旧记录保留为历史证据，不自动授予新的能力门。

## 11. 发布验收

### 11.1 自动验收

- 每课正常解、典型错误解和至少三个迁移变式均通过可重复测试。
- 概念无效但世界成功的方案必须被拒绝。
