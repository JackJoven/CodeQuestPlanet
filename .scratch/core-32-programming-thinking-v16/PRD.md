# CodeQuestPlanet PRD v1.6：前 32 课编程思维课程重规划

**Status:** implemented locally / 待课堂验证
**日期：**2026-09-15
**对象：**10–14 岁零基础或有图形化编程经验的学生
**范围：**32 节共同核心的课程、关卡、学习证据和必要产品能力
**文档性质：**当前课程实现基线；本地学习页与自动验收已经完成，真实课堂成效仍待验证
**配套材料：**[原 32 课逐课审查](REVIEW.md)

## 1. 本版决定

项目继续以“学生学会编程”为目标。学生需要能把目标拆成步骤，写出可执行的规则，观察程序如何改变状态，找到错误，并让同一种方法适应新的条件。

保留游戏操作、3D 世界和 Python。AI 可提供语法解释、局部示例和非核心模板；学生必须自己完成本课要学的关键决策。**课程不依赖开放式 AI 对话，也不以手打代码的数量或速度衡量学习。**

相对当前版本，本轮重点是：

1. 保留前 8 课的操作基础，降低重复走格子和填写表单的负担。
2. 恢复第 9–10 课的函数前置，再学习循环、条件和停止规则。
3. 第 13 课开始真实编辑 Python，模板支持语法，逐步撤去完整解法。
4. 第 17–24 课连续建立变量、参数、返回值、列表与字典，不在中间插入对象体系。
5. 第 25–32 课再进入地图数据、世界建造、对象与协作；修正等待的错误语义。
6. 用运行过程、反例和独立迁移验证概念，取消“出现指定文字就算会了”的判定。
7. 学生端少讲、及时讲；教师端保留完整教学设计和评价依据。

**本轮不扩大到算法/创作分支，不新增公共社区、排名、赛季、付费 AI 服务或完整类定义课程。**旧版本保留供追溯。前 32 课之外的长期规划不在此重新批准。

### 1.1 与现有项目定义的关系

- 沿用 [CONTEXT.md](../../CONTEXT.md) 的“标准课、挑战单元、核心能力、能力门、学习证据、概念有效解、渐进开放编辑器”定义。
- “完整知识讲解”指必要概念可在课内学会，不要求首次操作前阅读整页文章。本版将其具体化为短规则、微演示和情境补讲，取代旧文档中可能导致长篇先讲后练的呈现方式。
- 第 13–16 课仍依次为简单条件、布尔组合、while 与综合验证，恢复已有项目定义要求的自由编辑能力。
- 阶段作品不引入新核心能力。旧第 24 课的列表新语法提前教学，旧第 28 课的类定义与复杂组件设计退出本轮必修。
- 历史学号、课程 ID 和作品记录不能被重新编号覆盖；迁移规则见第 10 节。

## 2. 为什么需要这次重规划

原课的多数知识点都可以做成好关卡，问题主要在知识顺序、任务深度和判定方式。详见 [逐课审查](REVIEW.md#3-原课程逐课审查与新课映射)。

| 当前问题 | 本版对应改动 |
|---|---|
| PRD 有函数课，实际前 16 课没有函数前置 | 第 9–10 课恢复组合、调用和复用 |
| 一整课只改一个指定数字、名字或函数 | 局部修改仅用于引导；独立任务需要学生自己组织本课关键逻辑 |
| 课内混入太多新语法 | 每课一个主要能力；切片、嵌套循环、类定义等移选做或后续课程 |
| 第 13–16 课是只读代码拼接 | 可编辑源代码直接运行；提示不锁住编辑器 |
| 关键字检查认可死分支，追踪漏掉合法赋值 | 实际执行结构、事件轨迹和变化输入共同判定 |
| 等一次就允许进入仍被占用的格子 | 等待推进世界时间，通道真正释放后才能进入 |
| 通用变式只在参考路线外加障碍，不能直接作为独立迁移 | 根据核心能力改变有效条件，保留前五课已有的有效变式 |
| 阶段作品仍以固定答案补全为主 | 保存学生策略、测试用例、调试与迁移证据 |

审查已重新运行现有 49 个 Python 场景和 61 个前五课行为场景，均通过；另行复现了计数证据与等待占位问题。这说明可以在现有运行基础上改造，也说明旧测试还没有覆盖所有教学要求。尚无本版的课堂学习成效数据。

## 3. 课堂与学生界面

### 3.1 一节课的组织方式

仍以约 60 分钟为一个标准课。时间是备课预算，不能由单个短地图凑成一课，也不要求学生在同一个场景机械重复 60 分钟。

| 活动 | 参考时间 | 实际交互 |
|---|---:|---|
| 看懂任务与短示范 | 3 分钟 | 一句目标、一条规则、一次可重播的示范 |
| 小范围尝试 | 8 分钟 | 只改一个因素，看到直接反馈 |
| 完成本课主任务 | 15 分钟 | 规划、构造、读代码或调整数据 |
| 找错或比较方案 | 10 分钟 | 对照实际证据；不强迫先写错再改 |
| 独立迁移 | 12 分钟 | 换任务，或用同一份代码通过变化输入 |
| 保存与解释 | 5 分钟 | 自动保存；一次选择、标注或短答 |
| 机动 | 7 分钟 | 补讲、重试；已达标学生做选做挑战 |

学校 40–45 分钟课时可分两次完成一个标准课，第二次直达未完成任务，不重复导入。先试教再调整时间；不能把“等待学生阅读”当作课时容量。

不是每课都展示相同的“三关向导”：调试课直接看故障回放，创作课直接进编辑模板，作品课直接看任务板。底层共用记录与提示机制，前台突出本课的主要动作。

### 3.2 少文字，但保留必要教学

首屏只保留四项：

1. **任务一句话**：建议不超过 24 个汉字，说明要让世界发生什么变化。
2. **本课规则**：一句话，建议不超过 40 个汉字；配 5–15 秒演示或 2–4 行示例。
3. **现在操作哪里**：地图标记、代码编辑位置或当前数据格，只突出一个焦点。
4. **运行或单步按钮**：学生随时可以试，不被长讲解或无关问答拦住。

例如第 4 课：

> 任务：找出第一次走错的那一步。
>
> 规则：报错前，程序可能已经偏离计划。
> 操作：单步运行，在轨迹上点出第一次不同。

完整概念解释、术语和更多例子放在“看个例子”“为什么”中。首次出现的必要规则默认可见，不能全部藏进折叠区，让零基础学生无从下手。

失败反馈先说明“在哪里、预期什么、实际什么”，再给下一步观察入口。例如：“第 4 步朝向东，计划需要朝西。查看上一次转向。”避免只报“答案错误”，也避免直接替换整段代码。

运行前最多保留一个与本课有关的预测动作：点终点、选朝向、填一个状态格或标记预期分支。允许修正预测，不要求先答对才能实验。前置能力不足时给可返回的小补练，不叠加测验门槛。

每课最多一次简短解释；可以选择证据、在图上标注或口头回答。自由文本非空只能代表“已提交”，不能自动代表“理解正确”。不要求每个挑战单元都填反思。

### 3.3 编程操作与英文过渡

| 课次 | 默认操作 | 支持方式 | 独立验证要求 |
|---|---|---|---|
| 1–8 | 直观指令卡、轨迹与地图操作 | 中文动作，旁边可看对应英文调用 | 自己组织顺序、位置和计划；不考打字 |
| 9–12 | 可编辑的函数块、调用块与循环块 | 显示对应 Python，明确定义区、主程序和缩进 | 自己确定函数内容、调用位置、次数与循环体；不能只选不可修改的整条宏 |
| 13–14 | 真实 Python 编辑器 | 预填无关路线、行号、结构模板、按需中文释义 | 关键条件必须由学生形成；完整源代码始终可编辑 |
| 15–16 | 自由编辑 | 可选语法框架，减少答案定位与推荐标签 | 自己组织停止规则和控制流程 |
| 17–32 | 真实 Python 与数据/状态工具联动 | 非核心 API 可给模板；源码是唯一执行源 | 本课概念必须真实参与运行；接受等价解 |

第 13 课首次进入文本时，用约 3 分钟复现第 12 课已学过的循环，认识编辑、撤销和运行位置。这是操作桥接，不再引入新的编程概念。语法自动缩进可用，但不得把“补语法”变成“替学生补逻辑”。

## 5. 逐课关卡设计

下列“主任务、找错、迁移”是一个标准课的核心任务包，不是三个必须完全同形的页面。每课还需搭配短示范和一次小范围尝试。地图数值为出题规格，落地时必须生成可执行参考解与反例；不能仅按描述画图便宣称验收完成。

### 第 1 课｜启动信号

**学生任务：**让探测员到达信标并采集。

- **主任务与巧思：**起点和信标相隔 2 格，只开放前进与采集。让学生在时间线上排列指令；站上信标不会自动采集，体现“机器执行指令，而不是猜目标”。短示范只展示一次前进。
- **学生必须决定：**移动次数、采集位置及指令先后。初始空白的 3 个槽位可以增删，不标出答案顺序。
- **找错：**给出“前进、采集、前进”，让学生对照采集时的位置修复。另用尾部多余前进说明程序应完整执行，不在到达目标时提前宣布通过。
- **迁移：**距离改为 3–4 格，学生重新编排；保留同样的动作与规则。更长距离仅作熟练练习，不用重复次数制造难度。
- **学习证据：**完整成功轨迹；运行前标出的采集位置；一个独立距离任务。不能因为最后站在目标格就通过。
- **落地：**复用前五课流程；预测允许修正，移除无关前置问答。

### 第 2 课｜谁的左和右

**学生任务：**按角色的朝向转弯，找到信标。

- **主任务与巧思：**同一个路口可以旋转镜头。学生先转镜头，再运行相同的转向指令，观察角色相对左右保持不变；随后只改变角色初始朝向，正确指令随之改变。
- **学生必须决定：**角色应左转还是右转，而非点击屏幕的左侧或右侧。地图同时显示角色箭头与世界罗盘。
- **找错：**原地转弯被误认为移动了一格；学生选出转向前后不变的位置和改变的朝向。
- **迁移：**先换镜头不换朝向，再换朝向不换镜头；分别检验“程序是否该改”，避免把所有画面变化都当成重写理由。
- **学习证据：**两组相互独立的方向预测和实际路线；只转镜头时不误改程序。
- **落地：**复用罗盘与镜像地图，增加镜头变化和角色变化的分离条件。

### 第 3 课｜先画路线再出发

**学生任务：**先画路线，再编程走到信标。

- **主任务与巧思：**设计两条都可行的路线：A 移动少但转弯多，B 移动多但总指令少。地图旁将“移动格数”和“执行指令数”分开显示；学生按给定目标选择，而非默认直线永远最好。
- **学生必须决定：**选哪条路线、如何翻译成指令。基本任务只要求可行；“总指令更少”是比较任务，允许先成功再优化。
- **找错：**程序成功到达，但中途与原计划不同。学生标记首次分歧，选择改程序或更新计划并重新验证。
- **迁移：**移动一个影响路线的障碍，让原先更优的路线失去优势；学生重新比较。不得只在路线外加装饰障碍。
- **学习证据：**计划与执行可对照，能区分两种成本，接受多条满足目标的路径。
- **落地：**复用路线对比工具，重新制作有真实取舍的地图并核算两类成本。

### 第 4 课｜调试侦探社

**学生任务：**找出第一次走错的那一步。

- **主任务与巧思：**程序第 4 步转错，第 5 步才撞墙。将计划朝向与实际朝向并排展示，诱发学生区分“报错处”和“原因出现处”。本课直接进入故障回放，不先要求从零构造同一路线。
- **学生必须决定：**第一次偏离的位置、应修改的指令，并通过重跑验证。指定计划下可以判定首次差异，但不能把某条参考路线视为所有程序唯一合法计划。
- **找错：**分别提供方向错、采集过早、尾部多余动作三个短案例，每例只含一个主要错误。
- **迁移：**变换路线和错误位置；不继续把错误固定在同一序号。最终给一个此前未见的故障实例。
- **学习证据：**故障原始轨迹、学生标记、修改差异和成功重跑四者绑定；猜中步骤但未修好不构成调试通过。
- **落地：**复用现有修复证据，预测改为“这一步后的位置或朝向”，增加案例定义。

### 第 5 课｜星图坐标站

**学生任务：**按坐标找到两座信标。

- **主任务与巧思：**任务卡给出两个非对称坐标，如 `(2, 4)` 与 `(5, 1)`，先点位置，再编程验证。镜头可以旋转，但世界坐标不变。统一从 0 开始编号，x 向东增大、y 向南增大。
- **学生必须决定：**目标格与每次移动改变哪一个坐标。转向不改变坐标，向西/北分别减小 x/y。
- **找错：**把 `(2, 4)` 读成 `(4, 2)`；通过表格和世界同步高亮找出差别。
- **迁移：**改变起点和目标，不只整体旋转。增加一次“给出动作后的坐标，反推原来位置”的短题，范围保持在小地图内。
- **学习证据：**正确点位、坐标变化与实际轨迹一致；不能只按熟悉形状走完。
- **落地：**复用坐标轴与信标顺序；为非对称坐标制作明确的干扰项。

### 第 6 课｜三段救援任务

**学生任务：**收齐两份信号，再去上传。

- **主任务与巧思：**地图放出一个较近的中继站和两处信号，近路会诱使学生过早上传。用“找到 A → 找到 B → 上传”的分段卡显示每段的开始条件和结束状态。
- **学生必须决定：**子目标顺序和各段动作，理解到达中继站不等于已满足交付条件。暂不教授变量赋值，仅观察世界状态。
- **找错：**位置正确但只携带一份信号；学生从状态检查点定位缺失的任务段。
- **迁移：**改变中继站位置或两处信号的相对位置，要求重组路线，但保留“收齐再交付”的任务依赖。
- **学习证据：**分段计划、每段结束的携带状态和完整上传；长路线本身不额外加分。
- **落地：**复用上传与分段工具，缩短纯移动段，将失败反馈指向未满足的子目标。

### 第 7 课｜设计一条可解路线

**学生任务：**设计一关，并证明它能通关。

- **主任务与巧思：**在小模板内放一个信标、最多两块障碍，再设置动作上限。系统不给“可解”绿灯，直到作者用自己的程序真实通过；这样限制必须与解法一致。
- **学生必须决定：**目标、限制和作者解。目标位置不只提供三个答案选项，但限制编辑范围，避免开放创作时无从开始。
- **找错：**系统提供“上限少一步”或“目标被围住”的案例，让学生区分程序错与题目规则有问题。
- **迁移：**把作品交给同伴或内置试玩程序，找一个失败方案；作者解释失败来自哪条规则，再修改一次。没有同伴也能独立完成。
- **学习证据：**规则版本、可执行作者解和一个关联反例；截图或点击保存不算创作完成。
- **落地：**扩展现有路线创作模板与版本保存，不依赖公开发布功能。

### 第 8 课｜第一场独立救援

**学生任务：**独立完成救援，留下你的办法。

- **主任务与巧思：**三个短挑战组成作品：陌生路线的分段采集、错误程序修复、改变目标后的重新规划。沿用前七课规则，不加入新动作。
- **学生必须决定：**计划、关键转向与修复位置。提供工具入口和任务目标，不显示参考路线。
- **找错：**使用与第 4 课不同形状和不同错误序号的案例，可单独重试，不重做已通过的全部任务。
- **迁移：**改变起点朝向、有效障碍和目标中的一个主要因素；不能让空间难度突然翻倍。
- **学习证据：**顺序/方向、规划/坐标、调试、独立迁移分别达标；作品自动归档，解释只选一条关键证据。
- **落地：**复用现有动作世界；将单一长地图改为可保存进度的阶段任务包。

### 第 9 课｜把动作装进工具箱

**学生任务：**把同一套动作做成一个工具。

- **主任务与巧思：**主通道旁有三座形状相同的采集支路。学生把“进入支路—采集—回到入口并恢复朝向”组合为 `visit_side()`，再在各入口调用。修改函数内部会影响所有调用。
- **学生必须决定：**函数包含哪些动作、在哪里调用。函数名字可以自定；先定义但不调用时世界不动，用这一现象区分“写工具”和“使用工具”。
- **找错：**函数已定义，主程序却漏掉一次调用；学生在调用轨迹中找缺口，不重复抄一套动作。
- **迁移：**改变支路在主通道上的间距，函数体保持，主程序调用位置调整。此时尚不要求用参数适应不同支路深度。
- **学习证据：**同一个学生定义的函数至少在两处真实调用，调用执行了目标动作；未调用的定义不算复用。
- **落地：**恢复函数编辑区与调用事件；Python 对照使用标准 `def`，不把函数做成不可编辑的神奇按钮。

### 第 10 课｜一个工具，多处使用

**学生任务：**修好工具，让它每次都可靠。

- **主任务与巧思：**沿用采集工具，但起始函数少一次恢复朝向。第一次采集成功，第二次调用失败。学生检查函数的“从哪里开始、在哪里结束、朝向应是什么”，认识复用需要稳定约定。
- **学生必须决定：**应修函数内部还是调用之间的连接，不能只在某一个调用后补丁式转向。先展示入口/出口图标，用生活化语言介绍约定，不要求背术语。
- **找错：**对照每次函数调用前后的状态，找出看似成功却破坏后续任务的出口状态。
- **迁移：**整体改变通道朝向，同一个相对动作函数仍应成立；改变连接段时允许改主程序，不改函数体。
- **学习证据：**至少两次不同位置的调用都满足已声明的起止约定；不能因第一次采集成功就通过。
- **落地：**增加调用前后状态快照，保留第 9 课的操作方式，不新增参数或返回值。

### 第 11 课｜找出重复的一组

**学生任务：**找出重复动作，让循环来执行。

- **主任务与巧思：**三组采集站等距排列，每组需要“前进两格、采集”。学生圈出完整重复单元，将其放入循环；不局限于连续前进的 `repeat2/5` 宏。
- **学生必须决定：**重复哪一组、重复几次、哪些收尾动作留在循环外。展开面板显示循环节省的是重复书写，不是角色实际移动次数。
- **找错：**只循环移动，却把每站采集放到循环外；使用动作展开结果说明漏掉了哪些采集。
- **迁移：**站点由 3 组变成 4 组，只改次数；更换重复单元时需要重新选择循环体。两类变化分别练习。
- **学习证据：**循环体真实重复，展开轨迹与目标一致；不以代码字符更少或执行步数更少作为循环正确的证据。
- **落地：**新增任意已学动作组成的循环体编辑，复用展开工具与函数调用。

### 第 12 课｜循环到哪里为止

**学生任务：**让该重复的动作重复。

- **主任务与巧思：**设置一组对照任务：“每走一格都采集”和“走完才采集”。动作完全相同，只有采集的缩进位置不同。学生拖动循环边界，并预测两种程序各采集几次。
- **学生必须决定：**循环体范围和次数。用运行高亮连接图形块与 Python 缩进，不在本课加入两层循环。
- **找错：**分别修复次数多一、次数少一、收尾动作缩进错误；每个案例只动一处主要原因。
- **迁移：**新增“移动并转向”重复单元，让学生重新判断边界，而非记住 collect 必须在循环外。
- **学习证据：**指出每个动作实际执行次数，修复后的次数与轨迹一致；不能靠固定程序长度判定。
- **落地：**让现有缩进实验台与真实程序使用同一结构，避免实验台正确但主程序另跑一套宏。

### 第 13 课｜看到危险再行动

**学生任务：**前方有危险时，才打开护盾。

- **主任务与巧思：**四格走廊的危险位置会改变。移动循环由模板提供，学生在循环内编写“检测前方危险—开盾”。安全图中的多余开盾会耗能，危险图中的漏开盾会受损，两类情况共同检验条件的必要性。
- **学生必须决定：**检测什么、何时检测、条件成立执行什么。引导允许比较两个传感器；独立任务不标“本关修改”的正确答案。
- **找错：**检测当前位置而非下一格，或把检测放在移动之后。反馈同时显示检测格、条件真假与动作时机。
- **迁移：**同一份代码跑无危险、一处危险、多处危险。每种情况都规定可完成的能量预算，避免全部开盾也通过。
- **学习证据：**条件实际执行，危险与安全情况下有不同的动作分支，且均达成世界目标。
- **落地：**开放真实编辑，提供同代码多场景运行；护盾效果与消耗规则必须稳定、可见。

### 第 14 课｜写一条安全规则

**学生任务：**只有三个条件都满足，才能前进。

- **主任务与巧思：**状态台可切换“通路/阻挡、能量够/不足、危险/安全”。规则是：可通行、前方安全、移动后至少留 1 点能量。学生组合条件，再让系统提供能推翻错误规则的状态组合。
- **学生必须决定：**用 `and` 连接约束，用 `not` 表示“不是危险”。“没有动作”在不安全案例中是正确结果；不能要求每次都走到终点。
- **找错：**把 `and` 换成 `or` 的错误建议，学生找一个“其中一项满足但仍危险”的反例。`or` 在此用于对照解释，不要求写复杂混合逻辑或 `elif` 链。
- **迁移：**抽象状态台用相同条件代码验证 8 种二元组合，真实地图仅采用世界规则允许的组合，不把不可能同时出现的地形硬拼成关卡；能量边界测 1 和 2。新任务只改变保留能量要求，学生据此修改比较边界。
- **学习证据：**允许通过和必须停下的案例都判断正确；不要求固定条件顺序或固定数量的关键词。
- **落地：**复用传感器，新增状态案例板与预期行为判定，不再以一条固定路线代替逻辑验证。

### 第 15 课｜不数步，也能到达

**学生任务：**走到目标就停，不提前数步。

- **主任务与巧思：**一条保证畅通的走廊，目标距离在任务开始后才确定。学生用 `while not at_beacon()` 持续移动，观察每次循环前重新判断。没有转向迷宫，避免同时增加寻路难度。
- **学生必须决定：**停止条件和能改变条件的循环体。到达后执行一次采集；站在目标上开始时循环应执行零次。
- **找错：**条件写反、循环体只转向不前进、到达后仍执行多余移动。无进展由运行预算保护并展示最后几次状态，不让界面卡死。
- **迁移：**相同代码通过距离 0、1、4、6 的等价任务。下一小任务把目标改成中继站，学生更换检测对象，复用停止思路。
- **学习证据：**每轮重读条件，到达后停止；写死移动次数或无关 while 不能替代目标控制。
- **落地：**增加起点与目标可同格的任务数据，使用独立实体信息而非让一个字符承载全部状态。

### 第 16 课｜自动救援程序

**学生任务：**写一次程序，完成不同的救援。

- **主任务与巧思：**提供转弯连接段与已知 API，学生自己组织“安全前进到信标—采集—前往中继站”。路线距离和危险位置变化，世界明确保证每段目标可达。
- **学生必须决定：**什么行为值得做成函数、哪里需要条件、何时结束重复。不给六块已完成路线供顺序点击。
- **找错：**一份方案只在第一个危险格前检测，另一份在每次前进前检测；学生用反例说明并修复一次。
- **迁移：**冻结同一份代码，通过短/长距离、无危险/多危险的任务组。困难学生可以回到针对性补练，再换等价组重测。
- **学习证据：**函数调用、条件行为、停止规则分别通过；for 的掌握可引用第 11–12 课独立证据，不强迫作品同时塞入所有语法。
- **落地：**把作品做成分段保存的最小程序，核心区由学生组织；本课不增加新概念。

### 第 17 课｜会记数的探测员

**学生任务：**每采集一次，就把数量记下来。

- **主任务与巧思：**固定长度走廊放置数量可变的信标。行走与检测已有模板，学生建立计数器，并让采集成功与计数加一对应。显示“真实已采集数”和“程序记录数”，两者可能不同。
- **学生必须决定：**初始值、更新时机与更新表达式。结尾把计数交给任务报告板，变量参与结果展示，不只是写在无关位置。
- **找错：**漏记、采集前就加一、循环内反复归零。对照事件时间线寻找第一次数量不一致。
- **迁移：**同一份计数逻辑通过 0、1、3 个信标的场景；0 个信标场景以正确报告 0 为成功，不要求执行不存在的采集。
- **学习证据：**初始化后，每次成功采集恰好对应一次正确更新，报告值来自本次计数。死分支中的增量、最后硬写数量都不能代替过程证据。
- **落地：**补齐赋值事件与增量赋值追踪；新增轻量结果报告入口，不能拿世界计数冒充学生变量。

### 第 18 课｜能量账本

**学生任务：**算清用了多少能量。

- **主任务与巧思：**两条路线移动次数相同，但其中一条开过护盾。学生发现“移动次数”不等于“总消耗”，用开始值与当前值形成能量账本。
- **学生必须决定：**哪些状态参与计算，什么时候更新派生值。每次消耗只展示与本课有关的两三个变量，避免四五张同时变化的面板。
- **找错：**把 `energy_used = steps` 当总消耗，或在记录初始能量前已移动；找到账本首次与实际消耗不一致的时刻。
- **迁移：**改变初始能量与护盾次数，保留消耗规则；同一计算关系仍正确。不要以固定末值 10 作为唯一答案。
- **学习证据：**旧值、影响事件、新值与最终结果相符；允许用总消耗逐次累加或起始减当前等正确方法。
- **落地：**复用状态控制台，缩短移动路线，增加参数化测试而非仅检查静态目标值。

### 第 19 课｜给工具一个参数

**学生任务：**让同一个工具走不同距离。

- **主任务与巧思：**原本存在“走两步”“走四步”两个近乎相同的工具。学生把变化的数字变成参数，主程序调用同一个函数解决不同距离。
- **学生必须决定：**函数里哪一个量需要变化，传入值如何影响循环。用输入滑块和函数调用轨迹显示“传进去的数”与“里面用到的数”。
- **找错：**函数收到 `steps`，内部却仍写死 `range(2)`；两步任务能过，四步任务暴露错误。
- **迁移：**冻结函数体，测试输入 0、1、4；调用处可以换实参。独立题换成重复转向等已学动作，检验参数方法迁移，不增加多参数定义。
- **学习证据：**同一个函数的参数实际参与重复次数；只保留带参数的签名但不用参数不能通过。函数名、参数名不必与参考答案一致。
- **落地：**复用函数调用事件，将固定 2/4 的文字正则改成输入—执行关系。

### 第 20 课｜让函数交回答案

**学生任务：**让函数算出结果，再决定行动。

- **主任务与巧思：**`energy_after(steps)` 计算走完一段后剩余多少能量，调用者据此决定是否出发。函数负责回答，调用者负责行动；把结果连线到条件面板。
- **学生必须决定：**返回什么，以及调用处如何使用结果。对比“显示数字”“返回数字”“算完但没交回”三种可观察结果，示例不要求新学输入输出库。
- **找错：**函数里算出数值却没有 `return`，或主程序调用后仍用写死的数决策。
- **迁移：**测试剩余能量大于、等于、小于保留值三种情况；函数只读取当前能量并计算，不产生移动或开盾等副作用。
- **学习证据：**真实返回事件与调用者的判断关联，同一函数应随输入变化；只出现 `return` 或只把值显示出来不够。
- **落地：**复用返回轨迹，补足调用结果参与判断的关联记录与多案例验证。

### 第 21 课｜一张会变化的清单

**学生任务：**照着清单，依次完成任务。

- **主任务与巧思：**把多段距离放进列表，主程序 `for distance in distances` 调用已学移动函数。改变清单长度或其中一段距离，世界任务随数据变化，处理程序保持不变。
- **学生必须决定：**清单内容和顺序、循环如何使用当前项。先不引入索引和 `[1:]` 切片，让“一个数据项对应一次处理”清楚可见。
- **找错：**清单明明有三段，程序只手工处理两段；或循环每次都用了固定数字。当前项与实际动作同步高亮。
- **迁移：**同一遍历程序处理 1、3、4 项清单；空清单直接进入已提供的收尾步骤。每份距离数据与对应地图成套，不能改变数据后仍强求原地图答案。
- **学习证据：**每个列表项按顺序进入处理过程，增加一项不需要增加一段处理代码。
- **落地：**复用列表状态与函数轨迹，将数据与任务场景绑定成测试夹具。

### 第 22 课｜清单变长以后

**学生任务：**修改清单，让程序仍能完整执行。

- **主任务与巧思：**任务清单是从 0 编号的槽位。学生修改错误项并用 `append` 添加一个任务；固定 `range(3)` 会漏项或在缩短后的清单里越界，长度跟随数据的必要性随之显现。
- **学生必须决定：**改哪一项、合法索引范围是什么、循环怎样适应真实长度。核心语法仅为索引读写、`append` 与 `len`；不同时要求 `insert/remove/pop`。
- **找错：**把最后一个索引写成 `len(list)`，或新增任务后不修改固定边界。展示“长度 4、索引 0–3”的对应关系。
- **迁移：**使用更短、更长及空清单，检查没有漏项或越界。允许直接遍历元素作为完整处理的等价方案；索引理解通过单独槽位操作验证。
- **学习证据：**一次正确编辑、一次越界定位、变化长度下的完整遍历。不能强制只有 `range(len(...))` 才算正确。
- **落地：**把旧第 24 课的基础修改与边界训练移到此处；补充可视化索引与错误指向。

### 第 23 课｜用名字查规则

**学生任务：**按名字查规则，完成对应任务。

- **主任务与巧思：**任务卡用名称标识不同站点，字典保存名称对应的所需能量或动作参数。卡片展示顺序改变时，按名字查找仍正确，按“第几个位置”取值会错配。
- **学生必须决定：**键和值如何配对，查询结果怎样传给处理函数。名称同时用文字和图标标识，不单靠颜色；短示范解释字符串需要引号。
- **找错：**键拼写不一致、值配反，或取出了数据却仍用硬编码参数。反馈显示实际查询的键与取得的值。
- **迁移：**保留处理程序，替换一份键集合相同但数值不同的规则表，再更换任务顺序。必修输入保证键存在；缺失键作为可解释错误展示，不要求异常处理语法。
- **学习证据：**至少两个键的不同查询真正影响动作或计算；只改固定 H 对应值不能代表已会按名称查规则。
- **落地：**复用字典运行状态，增加查询/使用关联，避免使用字符串直接执行任意代码的设计。

### 第 24 课｜救援调度台

**学生任务：**按清单分配能量，完成救援。

- **主任务与巧思：**切换到 3D 基地旁的调度台，减少走格子。列表给出救援顺序，字典记录各任务消耗；学生用参数函数计算执行后能量，条件决定执行或暂缓，变量记录已完成数量。
- **学生必须决定：**数据如何进入函数、结果如何影响决策、任务完成后如何更新记录。固定按清单顺序处理，不增加“找最优调度算法”的新要求。
- **找错：**方案在一份订单上正确，换订单后漏项、用错键或重复计数。学生选择其中一个故障，留下定位和修改证据。
- **迁移：**相同代码处理不同清单长度、任务费用和初始能量。费用与世界实际消耗一致；能量不足的任务应被暂缓，空清单应正确报告 0。
- **学习证据：**列表、字典、参数/返回值、状态更新真实连接；引用第 22 课的索引证据，不强迫作品人为使用每一个列表方法。
- **落地：**提供非核心执行 API `rescue(name)` 和结果面板；它只执行已选任务并记录消耗，不替学生完成判断。此 API 为新增需求，不是现成能力。

### 第 25 课｜地图藏在表格里

**学生任务：**改对一个数据格，修好地图。

- **主任务与巧思：**使用 4 行 7 列的非方形地图，数据格与世界格联动。学生把目标位置或堵路格编码修好，再用已给路线验证；非方形能暴露把行列颠倒的错误。
- **学生必须决定：**世界 `(x, y)` 对应数据 `map[y][x]`，哪一行哪一列需要改变。这里的第二个索引是一个新定位方式，不同时引入双层循环。
- **找错：**修改 `map[x][y]` 导致另一处变化或越界；通过双高亮定位错误。
- **迁移：**地图变为 5 行 6 列，目标放在非对角位置。修图方法不变，不要求最终数组与唯一参考图逐字符相同；允许不同合法方案。
- **学习证据：**指定世界位置与数据修改一致，生成后能按规则运行；不能只点世界画面而不知道数据地址。
- **落地：**复用二维列表与 `build_world`，补数据—世界的双向定位提示；模型始终使用固定世界坐标。

### 第 26 课｜用数据修一座桥

**学生任务：**按施工清单，把断桥接起来。

- **主任务与巧思：**桥在固定行上，施工清单列出缺失的列号。学生遍历清单调用 `place_tile(x, row, "g")`，再运行探测员验证。桥宽变化时改数据即可，不手工复制建造语句。
- **学生必须决定：**清单包含哪些格、生成动作如何读取数据。材料按实际新建格消耗，多建无用格不能被无限预算掩盖。
- **找错：**施工清单少一格、坐标映射错，或把放置语句放在循环外；分清蓝图、施工事件和运行结果。
- **迁移：**同一生成程序应用到不同缺口清单，验证全部连续且没有额外堵路。传送门配对仅作选做，不承担本课必修能力。
- **学习证据：**施工数据产生对应世界事件；修图后参考路径真实通过。直接硬编码最终整图可以完成世界，但仍需补数据生成的能力证据。
- **落地：**复用放置/移除和世界事件，增加材料与施工清单验证，不扩建大型自由世界编辑器。

### 第 27 课｜把任务交给谁

**学生任务：**把任务交给有这项能力的角色。

- **主任务与巧思：**提供已经创建好的探测员、飞行器和运输船。采集、扫描、运输任务的图标对应不同能力；外形相似的角色未必拥有相同能力。学生查能力卡，再用点语法调用方法。
- **学生必须决定：**由哪个对象执行什么动作，并查看该对象自己的状态。本课不要求写构造函数或定义类。
- **找错：**让飞行器采集，或读取一个对象的传感器却让另一个对象行动。错误反馈给出对象名、方法和能力边界。
- **迁移：**更换名字与位置，类型能力保持稳定；学生不能依赖叫 Neo 的一定是采集者。预置能力清单仅作对比，复杂组件组合移选修。
- **学习证据：**所选对象真正执行任务，查询和动作属于同一对象；不是只在界面点中一个正确图标。
- **落地：**复用预置类型；为对象补齐有明确归属的状态与检测 API，消除“最近操作对象决定全局检测”的隐含规则。

### 第 28 课｜两个同款机器人

**学生任务：**创建两个机器人，各自完成任务。

- **主任务与巧思：**两个同类型实例有不同起点与能量。操作 A 时观察 B 的位置和能量保持不变；再对照 `b = a`，看到第二个名字并不会凭空制造另一台机器人。
- **学生必须决定：**何时创建新实例、初始化哪些状态、后续指令发给谁。初始化 API 的完整格式由可见字段卡说明，不让学生靠猜多个数字含义。
- **找错：**把同一对象的别名当成独立对象，或给两个实例错误的起点/能量。用身份标识和独立档案定位，不只按显示名字判定。
- **迁移：**两个实例交换起点与任务，状态仍独立；再创建第三个实例作为选做，避免靠固定名字过关。
- **学习证据：**至少两个真实实例，初始化影响后续运行，一方动作不修改另一方状态。名字相同不应成为对象身份相同的技术依据。
- **落地：**完善实例身份、独立位置和能量；保留类型预置，不新教 `class`、`self`、继承。

### 第 29 课｜接力运输

**学生任务：**交接货物，再让运输船送达。

- **主任务与巧思：**探测员能采集但不能完成远端运输，运输船能运输但不能采集。货物先属于探测员，双方到交接点相邻后才能执行交接，随后由运输船送到指定站。
- **学生必须决定：**分工、行动顺序、交接时机。固定地图先练顺序，不在本课加入随机延迟。
- **找错：**船尚未到交接点就转交，或船未装货就上传。界面显示货物当前所有者，避免一个对象采集后全世界都自动视为携带。
- **迁移：**交换两个对象的起点并更换交接位置；职责关系不变，学生调整移动和交接顺序。
- **学习证据：**采集、合法交接、运输和交付的事件链闭合，位置与货物归属一致；全局采集数量不能替代对象交接。
- **落地：**新增受控 `transfer_to(other)`、货物归属与交接条件；对象移动和能量复用现有能力。共享规则需先写明，不能靠剧情暗示。

### 第 30 课｜等到通道真的空了

**学生任务：**等通道空了，再安全通过。

- **主任务与巧思：**自动货车占用通道，按可回放的时间规则驶离。学生判断前方占位，必要时等待，再检查后前进；货车可能立刻离开，也可能晚两拍离开。
- **学生必须决定：**等待的条件和再次检查的时机。使用已学 while 与布尔检测，不引入线程、异步或并发语法。
- **找错：**固定等待一次在短延迟图成功、长延迟图仍冲突；另一错误是循环中不更新条件，永远等待。占位规则始终有效，不能因上一条指令是 wait 就取消碰撞。
- **迁移：**同代码通过初始已空、延迟 1 拍、延迟 3 拍。永久不释放的故障示范触发可解释的无进展保护，不伪装成成功任务。
- **学习证据：**条件重读、时间推进、阻挡者实际离开、学生再进入四者顺序正确。初始已空时允许零次等待，不要求每份正确程序都出现一次实际 wait。
- **落地：**必须先修确定性时间与占位模型，再制作关卡；这是本版明确的运行器改造依赖。

### 第 31 课｜让别人也能玩

**学生任务：**设计关卡，用测试证明规则成立。

- **主任务与巧思：**从建桥或接力运输模板中选一个，修改有效地图位置、目标或资源限制。系统提供任务字段表，学生用自己的参考程序跑通，再设计一个会失败的方案。
- **学生必须决定：**本关让玩家解决什么问题、什么算成功、什么限制会影响解法。学生界面叫“关卡规则”，`schema` 只出现在教师/开发说明中。
- **找错：**信标数量声明与地图不符、目标不可达、资源不足。静态校验查格式和基础连通，动态作者解验证完整规则；两者不可互相代替。
- **迁移：**同伴或内置试玩者尝试另一方案，作者据反馈修改一个有意义的规则并重跑测试。只换名字或配色不算规则创作。
- **学习证据：**规则版本、作者解、失败用例、预期与实际结果、一次有效修改。证明“存在一个解”即可，不要求枚举所有解，也不宣称连通检查证明所有动态任务可解。
- **落地：**复用 world schema 与构建，扩展作品版本、测试记录与受限模板编辑；无需公开作品平台。

### 第 32 课｜重建中继站

**学生任务：**让你的救援系统通过最后的测试。

- **主任务与巧思：**从第 31 课作品继续：读取任务数据、修复通路、由探测员采集、与运输船交接、等待通道释放、完成交付。可选已验证的建桥或接力模板，复用工具，不要求所有代码从空白写起。
- **学生必须决定：**至少一个有效世界规则和一个核心执行策略，能指出数据改动为何改变世界、条件改动为何改变行为。不能只补最后一条 wait 就毕业。
- **找错：**对自己作品中的失败或内置反例完成一次真实定位与修复，保存修改前后和关联轨迹；不要求故意破坏已正确的作品。
- **迁移：**教师选取模板契约内的两种数据/延迟变化，冻结该策略代码验证；涉及世界布局修改时允许改声明数据。另做一个资源不足或无法交接的反例，验证系统正确阻止违规行动。
- **学习证据：**数据驱动、对象独立、合法交接、条件同步、测试解释分别有证据；第 8、16、24 课的核心能力记录继续有效，不用在一份程序中刻意堆满所有语法。
- **落地：**阶段式保存作品与测试报告；前述运行能力全部通过后才开发本课。目标是可演示、可修改、可解释的系统，不以动画长度或作品规模评毕业。

## 6. 什么样的关卡才算巧妙

### 6.1 知识点必须影响任务，而非只出现在标题里

| 能力 | 能体现概念的变化 | 不足以验证的做法 |
|---|---|---|
| 顺序 | 到达前采集与到达后采集产生不同结果 | 走到目标自动采集 |
| 方向 | 镜头变化与角色朝向变化分离 | 只把同图旋转一次 |
| 规划 | 两条可行路线在不同成本下有取舍 | 显而易见的直走与无意义绕远 |
| 函数 | 一处定义影响多处调用，起止约定被验证 | 放一个没调用的函数定义 |
| 循环 | 循环体真实展开，次数或单元变化 | 只提供若干固定前进宏 |
| 条件 | 同代码在真假情况下做出不同动作 | 地图永远只有一种条件结果 |
| while | 同代码适应未知距离，含零次执行 | 地图固定，最后数对步数就过 |
| 变量 | 每次事件与状态变化对应，结果被使用 | 最后赋一个正确常量 |
| 参数/返回值 | 改输入能影响函数行为，返回结果影响调用者 | 只检查签名、函数名或 return 字样 |
| 列表/字典 | 数据变动驱动同一程序 | 只要求补上某个固定数字 |
| 对象 | 状态与能力归属清楚，不同对象互不串用 | 两个名字实际上共享隐含位置 |
| 同步 | 状态真正改变后允许行动 | 执行一次 wait 就豁免冲突 |
| 创作 | 有规则、有作者解、有失败测试 | 换名字或点击保存即算完成 |

规则限制必须有可见理由：能源约束对应实际消耗，材料约束对应实际建造，任务顺序对应交付依赖。可用代码结构要求做概念练习，但不要用任意“只准 5 行”冒充真实优化问题。物理动作数、书写长度、能源消耗分开呈现，不能混为一个效率分数。

### 6.2 三种迁移，不能混用

1. **改变方案的迁移**：如第 3、5、6、29 课，改变障碍、目标或起点，学生重新组织方案。保存新计划与新程序。
2. **保持规则的迁移**：如第 13、15、17、19、21、23、30 课，冻结关键代码，改变任务输入；相同规则仍应成立。程序不用改正是能力证据。
3. **创作与测试的迁移**：如第 7、31 课，学生改变规则或数据，并给出新的作者解和反例，证明改动有效。

等价版本需声明哪些因素可变、哪些规则保持不变。不能把多目标、空间旋转、能量紧张和新语法同时叠加给初学者。系统可以从有限题库选取版本，初期不需要无限随机生成；测试种子、地图和完整初始状态必须可复现。

对程序通用性的验证采用多输入任务；对“必须使用本课方法”的练习，另外检查实际执行结构。不能只凭几个样例通过就声称证明了所有输入，也不能把所有常量都判为作弊——合法初始值、地图配置和参数本来就可能是常量。

## 7. 学习证据与能力门

### 7.1 完成、独立验证、掌握分开记录

| 状态 | 条件 | 学生端显示 |
|---|---|---|
| 已完成任务 | 本次世界/数据目标达成，程序完整结束，允许用帮助 | “任务完成” |
| 独立验证通过 | 本课关键行为与等价新任务达标，没有本次任务的解法级提示 | “独立挑战完成” |
| 解释已提交 | 已提交标注、选择、短答或教师口头记录 | “解释已保存” |
| 能力已掌握 | 所需独立证据齐全，结构化解释题正确或教师确认理解 | 教师端显示依据，不由自由文本非空自动推断 |

核心判定路径：**完整执行 → 任务规则 → 概念实际参与 → 等价迁移 → 对应解释/教师确认。**每步的失败原因可见，可以局部补练，不能由 XP、总分、作品美观或社区活跃抵消。

强提示可以用于学习，不惩罚学生。若看过本题核心解法，保留完成记录；独立验证换一个未看解法的等价任务。基础语法释义、编辑器操作帮助、无障碍支持不计为解法提示。没有强制要求学生先“承认不会”才能查看帮助。

第 8、16、24、32 课是汇总能力门。此前能力证据缺项时明确列出需要补的短任务，保留已经通过的部分；不锁死后续课程浏览或清空整课进度。

### 7.2 最低证据结构（新增需求示意）

```text
learnerScope             # 明确账号或访客空间
curriculumVersion        # core-v1.6
lessonId / conceptId     # 稳定课程标识与能力标识
challengeId / variantId  # 具体挑战与可复现输入版本
attemptId / parentAttemptId
sourceSnapshot           # 程序或结构块快照
inputSnapshot            # 地图、目标、能量、清单、对象、时间规则
predictionOrPlan         # 该任务需要时记录
executedEvents           # 原代码行/节点、动作主体、前后状态、时序
diagnosis / codeChange   # 调试任务所需
hintExposure             # 内容、级别、对应任务版本
result                   # 世界结果、概念结果与未通过原因分开
explanation              # 类型、内容、自动结果或教师复核状态
saveState                # 本机、云端、待同步、失败
```

不要求把全部细节都展示给学生。学生只看当前相关的状态与证据，教师可以展开完整记录。重跑前保存输入快照；换数据后不能沿用上次结果而不重新执行。

### 7.3 判定实现要求

- 以真实 Python 解析为语言权威，不另造一套用正则判断 Python 意义的规则。结构性练习可检查 AST 节点，但必须关联实际执行；死代码、字符串、注释不作能力证据。
- 变量赋值、增量赋值、函数调用/返回、集合读写、分支和世界事件使用统一的事件记录。变量需区分作用域，不能把同名局部变量与全局变量混在一个槽里。
- 第 17 课检查事件与计数关系；第 19 课检查参数进入函数后影响行为；第 20 课检查返回结果影响调用者；第 23 课检查查找结果被使用。不能只看最终变量值和固定名称。
- 对支持范围内的等价表达式、变量改名、条件顺序变化和不同合法路径，允许通过。暂不支持的语法在运行前给出明确说明；无法可靠自动判定的解法标记待复核，不显示“你没有理解”。
- 每份运行都执行到结束或明确错误。采集最后一个目标后还有非法尾部指令，应记录失败，不能截断成成功轨迹。
- 世界结果与概念判定可以不同。例如直接写出固定路线可能完成地图，但在 while 独立任务中还需验证停止规则。反馈告诉学生缺哪份证据，而非否认已经完成的部分。
- 自由解释不使用关键词匹配判理解。初版不依赖大模型自动评阅儿童答案；教师判断和可直接验证的结构化题优先。

### 7.4 必须补上的反例验收

| 场景 | 应有结果 |
|---|---|
| 17：死分支放两次增量，结尾直接赋正确数量 | 世界完成可保留；计数能力不通过 |
| 17：合法 `+= 1`，逐次计数与采集一致 | 变量轨迹、界面和判定均正确 |
| 19：函数收到参数但内部写死次数 | 变化输入验证不通过 |
| 20：计算/返回正确但调用处仍使用固定值 | 返回值使用的证据不通过 |
| 22：直接遍历列表元素，不使用索引循环 | 完整处理可通过；索引能力由独立槽位题验证 |
| 14：全安全但能量恰不足，程序仍前进 | 安全规则不通过，并指向边界 |
| 15：起点就是目标 | 循环零次执行，采集后正常完成 |
| 27–29：检测 A 的状态，却行动 B | 按各对象实际状态执行；不给隐含对象切换的便利 |
| 30：等待后另一对象仍占用目标格 | 仍阻止进入，不因 wait 豁免 |
| 30：通道开始就空 | 允许立即通过，不强求等待一次 |
| 任意课：任务结束后继续执行错误指令 | 完整运行失败，保留错误前轨迹 |
| 使用强提示后重跑同一题 | 可以完成，不直接升级为独立掌握 |
| 自由短答任意输入一个字 | 仅记录提交，不自动评理解正确 |
| 旧课已完成，新课编号碰巧相同 | 保留旧记录，不自动取得新版能力 |

## 8. AI 在课程中的具体位置

初版 32 课在没有外部 AI 服务、没有聊天输入框时也必须可用。学生始终面对确定任务和可操作工具，不要求先想一个好提示词。

| 场景 | 可提供的支持 | 学生仍需完成 |
|---|---|---|
| 不懂动作或语法 | 一句话释义、一个与当前题不同的局部例子 | 把概念用到自己的任务 |
| 不知道为什么失败 | 指向实际行号、状态和一次观察问题 | 定位原因、提出修改、运行验证 |
| 非核心代码重复 | 提供已学过的移动/建造外壳或函数签名 | 本课关键条件、参数、数据或更新规则 |
| 比较一份程序建议 | 提供一份可运行但可能有缺陷的建议 | 预测、找反例、保留或修改，并用测试证明 |
| 阶段作品复盘 | 整理学生已有的轨迹和改动 | 选择关键证据并解释自己的决定 |

第 14、16、24、32 课可以安排“检查助手建议”的小任务，练习把建议当作需要验证的方案。没有真实模型时，必须标为“预设建议”或“示例程序”，不伪装成实时 AI 推理。

后续接入真实 AI 时，提示必须读取当前任务与运行证据，分级给帮助，并记录是否暴露解法。帮助不能直接修改编辑器然后自动提交；学生自己审阅和运行。即使模型不可用，预写提示与正常课程也要继续工作。

### 9.2 必须先固定的运行规则

1. **世界坐标：**统一 0 起算，`(x, y)` 对应 `grid[y][x]`，镜头不改变世界坐标。地图、课程提示、日志和 Python 必须一致。
2. **动作成本：**每课显式声明移动、护盾、上传等实际成本，UI 与运行器读取同份配置。第 13 课护盾保护下一次移动；若安全格也开盾则同样消耗能量，保护不能无限留存或隐含叠加。相关旧课必须兼容版本管理，不能悄悄改变历史任务规则。
3. **目标实体：**起点、信标、目标站与对象位置独立保存，支持起点就在目标上；不能只依赖单个地图字符表达叠加状态。
4. **对象归属：**第 27 课起，对象传感器和方法查询/修改指定对象。货物、能量、位置和身份有独立归属；类实例身份不是显示名称。
5. **交接：**基础模板要求双方位于指定交接区且相邻，发送方持货，接收方有容量。交接原子完成：发送方减少、接收方增加；同一货物不能在两个对象上各保留一份。
6. **时间：**第 30 课使用离散时间步，不与动画帧或真实网速绑定。传感器只读取状态，不推进时间；移动、转向、等待等约定动作完成后推进一拍，再执行环境脚本并保存状态。`wait` 保持当前对象位置，环境可能发生变化。
7. **占位：**动作先检查当前目标格是否可进入，时间推进后所有对象仍不得非法重叠。环境脚本也受占位约束，模板需验证不会把其他对象强行移到学生身上。等了一次不是通行凭证。
8. **预算：**所有程序有限时/事件预算；连续无进展时给出最后状态与条件。预算保护不代替课程规则，也不能把被中止的程序显示为成功。

### 11.3 课堂验证与推广门

先邀请一组约 8–12 名目标年龄学生试用代表课，覆盖零基础与有图形化经验者。按阶段安排，不要求一轮试用完 32 课。教师记录首次操作时间、卡点、提示级别、介入次数和独立任务结果；此为课程迭代样本，不作长期学习成效结论。

以下是初始迭代目标，需结合真实课堂调整：

| 观察项 | 初始目标 | 未达到时优先检查 |
|---|---|---|
| 知道先做什么 | 至少 80% 学生看完短示范后 60 秒内开始有效操作 | 任务句、操作焦点、按钮是否清楚 |
