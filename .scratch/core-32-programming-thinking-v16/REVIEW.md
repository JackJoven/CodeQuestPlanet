# 前 32 课课程与关卡审查

日期：2026-09-15。范围：当前工作区的学生课程数据、前五课新流程、Python 运行与判定，以及旧课程 PRD。本文为新版 [PRD v1.6](PRD.md) 的审查依据。

**结论：知识主线和运行基础值得保留，但需要重排部分前置知识、重做若干任务与判定。当前“能运行 32 课”不等于“32 课都足以验证学生理解”。**

本次没有修改课程代码，没有操作线上账号或数据库。以下区分代码确认、隔离运行验证和教学设计判断；没有把它们当作真实课堂效果。

## 2. 影响课程设计的主要问题

### A1. 函数学习断档，实际课程与 PRD 不一致

v1.5 第 9–10 课是函数组合、定义和调用；当前第 9–12 课是循环、缩进、能量与循环创作，生成后的前 16 课均未开启自定义函数。第 21 课却直接给出 `def move_steps(steps)`，要求修改实参。

这会把“会改括号里的数字”误当作“理解函数和参数”。新版恢复第 9–10 课的函数基础，再在第 19–20 课学习参数、返回值。

### A2. 部分任务测到了答案替换，没有充分测到概念

当前第 13 课直接写明替换哪个检测函数；第 17 课给出增量答案；第 21 课改一个实参；第 25 课改一个字典值；第 31 课把信标数改为 1；第 32 课补一次等待。它们适合作为第一次引导，单独承担一整课或毕业能力门则证据不足。

新版保留局部修改作为起步方式，但增加学生独立构造、反例和等价迁移。引导与独立验证使用不同任务实例，强提示使用情况随证据保存。

### A3. 知识密度不均，部分“阶段作品”继续引入新概念

旧第 14 课同时列出 `if/else/elif/and/or/not`；第 23 课同时出现列表、索引、遍历和切片；第 24 课继续增加 `append/insert/remove/len` 和越界。旧第 28 课标为“类与组件”，实际是给预置 `RescueKit` 补一个能力名称，并未让学生定义类。

新版将循环体、列表遍历、列表修改分别聚焦；二维数据之后再引入对象；类定义、继承、完整组件系统和双层循环不作为本轮共同核心必修。

### A4. 第 13–16 课的编辑能力与项目定义冲突

当前四课均为 `clickToBuild: true`，`app.js`据此将编辑器设为只读。项目定义则要求第 13 课开始真实编辑，第 15 课完整开放。

新版继续采用既定的真实 Python 过渡：可编辑源代码是唯一执行源，模板提供语法支持，独立验证不提供整段任务答案。不以输入速度评分。

### A5. 概念判定存在误接收和误拒绝

本次隔离运行重新确认第 17 课两种情况：

- 把两次 `collected = collected + 1` 放在 `if False:` 内，正常移动、采集两次，最后直接写 `collected = 2`。两座信标已采集，现有概念正则全部满足，最终变量也为 2，但没有发生要求的两次计数更新。
- 把正确程序中的两次更新改成 `collected += 1`。世界任务完成，但当前变量证据仍为 `{ collected: 0 }`；插桩没有记录这种赋值。

当前 `app.js` 的 `conceptChecks` 依赖源码正则，`python-runtime-core.js` 的变量追踪依赖文本模式。已有事件和最终状态是可用基础，但还不能直接支撑“已掌握”。新版要求运行事件、实际执行结构和输入变式共同验证，并接受语义等价写法。

### A6. 第 30 课的等待会绕过占位，容易教错同步

本次隔离运行当前第 30 课，加入推荐的 `atlas.wait()` 后执行 `atlas.move()`：

```text
Atlas：位置 (2, 2)，动作 [wait, move]
Nova ：位置 (2, 2)，动作 []
```

Nova 并没有移动。运行器在前一动作是 `wait` 时跳过占位冲突，因此两个对象进入同一格。等待没有推进另一个对象的行为，却被当作通行许可。

新版必须让时间推进产生可观察的世界变化，且等待后仍检查占位。第 32 课也不能再把“出现一次 wait”作为协作证据。

### A7. 地图变化不一定构成迁移

通用 `buildLessonVariantGrid()` 会保护参考路线，并在路径以外放置障碍；这种变化不能单独证明学生改变了方法。当前 Python 课程也未声明逐课成套的等价测试输入。

前五课新模块已经增加距离、目标位置、镜像、旋转和修错证据，这是进步；但旋转同一张地图本身也不能证明所有能力迁移。需要根据概念决定变化：固定指令路线可能需要重写；条件、循环、参数和数据驱动程序则应在同一份代码下适应不同输入。

### A8. 讲解与流程仍需按学习价值减量

旧 PRD 的单课包含剧情、概念、预测、引导、迁移、调试、开放创作、复盘、世界结算，负担偏重。前五课已经缩短文字，但仍可能在运行前叠加前置题、预测题、选路线与理由。

新版保留必要的概念说明，默认只显示一句目标、一条规则和一个短演示。预测可以直接在地图或状态表上操作；不要求每个短任务都填写理由、反思或人为制造一次错误。

## 4. 当前验证结果及其含义

- `scripts/test-python-runtime-core.mjs`：49 个场景与早期地图失败 UI 检查通过。
- `scripts/test-early-lessons.mjs`：61 个行为场景通过。
- 另行隔离运行当前运行器，确认 A5 的两种计数证据问题和 A6 的同格占位结果。
- 本次未做新一轮浏览器逐课试玩、32 课地图完整穷举或目标年龄学生试教。UI 字符串检查不等于浏览器验证，程序测试通过也不等于教学有效。

现有测试验证了既定行为，但尚未覆盖上述教学反例。后续要把反例纳入验收，不能通过保留旧期望把错误语义固化下来。

## 5. 保留与改造边界

**保留**：原创 3D 世界、路线与坐标操作、单步和日志、真实 Python 解析、代码版本档案、前五课的修错证据与简短文案方向。

**优先改造**：函数前置、独立编辑、每课测试输入、运行语义判定、对象归属与真实等待、阶段作品的能力证据。

**暂缓扩大**：全量 AI 对话、公开社区、排行榜、赛季、复杂组件与更大的课程库。先验证学生能否独立行动、理解反馈、把方法用到下一题。

详细课程方案、接口增量、验收与实施批次见 [PRD v1.6](PRD.md)。
