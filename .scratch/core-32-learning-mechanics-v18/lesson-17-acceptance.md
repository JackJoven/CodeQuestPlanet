# 第 17 课验收：成功采集才更新变量

内容版本：`1.8-17.1`。日期：2026-09-20。未提交、未部署。

## 已实现

- 修订旧工单，移除固定 `go_to_*()` 导航、必做修复/解释和两张独立图门槛。学生在原“选择指令 / 我的程序”中亲自编排前进、转向、`try_collect()`、`check_count(count)` 和过门路线。
- “计数工具”沿用原函数页签位置，学生选择 `count` 初值、更新时间（成功后/每次尝试后）和增量；主程序默认空白，迁移保留计数规则但路线重新从空白构造。
- 两阶段为“连接成功计数 / 回收港迁移”。构造图要求成功、重复、空采和第二次成功；迁移图改变起点、朝向、连接侧、宝石数量与路线，要求空采、成功和重复采集。一次干净迁移即可形成能力证据。
- `try_collect()` 返回真实布尔值并记录 `collect-attempt`；空采与重复采集不终止程序、不复制宝石、各推进一拍。`check_count()` 只比较 Python 变量、世界实际数和任务目标，成功才打开 `kind: count` 的计数门，绝不修改变量。
- Python 变量和世界实际宝石数分别取自变量事件与世界状态；每次尝试的成功类型、变量旧值/新值和世界旧值/新值可在折叠证据中检查。
- 左侧保持 3D 地图，任务、计数工具、原卡片、反馈、Python、俯视图与证据均在右侧；窄屏保持单列可用。

## 浏览器验证

在隔离浏览器中从空白程序开始，只通过页面自身控件操作，没有写入程序模型或掌握状态：

2. 点击“回收港迁移”，确认程序为空、同一计数规则保留；逐次点击 21 张卡完成新路线。真实播放结束后显示 `count = 1`、世界实际 `1 颗`，进度 2/2、`mastered=true`。
