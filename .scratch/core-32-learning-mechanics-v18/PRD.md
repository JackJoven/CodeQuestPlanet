## 1. 本版要解决的问题

现有课程的知识顺序可以保留，但第 16 课后不少知识点主要存在于选择题和说明中。学生走通路线，并没有实际配置变量、参数、容器或对象关系。部分修复题的真实故障与标准诊断不一致，迁移重复和掌握记录也会放大完成程度。

本版要求每课形成一条能被观察的因果链：

**学生修改本课结构 → 程序按该结构执行 → 世界发生对应变化 → 改变输入后再次验证。**

示例：第 19 课在工具页签选择 distance 参数，连接到循环次数；调用输入从 2 改成 4，Nova 就从移动 2 格变为 4 格。错误地写死 3 时，必须在真实运行中暴露偏差。

“已实现”“技术验收通过”“课堂效果已验证”分别记录。文档写完、关卡能运行、参考答案能成功，都不等于课程完成教学验收。

## 2. 保留与调整的产品决定

### 2.1 保留

- 32 课顺序、四阶段及第 8、16、24、32 课阶段作品。
- 游戏世界是主要操作环境；学生通过指令卡、结构块、数据表和对象操作构造程序。
- 规范 Python 可检查，随能力逐步开放局部编辑；不在固定课次切换为整页代码编辑器。
- 短任务、短规则、真实运行、构造与迁移；修复和解释按知识点需要选用。
- Nova、宝石、尖刺等既有统一术语；公开采集 API 使用 gem。
- 第 9–10 课的函数调用状态证据，第 13–15 课的真实条件与循环轨迹，作为保留和扩展的基础。

### 2.2 本版新增的硬性要求

1. **学生必须操作核心结构。** 选择“应该使用参数”不能代替连接参数；选择“要查字典”不能代替实际查找。
2. **可执行的错误允许发生。** 合法但错误的参数、次数、边界和规则可以运行，反馈指出实际后果；仅缺失必要结构或不受支持语法可以阻断。
3. **用于调试的坏方案包含本课故障。** 故障注入、真实日志、诊断选项和修复动作必须一致。
4. **证据来自运行。** 固定流程图标为“规则说明”；只有实际读取、修改、调用和判断事件才能标为“执行证据”。
5. **独立任务输入不同。** 不能靠改变编号、主题或美术清除提示历史；迁移不显示参考路线。
6. **正确方案可以不同。** 用语义、执行事件和任务结果判断，不能要求与参考卡片序列完全相同。
7. **阶段作品逐项验收。** 各核心能力不能用总分互相抵消，也不能在阶段作品首次引入必需工具。
8. **地形多样性服务知识点。** 高低与连通性、传送关系、机关状态和时间变化必须真正参与执行；每课最多引入一条新环境规则，并通过布局、任务和操作交替提供新鲜感。

### 2.3 操作形式与任务数量（2026-09-19 用户修订）

- 保留原有编程操作：左列指令卡、右列程序卡片，点击加入、选中后替换、删除及原工具栏。新知识扩展卡片或原工具页签，不另外造一套列表编辑器。
- 默认两阶段：学生先构造程序，再在变化后的任务中独立运用。阶段名称沿用“本课具体操作 / 具体变化迁移”的方式，例如第 19 课“连接参数槽 / 距离参数迁移”。
- 修复不是每课必做流程。第 4 课等以调试为目标的课保留；其他课可把故障作为按需提示、可选实验或工程反例。
- 不因省去修复阶段而自动放宽概念判定：构造与迁移都必须真实执行本课结构。正常、错误、边界夹具仍须由开发者验证；工程夹具不等于学生必做任务。
- 下文与旧工单里的修复方案为可用素材，不自动构成必做第三阶段。实施每课前按此规则确认任务结构，不再套统一三段模板。

### 2.4 与 v1.7 的关系

本版作为后续修改的课程机制与验收基准；v1.7 保留为历史实现记录。统一游戏外壳、逐步代码化、地图可玩尺度和术语要求继续有效。

难度按标准课和阶段整体递进。引入新概念时允许短而简单的微实验，再回到有足够决策与关系的主任务。地图规格继续参考 v1.7；不能用三行微实验单独承担一整课，也不能靠扩大空白外框达标。每个新关卡还必须满足第 6 节的有效地图要求。

AI 可提供操作提示、语法解释或非核心脚手架。学生必须亲自决定当前课的核心规则；获得强提示后，使用等价新任务重新评测。开放式 AI 对话不是本版必需入口。

## 3. 一节课应该怎样呈现

### 3.1 首屏与操作

- 一句话任务，建议不超过 30 个汉字；一条规则，建议不超过 45 个汉字。首屏首先回答“现在要改哪里”。
- 地图旁只显示当前课需要观察的状态。例如第 17 课显示计数旧值和新值，第 28 课显示两个实例各自的电量。
- 本课第一个有效操作应在两次点击或一次拖动内可达。支持点击选择与放置，不强制精确拖拽。
- 一次只突出当前一步；详细原理、术语和完整轨迹按需展开。
- 完成后显示一句具体反馈，例如“输入变成 4 后，同一个函数移动了 4 格”，并提供查看证据入口。
- 长篇文字、逐条选择题和反复点击相同动作不承担主要课时。

### 3.2 挑战单元

| 单元 | 学生做什么 | 系统提供什么 | 留下什么证据 |
|---|---|---|---|
| 短实验 | 修改一个值或结构，先观察变化 | 一个可操作的起点和一句规则 | 初次预测、真实结果；不据此判掌握 |
| 构造 | 搭建本课结构，完成主任务 | 可见目标与必要脚手架，可请求提示 | 程序版本、核心操作和执行结果 |
| 修复 | 先运行坏方案，定位根因，修改后再运行 | 与本课概念一致的故障和可回看轨迹 | 原始失败、修改差异、修复后结果 |
| 独立迁移 | 在新的输入或约束下使用同一原理 | 任务要求、状态反馈、复位；不显示答案路径 | 未受强提示污染的新任务结果 |
| 简短解释 | 指出一个关键状态或因果关系 | 指认操作或一句话入口 | 操作解释证据，或等待教师审核的文字 |

以上是可选单元库，不是每课流程清单。默认构造后进入一次独立迁移；短实验、修复、解释与扩展按本课需要出现。实际课时需试教校准，不为凑满时间加入机械任务。

### 3.3 迁移规则

- 每课准备不同输入及边界的候选任务池，用于独立练习、强提示后的等价重试和可选扩展。
- 默认一次未受强提示影响的陌生迁移即可与构造共同形成能力证据；只有本课目标必须区分多种语义时才增加必做验证，例如 if 真假两种结果。0 次、空列表等边界必须通过工程测试，是否作为学生必做任务另行判断。
- 函数、参数、数据、条件任务以同一程序应对变化为主要证据；路线规划、关卡创作允许按新世界修改程序，检查方法是否成立。
- 候选池不足时生成新的等价任务或标记“待新的独立任务”，不能重新编号旧题冒充陌生题。
- 0 次循环、空列表等情况下可以没有动作；要记录条件检查或数据读取，不能硬性要求每个场景都执行循环体。

## 4. 32 课的实施规格

以下每课默认包含构造与独立任务。真实坏方案、变化与边界均须固化为工程夹具；修复是否出现在学生必做流程按第 2.3 节决定。未通过夹具及浏览器验收的课程保持“待实现/待验收”。

本节定义核心学习操作；具体地形、机关、首次引入课次与 32 张主任务的设计方向见配套 LEVEL_DESIGN.md 第 3–5 节。两份规格共同验收，不能只完成题目配置或只完成机关美术。

### 4.1 第 1–8 课：执行、规划与分解

| 课次 / 核心能力 | 学生实际修改 | 地图与主要关系 | 真实坏方案 | 变化与边界 / 必须证明 |
|---|---|---|---|---|
| 01 顺序执行 | 排列前进与采集 | 短路线接到可辨认的目标站 | 提前采集；多走一格 | 距离 1/3/5，逐步执行；采集与到达区分，多余动作产生真实后果 |
| 02 相对方向 | 修改转向与第一段动作 | 同一地图不同初始朝向；镜头旋转另作对照 | 将屏幕右侧当成角色右侧 | 角色朝向变时程序适配；仅镜头变时程序结果不变；转向不改变位置 |
| 03 规划与成本 | 选择路径，排动作，解释成本 | 短而多转弯、长而少转弯的双通路 | 路线与计划不符，或误数转弯成本 | 分别给定动作数/转弯数目标，并提供等成本情形；接受不同合理策略 |
| 04 首次偏离与调试 | 指认状态首次不同的一步，修改该处 | 两条不同错误路径可以撞到同一堵墙 | 早转、漏走、多走三类 | 故障位置改变仍能找到根因；不能只选最终报错步或固定行号 |
| 05 坐标定位 | 根据 (x,y) 点选传送出口并规划路线 | 两座不相连岛屿、固定配对传送门与投递点 | 把 (2,5) 读成 (5,2) | x/y 不相等、接近边界、出口换位；选格与真实落点一致，传送保留朝向 |
| 06 子任务与依赖 | 排采集 A、采集 B、交付三个段落 | 中心中继站连两条支路，起点在中继站 | 未收齐就在中继站上传 | 缺 A/缺 B/收齐、支路长短变化；位置条件与收集条件分别验证 |
| 07 规则与可解性 | 改目标、障碍或动作上限，写作者解 | 受限地图编辑器，至少两个可变关系 | 目标封死或上限小于最短合法解 | 针对真实原因改规则；碰撞不能靠加上限算修好；新作品有可运行作者解 |
| 08 阶段综合 | 找坐标、规划、分段、定位一次故障 | 多目标、多路线、交付点的救援区域 | 可定位的方向或子任务错误 | 独立地图保留多目标和依赖；分别验收定位、规划、修复、完整交付 |

### 4.2 第 9–16 课：结构与控制

| 课次 / 核心能力 | 学生实际修改 | 地图与主要关系 | 真实坏方案 | 变化与边界 / 必须证明 |
|---|---|---|---|---|
| 09 定义与调用 | 编辑一份函数体，在主程序放调用 | 主干连接多个重复采集支路 | 定义正确却漏调用一个支路 | 支路数量、间距、入口靠近边界变化；同一函数实际在至少两处调用 |
| 10 调用约定 | 修改函数出口的返回动作与朝向 | 多个入口连续复用同一支路工具 | 出口位置错、出口朝向错分别出题 | 旋转入口、短返回空间；全部调用恢复约定状态，不能只补一个调用点 |
| 11 完整循环单元 | 圈出并编辑一组动作，设置次数 | 多个货架，每组需移动并采集 | 循环体漏采集；次数少一轮 | 组数 2/3/4、组内步距变化；允许错误次数运行，轨迹显示完整单元重复 |
| 12 循环作用范围 | 把动作移入或移出循环体 | 逐站采集货架与最后交付站 | 逐站任务把采集放外；最终交付放内 | 内外答案都出现；循环内采集与循环外上传组合，按事件次数验收 |
| 13 if 真假 | 分别选择条件与条件体动作 | 可通行地面上出现或不出现尖刺 | 检测岩石而不是尖刺 | 尖刺前移、后移、缺席；真实 TRUE 执行及 FALSE 跳过，条件和动作都可检查 |
| 14 布尔组合 | 连接 AND/OR，选择是否取反 | 通行性、能量、尖刺三类独立风险 | OR 放过风险；漏掉 NOT | 全真及 T/T/F、T/F/T、F/T/T；每个子条件各有独自阻止前进的情形 |
| 15 while 停止 | 选择继续条件，搭建推进状态的循环体 | 距离不预先固定的目标走廊与实验区 | 继续条件反了；循环体不推进状态 | 距离 0/1/6 与安全停止实验；每轮重查，已到达时体执行 0 次 |
| 16 阶段综合 | 组合已有函数、布尔规则和状态循环 | 检测区、通行区、采集区、交付区 | 一个模块破坏入口/出口约定 | 风险有无、目标距离、能量变化；函数、布尔、循环和依赖各自有执行证据 |

### 4.3 第 17–24 课：状态、输入输出与数据

| 课次 / 核心能力 | 学生实际修改 | 地图与主要关系 | 真实坏方案 | 变化与边界 / 必须证明 |
|---|---|---|---|---|
| 17 变量更新 | 初始化计数；把 +1 接到成功采集后 | 回收站与成功、空采、重复采集实验点 | 每次尝试前 +1 | 事件次数和成功数不同；0/1/多次成功；旧值→新值由学生规则产生 |
| 18 共享状态 | 将移动、护盾、补给接入同一能量账本 | 消耗路、尖刺路、补给站 | 护盾漏记、补给写到另一份账 | 刚够、差 1、补给后够；一次事件只记一次，所有动作读取同一余额 |
| 19 参数输入 | 参数槽连接到函数内重复次数；各调用填写实参 | 不同长度与高度的台阶码头 | 函数内部写死 3，忽略输入 | 同一函数收到 2/4/0，另有未见距离；高度不改变步数含义，详见第 5 节 |
| 20 返回值 | 放置 return 块，把调用结果连到判断 | 检测站返回状态，分岔门按结果选路 | 丢弃返回值；调用者写死判断值 | 返回真/假或 0/非 0；调用者的选择由实际返回值驱动，函数不替调用者选路 |
| 21 列表遍历 | 编辑、重排任务清单，将当前项接到访问动作 | 多站投递网络，导航辅助负责已学的移动细节 | 固定访问 A/B/C，未读取清单 | 空、单项、多项、重排；同一程序按当前清单顺序执行，无任务时安全待命 |
| 22 长度与索引 | 追加任务，读取长度，连接有效索引范围 | 沿用投递网络并新增站点 | 追加后仍用旧长度；访问 index == len | 执行前追加 0/1/2 项；空列表及最后有效索引；不漏新项、不越界 |
| 23 按键查值 | 编辑入口名称→出口坐标表，将当前名称接到查询，再使用查询结果 | 有多个目的地的可编程传送枢纽 | 查错键；改表后仍传向旧出口 | 键顺序改变、值修改、缺失键；真实查询驱动目的地，缺键时原地停止并指出键 |
| 24 阶段综合 | 遍历任务，查规则，检查库存，调用处理函数 | 仓库与多个目的地构成调度网络 | 未检库存；结果未写回 | 空任务、缺货、重排；实际派发量不超过库存，未完成项有明确状态 |

第 17 课的空采/重复采集采用可恢复的尝试语义，便于观察计数；只在指定实验工具中启用，并在 UI 标注“采集尝试”。其他课程的普通采集失败策略保持明确，不暗中全局改动。第 22 课先追加再遍历，本版不引入遍历过程中修改列表的新复杂性。

### 4.4 第 25–32 课：数据世界与对象协作

| 课次 / 核心能力 | 学生实际修改 | 地图与主要关系 | 真实坏方案 | 变化与边界 / 必须证明 |
| 25 二维数据映射 | 编辑表格单元格，指定行列映射 | 表格与非正方形地形同步 | 读取时交换 row/column | 不对称点、边界格、尺寸变化；world(x,y) 对应 table[y][x]，只改预期格 |
| 26 数据批量生成 | 编辑桥格数据，将当前项接到建造位置 | 峡谷两岸与真实缺失的桥面 | 只建第一格；坐标偏移一格 | 桥长 2/4/6、缺中间格、整表平移；生成位置与数据一致，碰撞按生成结果计算 |
| 27 对象职责 | 给方法指定执行对象 | 侦察区、运输区，两种对象能力不同 | 把搬运方法交给无搬运能力对象 | 对象起点、任务点变化；方法由选定接收者执行，错误能力调用真实失败 |
| 28 实例独立状态 | 同一行为定义绑定到 A/B，各自设置属性 | 两台同型号运输机器人、不同位置与电量 | 操作 A 时误改共享状态，B 跟着变化 | 只给 A 充电、交换起点、不同初值；共用行为但位置/电量/载物独立 |
| 29 协作交接 | 排会合、选择交出者与接收者、执行 transfer，并让一方留守压力板 | 各自可通行区、共同会合格与压力门 | 远程交接；复制宝石而非转移；留守者提前离开 | 不同位置、无持有物、接收方已满；失败不改归属，成功仅有一个 owner，门状态可观察 |
| 30 时间与条件重查 | 组合“已停靠 AND NOT 被占用”，将不可进入作为 while 条件，体内放 wait 并重查 | 升降中继塔入口与共享平台 | 固定等待两次；只查占用但未查停靠 | 初始可入、1/3 拍后可入、长期不可入；每次等待后重查，禁止固定延迟冒充条件等待 |
| 31 作品与测试 | 改关卡或数据，保存作者解、反例和边界用例 | 第 7 课编辑器升级为受限任务编辑器 | 修改作品却仍提交旧测试；只有成功例 | 正常解应成功，反例应按指定规则失败，边界应安全；三类用例真实执行 |
| 32 阶段综合 | 组合数据生成、对象分工、交接、等待、验证 | 断桥、分工区、会合点、共享通道与中继站 | 一处模块接口或状态更新错误 | 数据、对象起点、占位时长分别变化；各模块逐项达标，任一缺口不能被路线成功覆盖 |

第 27–28 课不用手写类定义作为前置。学生先操作方法接收者和实例属性；生成代码应能检查对象名称与状态归属。第 29 课会合格允许双方同格；第 30 课独占通道另有占位规则，不能把两者设为互相矛盾的全局碰撞规则。

## 5. 第一节完整样板：第 19 课“给工具一个参数”

### 5.1 学习目标与界面

学习目标：学生能定义一份使用输入的函数，在至少两次不同实参调用中复用，并能解释写死常量为什么失败。

本课内容版本为 `1.8-19.5`。保留原双码头地图、宽平台、窄桥、缺口、两级高台和两颗宝石。桌面左侧只有 3D 地图，右侧集中任务、编程、运行与反馈。

### 5.2 原操作形式与两阶段流程

**复用原来的编程操作区。**“选择指令”在左，“我的程序”在右；点击指令卡追加，点某条的“替换”后再选卡片即原位替换；× 删除，底部保留运行、单步、撤销、复位、清空。主程序默认空白，掉头、返回、过桥、转向与采集全由学生编排。

“前进工具”放在原函数页签中设置：“重复传入步数次，每次前进一步。”主程序的同类指令卡新增前进工具，点击加入 `walk(?)`，在卡片内选择本次步数 0–6。工具定义共享，每条调用各有自己的实参。固定数字也可选，合法错误方案允许真实执行。

两个必做阶段：

1. **连接参数槽**：原双码头 2/4 距离，学生设置工具并逐条编排完整程序。从 A/B 入口到宝石的两段须真实使用参数工具。
2. **距离参数迁移**：变化后的地图使用同一函数规则，学生独立构造新程序。一次有效迁移即可完成；首张为 1/5。用过强提示可换等价版本。

不再设置必做修复或额外说明提交。0/4、5/0 等图是完成后的可选练习；输入 0 时函数移动 0 次后返回，采集仍由学生安排。纯普通指令可完成世界，但不能取得参数能力证明；额外工具调用用于返回、过桥均可接受。

短实验在“需要帮助？”中按需打开，沿用学生自己的程序，观察固定两格与参数步数的差异，不计整课完成。详细帮助、Python、俯视图与记录默认折叠。说明保持简短，参数含义与职责在工具页签明确可见。

### 5.3 验收用例

| 输入/方案 | 期望世界结果 | 期望程序证据 |
|---|---|---|
| 同一函数依次接收 2、4 | 分别移动 2、4 格 | 函数定义未复制；记录两次不同实参及参数读取 |
| 距离 0 | 原地完成函数调用，主程序可继续 | 参数为 0；循环体 0 次；调用正常返回 |
| distance 存在，但体内仍重复 3 次 | 非 3 输入时出现实际偏差 | 无参数驱动循环的证据，不能判掌握 |
| 主程序为每段复制固定动作 | 可能完成当前路线 | 不满足函数输入复用能力；世界完成与能力未达标分别反馈 |
| 同一参数函数用于未见距离与新入口 | 所有对应任务成功 | 使用同一规则，独立任务未读参考答案 |

样板只有在图形操作、生成代码、真实运行和迁移全部一致后，才推广参数工具。用户可直接试玩这节完整课；不以展示一个参数输入框算完成。

## 7. 执行模型与学习证据契约

### 7.1 单一语义来源

学生编辑的结构、生成的 Python、游戏运行和学习证据使用同一份程序定义。优先复用现有运行器的参数、返回、容器和对象能力；先用第 19 课验证能否通过图形编辑接入并逐步播放，再决定适配方式。禁止继续增加“答题选项 + 另一个固定路线模拟器”的并行语义。

本版不要求先重写整个应用。旧课可通过适配层逐课接入，但同一节课的一次运行只有一个权威执行结果。文本编辑只在能与图形结构一致映射的范围内开放。

### 7.2 必须可观察的事件

| 机制 | 事件至少包含 |
|---|---|
| 变量、共享状态 | 事件原因、变量/对象身份、旧值、新值；区分学生更新与引擎真实计数 |
| 函数与参数 | 调用 ID、函数 ID、实参、参数读取、进入/离开状态 |
| 返回值 | 调用 ID、返回数据、调用处接收与后续判断使用 |
| 列表与字典 | 数据版本、当前项/索引/键、实际长度、查找结果或缺失 |
| 建造 | 数据项、生成坐标、变更前后格子、最终可通行性 |
| 对象与交接 | 执行者、接收者、能力、交接前后归属与容量 |
| 条件与时间 | 检查值、真假、tick、占位者、动作后状态及下次重查 |
| 地形与机关 | 起止格/高度/朝向、连接或设备 ID、状态前后值、主动指令与附带效果的共同来源 |

事件必须能定位到学生的结构块。状态面板显示事件中的实际值，说明文字不能伪装成运行结果。

### 7.3 关键运行语义

- 上传只记录交付成功，不自动终止整个程序；程序继续执行，最终按完整轨迹判定。上传后的错误动作必须可见并影响程序有效性。
- 循环逐轮可观察；单步不会一次执行完整个 while。纯条件检查可以单独高亮，不必伪造移动。
- 第 18 课共享账本只采用一个计费源。引擎真值用于核对学生账本，不得同时把两套扣费重复施加到角色。
- 第 25 课统一原点为左上角 (0,0)，x 向右、y 向下；表格第 y 行第 x 列对应世界 (x,y)。说明外框是否可玩，避免显示与坐标偏移。
- 第 26 课生成结果参与碰撞。重复“生成”从本次施工数据重建其负责区域，不把旧桥永久叠加留下漏洞。
- 对象状态按稳定身份保存；显示名、颜色、出生位置都不能充当状态主键。
- 第 30 课每个世界动作及其附带效果完成后推进一拍并更新环境；读取条件不推进时间。下一次判断读取更新后的停靠与占位状态，两者分开显示。长期不可进入由明确的运行上限安全停止，不能宣布通行成功；本课不额外要求学生发明超时语法。

### 8.1 判定

课程掌握证据默认包含有效构造与规定的独立迁移；仅在本课目标需要时增加修复前后或解释证据。UI 区分：

一次证据关联课程内容版本、任务语义指纹、程序版本、输入、执行轨迹、提示暴露和时间。世界更新后，旧轨迹继续属于旧版本，不能用于新版本能力门。修复的 before/after 必须是同一故障任务。
