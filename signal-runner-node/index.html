挑战：信标已经发出启动信号。让探测员向前移动两格，站到信标所在的格子，再完成采集。

程序里的指令会从上到下，一条接一条地发生：

  • move() 会让探测员沿当前朝向前进一格，并改变它的位置。
  • 排在上面的指令会先执行。下一条指令要等上一条完成后才会开始。
  • collect() 只有在探测员已经站到信标格时才会成功。

完成挑战：依次放入两条 move()，最后放入 collect()，再运行你的程序。

挑战：探测员开始时面向东，但正前方被岩石挡住。让它先转向南走两格，再转向东抵达信标并完成采集。

屏幕上的方向不会替探测员做决定。程序执行时，要以探测员自己的朝向为准：

  • turnRight() 和 turnLeft() 只改变朝向，不会移动位置。
  • move() 会沿探测员此刻面对的方向前进一格。
  • 每次转向后，先看朝向罗盘，再决定下一次前进会走向哪里。

完成挑战：按照“右转 → 前进两格 → 左转 → 前进 → 采集”的路线排列程序，然后运行验证。

挑战：同一个信标可以从两条路线到达。先比较路线，再把你选择的路线翻译成程序并完成采集。

不要急着点击指令。先判断每条路线是否可行，再比较它们的代价：

  • 动作数量越多，程序越长，需要检查的步骤也越多。
  • 每次转向都会改变后续前进方向，也会增加出错机会。
  • 路线能到达信标只是第一步，还要在正确位置执行 collect()。

完成挑战：在路线比较板中选择方案，按照路线说明排列程序，然后运行验证你的选择。

挑战：导航程序在接近信标时转错了方向。运行这段错误程序，找出第一次偏离正确路线的步骤并修复它。

程序会从上到下逐步执行。先运行一次，观察探测员从哪一步开始偏离正确路线：

  • move() 让探测员沿当前方向前进一格。
  • turnLeft() 和 turnRight() 会改变下一次前进的方向。
  • 日志会记录步骤编号，以及动作后的关键位置或朝向。第一处与预期不同的步骤，通常就是错误源头。

完成挑战：运行错误程序，点选一条指令并替换它，然后再次运行验证。只修改一处。

如果不知道怎样比较步骤，可以打开左侧的“调试侦探社（可选）”。

挑战：地图上有两座信标。根据坐标档案，先到达信标 A，再转向前往信标 B，并完成两次采集。

坐标用一对数字记录格子的位置。第一项是 x，第二项是 y：

  • 向右移动一格，x 增加 1；向下移动一格，y 增加 1。
  • turnLeft() 和 turnRight() 只改变朝向，不会立刻改变坐标。
  • 旋转观察地图不会改变任何格子的坐标。坐标描述的是地图，不是镜头。

完成挑战：按照坐标档案依次找到两座信标，每到一座信标就执行一次 collect()。

挑战：这次任务分成三段：采集信标 A、采集信标 B、把两份信号带到中继站上传。

长程序可以用几个有完成条件的子目标来理解：

  • 站在信标格执行 collect() 后，携带状态会从 0 变为 1，再变为 2。
  • 必须先完成两次采集，最后才前往中继站。
  • upload() 只有在中继站且携带 2 份信号时才会成功。

完成挑战：把程序按三段排列，观察携带状态逐段变化，最后在中继站执行 upload()。

挑战：制作你的第一张原创路线关。选择一座信标的位置，再决定采用严格还是宽松的步数限制。

一张能交给别人玩的关卡，需要同时满足三条规则：

  • 起点和目标必须清楚，信标不能放在岩石或地图外。
  • 起点到信标必须存在一条可走的路线。
  • 步数限制不能小于参考解法，否则关卡没有办法完成。

完成挑战：在原创路线工作台选择目标和限制，观察左侧 3D 地图改变，再写出程序并运行验证。

挑战：陨石干扰了信号网络。穿过一张更长的陌生地图，采集两座信标，再抵达中继站完成最终上传。

这一关没有新指令。你要把前七课的方法组合起来：

  • 先观察起点、朝向、坐标和完整路线，再开始编程。
  • 把长任务拆成“采集 A → 采集 B → 上传”三个子目标。
  • 运行失败时查看带步骤编号的日志，只修复第一处偏离。

完成挑战：完成两次采集和最终上传，逐项点亮综合能力档案。不限重试次数。
