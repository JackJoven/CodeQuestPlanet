# 产品需求文档 v1.1：CodeQuestPlanet从零到算法完整课程

状态：草案  
日期：2026-06-09

> 本版本已被 `v1.2-signal-runner-standard-course-prd.md` 替代。v1.1 把微知识点拆成 72 节课，课次粒度过细，不再作为当前课程结构使用。

## 1. 问题陈述

当前项目已经转向以 `signal-runner-node` 为主的 3D 编程学习产品。上一版文档把它定义为 6 节课作品节点，但这个范围不足以支撑“让学生从 0 学会编程、理解编程，并最终学到算法”的目标。

如果只做 6 节课，学生最多能建立序列、条件、循环、函数和调试的初步直觉，不能稳定完成以下能力：

1. 从零基础过渡到能独立写出一段可解释的程序。
2. 理解变量、状态、数据集合和程序结构。
3. 从“拖指令通关”过渡到“用算法解决问题”。
4. 形成调试、验证、复盘和作品表达的长期习惯。
5. 系统学习搜索、排序、递归、图、路径、贪心和动态规划入门。

因此，本版本把课程重新设计为一整套主线课程：

> 面向 12-14 岁零基础学生，用 3D 信标探测员任务和逐步抽象的编程挑战，完成 72 节核心课，从程序执行入门一直学到基础算法和综合算法作品。

## 2. 总体判断

建议设计为：

```text
72 节核心课
+ 12 节算法挑战选修
```

其中 72 节是主课程，适合一学年到一年半完成；12 节选修用于对算法兴趣更强、准备继续深入竞赛或真实代码项目的学生。

不建议少于 48 节。少于 48 节会导致变量、数据结构和算法部分只能点到为止，学生很容易“会点按钮但不会迁移”。

不建议一开始设计成 100 节以上。超过 100 节会让第一阶段产品过重，课程验证变慢，也会让家长难以理解学习路径。

72 节的好处：

1. 每 12 节形成一个阶段作品。
2. 6 个阶段从浅到深，结构清楚。
3. 能覆盖编程基础、数据结构和基础算法。
4. 每阶段都有可展示作品，学习不只停留在概念。
5. 后续可以按阶段拆成短期营、学期课或全年课。

## 3. 目标用户

主目标用户：

- 年龄：12-14 岁。
- 基础：零编程基础，或只接触过图形化编程。
- 兴趣：喜欢 3D 游戏、机器人、探测角色、闯关任务。
- 学习目标：想真正理解编程，而不是只做一个小游戏。

可兼容用户：

- 10-11 岁逻辑能力较强的学生，可以放慢节奏学习前 24 节。
- 15 岁以上零基础学生，可以加速完成前 36 节，再进入算法和真实代码迁移。

暂不主攻：

- 6-9 岁低龄启蒙。
- 已经系统学过文本代码和数据结构的学生。
- 以竞赛算法获奖为唯一目标的学生。

## 4. 课程总目标

学生完成 72 节核心课后，应能做到：

1. 理解程序按顺序执行。
2. 理解条件、循环、函数、变量和状态。
3. 能把一个 3D 空间任务拆成步骤和规则。
4. 能通过运行日志定位错误。
5. 能用单步执行观察程序行为。
6. 能使用列表、集合、映射、栈、队列、图等基础数据结构。
7. 能理解并应用线性搜索、二分搜索、排序、递归、深度优先搜索、广度优先搜索、最短路径、贪心和动态规划入门。
8. 能解释算法为什么有效，而不是只背答案。
9. 能完成一个综合算法作品，并用作品卡说明自己的设计、调试和验证过程。

## 5. 学习逻辑

课程从“看见程序执行”开始，而不是从语法开始。

主学习闭环：

```text
观察任务
-> 预测路径
-> 编排程序
-> 运行或单步
-> 阅读日志
-> 定位错误
-> 修改程序
-> 提炼规律
-> 学习概念
-> 迁移到新任务
```

概念推进顺序：

```text
动作顺序
-> 方向和坐标
-> 条件判断
-> 循环
-> 函数
-> 变量和状态
-> 列表和表格
-> 栈和队列
-> 图和路径
-> 搜索
-> 排序
-> 递归
-> 贪心
-> 动态规划入门
-> 综合算法项目
```

关键原则：

- 每个新概念都先通过 3D 任务出现，再抽象成编程概念。
- 每个算法都必须有可视化任务和可运行验证。
- 不追求学生背诵术语，追求学生能解释“为什么这样做”。
- 参考答案只作为对照，不能成为默认学习路径。
- 调试不是附加环节，而是每阶段都要训练的核心能力。

## 7. 完整课程框架

### 第一阶段：程序执行入门

目标：让零基础学生理解“程序是一串会被执行的指令”，并能用运行日志修正错误。

| 课次 | 主题 | 学习重点 | 任务产出 |
|---:|---|---|---|
| 1 | 第一次启动信标探测员 | 指令、程序、运行 | 让信标探测员前进到第一个标记点 |
| 2 | 按顺序采集信标 | 顺序执行 | 先到信标，再采集，再上传 |
| 3 | 方向不是视角 | 朝向、左转、右转 | 修正信标探测员朝向错误 |
| 4 | 读懂运行日志 | 错误信息、失败原因 | 根据日志修复一次撞墙 |
| 5 | 单步执行 | 一步一步观察程序 | 找出第几步开始出错 |
| 6 | 地图坐标入门 | 行、列、位置 | 说清信标探测员在地图上的位置 |
| 7 | 路径预测 | 先想后跑 | 在运行前画出预计路线 |
| 8 | 空采集错误 | 当前位置和动作匹配 | 修复不在信标格采集的问题 |
| 9 | 上传条件 | 目标位置 | 修复不在中继站上传的问题 |
| 10 | 第一组综合路线 | 顺序、方向、目标 | 完成两段转向路线 |
| 11 | 调试复盘 | 现象、原因、修改、结果 | 写出一次调试记录 |
| 12 | 阶段作品：单信标任务包 | 综合执行 | 完成 3 个单信标任务并生成作品卡 |

### 第二阶段：控制结构和状态

目标：让学生理解条件、循环、函数、变量和状态是为了解决真实任务中的变化和重复。

| 课次 | 主题 | 学习重点 | 任务产出 |
|---:|---|---|---|
| 13 | 危险格和能量 | 状态、能量变化 | 穿越危险区并保留能量 |
| 14 | 如果前方危险 | 条件判断 | 只在危险前开启护盾 |
| 15 | 条件放错位置 | 条件时机 | 修复开盾太早或太晚的问题 |
| 16 | 多条件任务 | 条件组合 | 判断危险、阻挡和信标 |
| 17 | 重复前进 | 循环入门 | 用重复指令压缩直线路径 |
| 18 | 循环次数 | 次数、边界 | 修复多走一步或少走一步 |
| 19 | 循环和动作组合 | 循环块 | 用循环完成采集前后的移动 |
| 20 | 给路线起名字 | 函数入门 | 定义一段可复用路线 |
| 21 | 调用函数 | 主程序和子程序 | 在主程序中调用路线函数 |
| 22 | 变量记录状态 | 计数、是否完成 | 记录已采集数量和任务状态 |
| 23 | 状态影响决策 | 状态驱动行为 | 根据剩余能量选择路线 |
| 24 | 阶段作品：能量与危险任务包 | 条件、循环、函数、状态 | 完成一个带危险和能量管理的任务组 |

### 第三阶段：数据结构入门

目标：让学生从单个变量进入“管理一组数据”，为后续算法打基础。

| 课次 | 主题 | 学习重点 | 任务产出 |
|---:|---|---|---|
| 25 | 多个信标怎么记 | 列表 | 保存多个信标位置 |
| 26 | 按编号访问 | 索引 | 访问第 1、第 2、第 3 个信标 |
| 27 | 遍历所有信标 | 遍历 | 逐个检查信标是否采集 |
| 28 | 二维地图表格 | 二维数组 | 用表格表示地图格子 |
| 29 | 障碍和危险标记 | 数据编码 | 标记墙、危险、水域、中继站 |
| 30 | 去重和集合 | 集合 | 避免重复采集同一信标 |
| 31 | 名字到数据 | 映射 | 用名称查找任务数据 |
| 32 | 最近一次操作 | 栈 | 撤销最近一步路线编辑 |
| 33 | 等待执行的任务 | 队列 | 让信标探测员按队列处理多个目标 |
| 34 | 数据驱动关卡 | 配置和生成 | 从任务数据生成地图对象 |
| 35 | 数据调试 | 数据错误 | 找出地图数据里的错误标记 |
| 36 | 阶段作品：信标数据管理任务包 | 列表、集合、映射、栈、队列 | 管理并完成多个信标任务 |

### 第四阶段：搜索和排序

目标：让学生理解算法开始于“在数据中找到目标、按规则整理数据、比较方法效率”。

| 课次 | 主题 | 学习重点 | 任务产出 |
|---:|---|---|---|
| 37 | 找到目标信标 | 线性搜索 | 在信标列表中找到指定目标 |
| 38 | 找最近的信标 | 最小值搜索 | 选择距离最近的目标 |
| 39 | 搜索条件 | 条件筛选 | 找到未采集且安全的信标 |
| 40 | 有序数据 | 排序的意义 | 按距离或能量消耗排列目标 |
| 41 | 选择排序直觉 | 选择最小 | 手动模拟选择排序 |
| 42 | 冒泡排序直觉 | 相邻比较 | 可视化交换顺序 |
| 43 | 插入排序直觉 | 插入到合适位置 | 整理逐步到来的任务 |
| 44 | 二分搜索 | 有序数据和中间点 | 在有序信标表中快速查找 |
| 45 | 哪个方法更快 | 复杂度直觉 | 比较线性搜索和二分搜索 |
| 46 | 排序稳定性和取舍 | 算法取舍 | 比较不同排序适用场景 |
| 47 | 搜索排序综合调试 | 边界情况 | 修复空列表、重复距离、找不到目标 |
| 48 | 阶段作品：信标检索和排序中心 | 搜索、排序、复杂度 | 做一个目标选择和排序工具 |

### 第五阶段：图和路径算法

目标：让学生把 3D 地图抽象成图，理解路径算法如何解决空间问题。

| 课次 | 主题 | 学习重点 | 任务产出 |
|---:|---|---|---|
| 49 | 地图可以变成图 | 节点、边、相邻 | 把格子地图转成可走关系 |
| 50 | 相邻格检查 | 邻居列表 | 找出当前位置能走到哪里 |
| 51 | 深度优先探索 | 深搜 | 探索一片未知区域 |
| 52 | 回退和死路 | 回溯 | 从死路退回上一个选择 |
| 53 | 递归入门 | 函数调用自己 | 用递归描述探索过程 |
| 54 | 广度优先探索 | 广搜 | 一层一层寻找目标 |
| 55 | 最短步数路径 | 广搜应用 | 找到到达目标的最少步数 |
| 56 | 路径重建 | 前驱记录 | 从搜索结果还原路线 |
| 57 | 有代价的路径 | 权重 | 危险格和普通格代价不同 |
| 58 | 最短代价路径 | 最短路径入门 | 找到能量消耗更低的路线 |
| 59 | 搜索算法调试 | 已访问、重复、边界 | 修复搜索绕圈和漏格问题 |
| 60 | 阶段作品：自动寻路任务包 | 图、深搜、广搜、最短路径 | 让信标探测员自动规划路线 |

### 第六阶段：综合算法作品

目标：让学生在真实约束中比较算法策略，完成一个能解释、能验证、能展示的综合作品。

| 课次 | 主题 | 学习重点 | 任务产出 |
|---:|---|---|---|
| 61 | 多目标任务 | 目标组合 | 规划多个信标的采集顺序 |
| 62 | 贪心策略 | 每步选当前最好 | 总是先采最近信标 |
| 63 | 贪心不一定最优 | 反例 | 找出贪心失败的地图 |
| 64 | 穷举小规模方案 | 枚举 | 比较几种采集顺序 |
| 65 | 递归生成路线方案 | 递归搜索 | 生成所有可行顺序 |
| 66 | 剪枝 | 提前停止无效分支 | 排除能量不足的方案 |
| 67 | 动态规划直觉 | 记住子问题答案 | 避免重复计算相同状态 |
| 68 | 状态表示 | 当前点、已采集集合、剩余能量 | 设计一个可计算的状态 |
| 69 | 策略评分 | 成功率、能量、步数 | 比较算法策略优劣 |
| 70 | 综合调试日 | 日志、测试地图、边界 | 用多张地图验证算法 |
| 71 | 作品打磨 | 可解释性、展示 | 完成作品卡和路线解释 |
| 72 | 毕业作品：多目标信标探测员算法挑战 | 综合算法 | 展示信标探测员如何规划、采集、避险和上传 |

## 8. 算法挑战选修

72 节核心课完成后，可提供 12 节选修挑战。它不作为所有学生必修，也不承诺竞赛全覆盖。

| 课次 | 主题 | 学习重点 | 任务产出 |
|---:|---|---|---|
| 选修 1 | 更快的排序 | 归并排序直觉 | 可视化分治排序 |

| 选修 4 | 更完整的最短路径 | 代价图 | 处理不同地形代价 |

| 选修 8 | 记忆化搜索 | 缓存 | 优化递归搜索 |
| 选修 9 | 动态规划表 | 表格推导 | 用表格解决资源分配 |
| 选修 10 | 简单博弈 | 对手和策略 | 设计巡逻对抗任务 |

## 9. 产品形态要求

课程仍沿用当前呈现形式：

- 左侧或主区域为 3D 任务地图。
- 学生可以拖拽旋转地图观察路线。
- 编程区域提供当前关卡允许的指令。

每阶段都必须有学生可见、家长可读、老师可判断的证据。

| 阶段 | 证据类型 | 说明 |
|---|---|---|
| 第一阶段 | 调试记录 | 学生能说出哪一步错了 |
| 第二阶段 | 控制结构说明 | 学生能解释条件、循环、函数的用途 |

| 第四阶段 | 搜索排序对比 | 学生能比较两种方法的效率 |
| 第五阶段 | 路径算法回放 | 学生能解释搜索如何找到路线 |
| 第六阶段 | 综合算法作品卡 | 学生能说明策略、验证和取舍 |

毕业作品卡应包含：

```text
作品名称
任务目标
我使用的数据结构
我使用的算法
我调试过的问题
我如何验证算法有效
我发现的取舍
下一步我想优化什么
```

## 11. 用户故事

1. 作为零基础学生，我希望先通过 3D 任务学习编程，这样我能看见程序执行的结果。
2. 作为零基础学生，我希望不用一开始手写复杂语法，这样我能先理解逻辑。
3. 作为学生，我希望每次失败都有日志，这样我知道问题可以被分析。
4. 作为学生，我希望能单步运行程序，这样我能看清每条指令的效果。
5. 作为学生，我希望逐步解锁指令，这样我不会被太多概念淹没。
6. 作为学生，我希望地图能旋转观察，这样我能更好地规划路线。
7. 作为学生，我希望学习条件时能看到危险格，这样我知道条件是为了解决变化。
8. 作为学生，我希望学习循环时能看到重复路线，这样我知道循环不是抽象语法。
9. 作为学生，我希望学习函数时能复用路线，这样我知道函数是给一段动作命名。
10. 作为学生，我希望学习列表时能管理多个信标，这样我知道数据结构是用来整理信息的。
11. 作为学生，我希望学习搜索时能看到目标被找到的过程，这样我知道算法不是黑盒。
12. 作为学生，我希望学习排序时能看到比较和交换，这样我能理解排序如何发生。
13. 作为学生，我希望学习图时能看到地图变成节点和边，这样我能理解路径算法。
14. 作为学生，我希望最终做一个综合作品，这样我能证明自己真的学会了。
15. 作为家长，我希望课程路径清楚，这样我知道孩子每阶段学到了什么。
16. 作为家长，我希望作品卡能展示算法和调试过程，这样我知道孩子不是只在玩游戏。
17. 作为老师，我希望每 12 节形成一个阶段，这样方便排课和验收。
18. 作为老师，我希望每节课有明确出口证据，这样方便判断学生是否理解。
19. 作为课程设计者，我希望算法从任务中自然出现，这样学生不会觉得算法只是刷题。
20. 作为产品开发者，我希望运行器和渲染器分离，这样算法逻辑可以被测试。

## 12. 实现决策

1. 主课程按 72 节核心课设计，6 个阶段，每阶段 12 节。
2. 当前 6 节CodeQuestPlanet节点可以作为第一阶段和第二阶段的雏形，但需要扩展为完整课程结构。
3. 课程不回到旧全学段路线，不再同时设计低龄启蒙和高中真实项目路线。
4. 3D 地图继续作为主要学习场景，但算法逻辑必须独立于 3D 渲染。
5. 指令运行器要逐步支持变量、列表、集合、队列、图、搜索过程和算法策略。
6. 每节课只开放当前必要指令，避免学生提前使用高级能力绕过学习目标。
7. 代码视图应从伪代码逐步过渡到接近真实代码，但不在前 24 节强迫手写语法。
8. 运行日志要持续作为调试学习核心。
9. 每阶段作品卡要由真实学习记录生成，而不是静态模板。
10. 算法挑战选修应独立于 72 节核心课，不影响主线学习完整性。

建议后续抽出的深模块：

| 模块 | 职责 |
|---|---|
| 课程模型 | 管理阶段、课次、概念、任务和出口证据 |
| 指令运行器 | 执行程序并输出状态和日志 |
| 数据结构可视化器 | 展示列表、集合、队列、图等结构 |
| 算法过程记录器 | 记录搜索、排序和路径计算过程 |
| 失败日志生成器 | 把失败状态转成学生能读懂的提示 |
| 作品证据生成器 | 汇总调试、算法和作品说明 |
| 视角控制器 | 控制 3D 地图旋转和渲染节流 |

## 13. 测试决策

测试重点不应放在 3D 美术细节，而应放在学习行为是否正确。

优先测试：

1. 指令顺序是否按预期执行。
2. 撞墙、空采集、错误上传是否产生正确日志。
3. 条件判断是否只在条件成立时执行动作。
4. 循环是否展开为正确次数。
5. 函数调用是否执行函数体。
6. 列表遍历是否覆盖所有目标。
7. 集合是否避免重复采集。
8. 队列是否按顺序处理任务。
9. 线性搜索是否找到目标或正确返回找不到。
10. 二分搜索是否只用于有序数据。
11. 排序结果是否正确。
12. 深搜和广搜访问结果是否符合预期。
13. 最短路径是否避开障碍并生成可回放路线。
14. 算法作品卡是否包含算法、调试和验证证据。
15. 地图旋转是否不改变任务逻辑结果。

## 14. 验收标准

完整课程设计验收：

1. 明确 72 节核心课和 12 节选修挑战。
2. 72 节课从零基础逐步推进到基础算法。
3. 每 12 节有一个阶段目标和阶段作品。
4. 每节课都有学习重点和任务产出。
5. 算法内容不是孤立刷题，而是嵌入 3D 信标探测员任务。
6. 课程包含变量、状态、函数、数据结构、搜索、排序、图、路径、递归、贪心和动态规划入门。
7. 每阶段都有可展示证据。
8. 最终作品能证明学生理解算法取舍和调试验证。

产品实现验收：

1. 当前 3D 任务框架可以承载第一阶段课程。
2. 指令运行器可以逐步扩展到变量、数据结构和算法过程。
3. 运行日志和单步执行贯穿整个课程。
4. 3D 视角操作不影响程序逻辑。
5. 作品卡从静态展示升级为学习证据汇总。

## 15. 非目标

本版本不做：

- 6-9 岁低龄启蒙课程。
- 高中真实软件工程课程。
- 竞赛算法完整体系。
- 一开始就手写完整真实代码。
- 复杂开放世界 3D 游戏。
- 多人联网。
- 账号系统。
- 云保存。
- 后端管理平台。
- 真实人工智能模型接入。
- 让人工智能自动替学生完成程序。

## 16. 风险和取舍

| 风险 | 表现 | 对策 |
|---|---|---|
| 课程太长 | 学生和家长看不到阶段成果 | 每 12 节形成一个作品 |
| 3D 游戏感太强 | 学生只玩画面 | 每节课绑定出口证据 |
| 算法太抽象 | 学生回到死记公式 | 所有算法先从任务和可视化出现 |
| 前期不写真实代码 | 后续迁移困难 | 代码视图逐步从伪代码过渡到真实表达 |
| 参考答案被滥用 | 学生跳过思考 | 先预测、运行、调试，再允许对照 |
| 数据结构阶段枯燥 | 学生看不到用途 | 每种结构都绑定信标探测员任务 |
| 动态规划过难 | 学生挫败 | 只做入门直觉，不做竞赛难题 |

## 17. 推荐落地顺序

不要一次性开发 72 节。

建议落地顺序：

1. 先把第 1-12 节做成完整可交付阶段。
2. 再扩展第 13-24 节，完成控制结构和状态。
3. 第 25-36 节开始引入数据结构可视化。
4. 第 37-48 节加入搜索排序过程可视化。
5. 第 49-60 节加入图和路径算法。
6. 第 61-72 节做综合算法作品。

每完成一个阶段，都应进行一次学生试玩和家长反馈验证。

## 18. 本版本结论

这套课程不再是 6 节作品节点，而是一整条 12-14 岁零基础编程主线。

一句话定位：

> CodeQuestPlanet是一套用 3D 信标探测员任务教会学生真正理解编程和算法的课程：先看见程序如何执行，再学会调试和组织数据，最后用搜索、排序、图和路径算法解决复杂任务。
