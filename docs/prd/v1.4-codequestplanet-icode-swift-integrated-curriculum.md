# 产品需求文档 v1.4：CodeQuestPlanet iCode × Swift Playgrounds 融合课程体系

状态：草案

日期：2026-07-14

替代版本：v1.3

适用对象：10-14 岁零基础或有图形化编程基础的学生

标准课时：每课 60-90 分钟；校内 40-45 分钟课时可拆成两次

## 1. 版本结论

v1.4 不再把所有学生固定在同一条 48 课算法路线中，而是改为：

```text
32 节共同核心
+ 16 节算法探索分支
+ 16 节互动创作分支
= 64 节完整课程库
```

学生通常完成 48 节：32 节共同核心加一个 16 节分支。也可选择 8 节算法加 8 节创作的均衡路线。能力较强、课时充足的学生可以完成全部 64 节。

这个结构同时保留三类优势：

1. iCode 的多对象协作、Python 式代码表达、失败反馈、列表/字典/函数/递归/类等知识覆盖。
2. Swift Playgrounds 的小步递进、类型与初始化、世界建造、触摸事件、图形声音、组件化和开放创作。
3. CodeQuestPlanet 已形成的 3D 地图、日志、单步、数据结构、搜索和路径算法特色。

## 3. iCode 与 Swift Playgrounds 的异同

### 3.1 共同覆盖

两者共同覆盖的稳定主干是：

```text
命令与顺序
-> 路线规划与调试
-> 函数
-> for 循环
-> 变量
-> 条件与逻辑运算
-> while 循环
-> 参数
-> 列表/数组
-> 对象与世界
-> 综合创作
```

共同的教学方法是：学生先观察环境，再把自然语言步骤变成代码，通过可视化运行结果修正程序。

### 3.2 iCode 更强的部分

- Neo、Spaceship、Flyer、Solar、Item 等多对象协作。
- 前进、后退、转向、等待、坐标、能量和运载等任务动作。
- 步数错误、能量耗尽、危险能量、漏收集、障碍和工具冲突等明确失败类型。
- Python 缩进、参数数量、未定义名称、属性不存在、索引越界和死循环等语法反馈。
- 列表、字典、函数返回值、递归、类、注释、迷宫、数独和竞赛主题。
- 图形化到 Python/C++ 的迁移潜力。

### 3.3 Swift Playgrounds 更强的部分

- 每章由导入、引导练习、迁移练习和开放挑战组成，学习坡度更平滑。
- 函数较早出现，先建立“分解和复用”再进入复杂控制结构。
- 类型、属性、方法、初始化和多实例有连续关卡，不只是术语。
- 数组覆盖存储、遍历、索引变化、插入、删除、越界、随机生成和重构。
- 从解谜自然过渡到世界建造、坐标图形、触摸、事件、文字、语音和声音。
- 最终从玩家转为工具、互动作品和 App 的创造者。

### 3.4 当前材料的共同缺口

- 16/24 课版知识密度过高，不能承担完整掌握目标。
- v1.3 虽有 48 课，却默认所有学生都学到动态规划，分层不足。
- iCode 大纲中的“类”没有类型与初始化的前置阶梯。
- 列表/数组、字典、二维地图的关系没有统一数据模型。
- 事件驱动、图形、声音、组件化和作品交互没有形成连续课程。
- 缺少从积木、双栏代码到独立文本代码的明确迁移门槛。
- 评价强调完成和展示，但缺少阶段能力门、自动证据和可复用作品档案。
- 原始地图数量很大，但没有关卡元数据、难度标签和知识点覆盖矩阵。

## 4. 产品定位

CodeQuestPlanet 是一套以 3D 星际任务为主场景的编程思维与创作课程。学生先控制角色和工具解决地图问题，再学习用数据描述世界、用算法规划行为、用事件和组件创建互动作品。

课程不是 Swift Playgrounds 的复刻，也不是 iCode 地图的搬运。它使用原创角色、世界、关卡、文本和代码接口，吸收两者已验证的知识顺序与反馈机制。

完成共同核心后，学生应能：

1. 预测程序执行结果并用证据调试。
2. 使用顺序、函数、循环、条件、变量和数据容器组织程序。
3. 理解类型、实例、属性、方法、参数和返回值。
4. 用数据描述地图、对象、目标和规则。
5. 设计可运行、可测试、可解释的原创关卡。

完成算法分支后，学生应能用搜索、排序、图和路径算法解决任务，并比较算法取舍。

完成创作分支后，学生应能使用坐标图形、事件、状态、声音和组件完成互动故事、游戏或工具作品。

## 6. 单节标准课结构

每节课不是一个知识点，而是一个完整任务包。建议包含 5-7 个页面或挑战单元：

| 环节 | 建议时间 | 页面/挑战作用 |
|---|---:|---|
| 剧情与概念导入 | 5-8 分钟 | 用现实类比或动画说明为什么需要新概念 |
| 观察与预测 | 8-12 分钟 | 标记地图、状态和目标，先写预测 |
| 引导挑战 | 10-15 分钟 | 只变化一个因素，建立正确操作 |
| 迁移挑战 | 15-20 分钟 | 换地图或条件，不照抄上一题 |
| 调试挑战 | 10-15 分钟 | 阅读错误程序、日志或状态并修复 |
| 开放挑战 | 10-20 分钟 | 比较方案、优化或补全作品 |
| 复盘与作品卡 | 5-10 分钟 | 记录策略、失败、修改和证据 |

统一学习闭环：

```text
接收任务
-> 侦察环境
-> 预测方案
-> 编写程序
-> 运行/单步
-> 阅读状态和失败证据
-> 修改与重构
-> 迁移或创作
-> 讲解与保存作品
```

## 10. 图形化到文本代码的迁移

| 阶段 | 默认表达 | 学生责任 | 教师验收 |
|---|---|---|---|
| 1-8 | 指令块 + 同步代码镜像 | 排序、组合、预测 | 能读懂对应代码行 |
| 9-16 | 结构块 + Python 式代码镜像 | 修改次数、条件和函数名 | 能解释缩进和代码块 |
| 17-24 | 双栏模式，可编辑变量和参数 | 补全表达式、修复语法 | 能根据错误定位行和原因 |
| 25-32 | 文本优先，积木可作提示 | 编写数据、函数和对象调用 | 能独立完成短程序 |
| 算法/创作分支 | 文本代码 + 可视化状态 | 组织多函数程序和项目文件 | 能解释结构、测试和取舍 |

必须覆盖的文本错误：未知指令、参数遗漏、参数过多、未定义名称、错误属性、非法赋值、索引越界、缩进错误、死循环和禁止指令。

## 11. 关卡内容标准

每个关卡必须声明：

```text

mapOrScene
startState
successCriteria

expectedConceptUse

extensionChallenge
artifactFields

```

设计要求：

1. 每个引导关只新增一个主要变量。
2. 每节至少有一个调试关，不只检测最终成功。
3. 每个概念至少经历“引导、迁移、调试、开放”四种任务。
4. 允许多个正确解法，并分别记录步数、能量、代码长度和可读性。
5. 参考策略用于教师和测试，不作为学生默认入口。
6. 每张学生创作关必须通过可解性、边界、目标和资源校验。

## 12. 调试与学习证据系统

运行或单步时应记录：

- 当前步骤和高亮代码。
- 每个对象的位置、朝向、能量和任务状态。
- 变量旧值、新值和变化来源。
- 列表/字典的当前内容和索引操作。
- 函数调用、参数、返回值和调用栈。
- 搜索分支中的 visited、栈、队列、前驱和路径。
- 事件分支中的事件类型、参数、目标对象和处理器。

统一失败类型：

```text
wall_hit
wrong_direction
empty_collect
missing_target
wrong_delivery
energy_empty
hazard_contact
tool_state_conflict
invalid_command
missing_argument
extra_argument
undefined_name
invalid_property
invalid_assignment
index_out_of_bounds
invalid_indentation
infinite_loop
invalid_level_data
unreachable_goal
event_handler_error
```

失败反馈采用三层：

1. 现象：发生了什么。
2. 证据：在哪一步、哪个对象、哪个状态发生。
3. 提问：学生下一步应该检查什么，不直接给答案。

## 13. 学生产出与评价

每节作品卡至少包含：目标、预测、程序、第一次失败、失败证据、修改、最终结果和可优化点。

每 8 课阶段作品增加：回放或截图、测试用例、策略比较、同伴反馈和口头讲解。

建议总评：

| 维度 | 权重 | 关注点 |
|---|---:|---|
| 任务完成 | 30% | 能满足目标和限制，不只偶然跑通 |
| 调试证据 | 25% | 能定位现象、原因、修改和结果 |
| 思路解释 | 20% | 能说明选择、状态和算法理由 |
| 创作与迁移 | 15% | 能修改规则、设计变式或原创作品 |
| 协作与反馈 | 10% | 能轮换角色、阅读他人代码并给出建议 |

小队角色继续使用舰长、导航员、工程师、调试官和讲解员，但每节必须轮换。

## 16. 原始 iCode 地图的使用方式

4826 个公开 `stage_*.tmx` 文件名只能证明资源存在，不能证明它们与目标课程逐关对应。它们不应直接写进课程主表。

正确流程：

1. 建立地图资产目录，不混入教学大纲。
2. 为实际可读取地图生成尺寸、对象、路径、机关和难度特征。
3. 人工抽查后标注知识点、前置能力、可解性和适用课次。
4. 只把通过授权和原创性审查的结构灵感转成 CodeQuestPlanet 原创地图。
5. 课程引用自己的关卡 ID，不引用无法确认的 iCode 逐关映射。

## 17. 与 v1.3 的关键变化

| v1.3 | v1.4 优化 |
|---|---|
| 48 节固定单线 | 32 节共同核心 + 两个 16 节分支 |
| 所有学生进入 DFS、BFS、贪心、DP | 学生按兴趣和能力选择算法、创作或均衡路线 |
| 类型与初始化分散 | 第 19-20 课连续建立类型、实例和初始化 |
| 数组主要作为多目标工具 | 单列索引、修改、越界和重构任务包 |
| 创作主要是关卡编辑 | 增加图形、触摸、事件、文字、声音和互动作品 |
| 积木与文本迁移未分阶段 | 明确四阶段迁移和文本错误验收 |
| 原始 iCode 材料角色不清 | 明确证据、知识、机制、短课和主课程五层文档关系 |

## 18. 验收标准

课程验收：

1. 32 节共同核心和两个 16 节分支均有明确任务、知识、产出和能力门。
2. iCode 公开显式知识点全部进入共同核心或算法分支。
3. Swift Playgrounds 的类型/初始化、数组重构、世界建造、事件和创作链路均有对应课程。
4. 每节包含引导、迁移、调试和开放任务，不以单个微知识点充当整节课。
5. 每 8 节形成可保存、可试玩、可讲解的阶段作品。

产品验收：

1. 课程数据、地图数据和运行逻辑分离。
2. 调试系统能展示状态变化和结构化失败证据。
3. 学生能从积木逐步迁移到文本代码。
4. 共同核心完成后，算法和创作分支都能独立运行。
5. 学生原创关卡或互动作品可保存、校验、试玩和评价。

## 19. 一句话定位

CodeQuestPlanet 让学生先用代码探索世界，再用数据和算法理解世界，最后用事件与组件创造自己的世界。
