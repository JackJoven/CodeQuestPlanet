# 产品需求文档 v1.3：CodeQuestPlanet Code Quest 创作型课程大纲

状态：草案  
日期：2026-07-08  
替代版本：v1.2  
适用项目：`signal-runner-node`

## 1. 版本目标

v1.3 在 v1.2 的 48 节标准课基础上，吸收 iCode 公开资料中的知识点完整性、失败调试路径、课堂互动和学生出题机制，重新定义一套更适合开发落地的课程主线。

本版重点解决三个问题：

1. 知识点要更完整：补齐后退、等待、坐标、变量、列表、字典、参数函数、返回值、while、多对象协作等基础能力。
2. 学生要更多动手：每 4 节课安排一次创作关，让学生从“解题者”逐步变成“设计者”。
3. 开发要能执行：课程大纲不仅写教学目标，还明确产品功能、关卡数据、创作工具和验收标准。

## 2. 产品定位

CodeQuestPlanet Code Quest 是一套面向 10-14 岁学生的 3D 编程闯关课程。学生通过控制信标探测员在 3D 地图中移动、采集、避险、上传、协作和自动寻路，学习编程基础、数据结构和算法思维。

课程不以“记住语法”为目标，而是训练学生完成一条完整的问题解决链路：

```text
观察任务 -> 规划路线 -> 编写程序 -> 运行验证 -> 调试修改 -> 解释复盘 -> 创作新关
```

学生最终要能做到：

1. 看懂地图目标、障碍、危险、工具和限制。
2. 把任务拆成路线、动作、条件、状态和数据。
3. 使用顺序、循环、条件、变量、函数、列表、字典和对象协作完成任务。
4. 根据日志和失败提示定位错误，而不是随机试错。
5. 设计自己的关卡，写清规则、限制、陷阱、参考解法和评分方式。
6. 用作品卡讲清自己的策略、错误、修复和优化。

## 3. 设计原则

### 3.1 先体验，再抽象

每个知识点都先出现在关卡任务里，再抽象成编程概念。

例如：

- 学生先看到角色沿当前朝向走错方向，再学习“朝向”和“视角”的区别。
- 学生先发现重复路线太长，再学习循环。
- 学生先遇到危险格和能量变化，再学习条件和变量。
- 学生先需要管理多个目标，再学习列表和字典。

### 3.2 每节课都要有调试

每节课至少设计一个典型错误。错误不是扣分点，而是学习入口。

常见失败卡：

- 撞墙：路线预测或方向判断错误。
- 空采集：动作位置错误。
- 提前上传：状态顺序错误。
- 能量耗尽：路线或策略需要优化。
- 漏采集：目标列表或遍历遗漏。
- 危险格失败：条件判断或护盾时机错误。
- 工具状态冲突：多对象协作顺序错误。
- 死循环：while 或搜索停止条件错误。

### 3.3 每 4 节一次创作

每 4 节课形成一个小循环：

```text
第 1 节：引入新能力
第 2 节：变式练习
第 3 节：调试和优化
第 4 节：学生创作关
```

创作关不是自由发挥到失控，而是给出清晰模板：

1. 学生设计地图。
2. 学生写任务目标。
3. 学生设置至少一个限制。
4. 学生写自己的通关程序。
5. 学生故意或真实记录一次失败，并说明如何修改。
6. 同伴试玩并给出反馈。

### 3.4 每 8 节形成阶段作品

第 4、12、20、28、36、44 节偏“小创作”。  
第 8、16、24、32、40、48 节偏“阶段作品/作品展示”。

这样学生既有频繁动手机会，也有阶段性成果。

## 4. 总体结构

主线为 48 节标准课，分成 6 个阶段。每节课建议 60-90 分钟；如果机构采用 45 分钟课时，可拆成两个校内课时。

| 阶段 | 课次 | 阶段名称 | 核心能力 | 阶段作品 |
|---|---:|---|---|---|
| 第一阶段 | 1-8 | 基础动作与路线规划 | 顺序、方向、后退、等待、坐标、日志 | 基础采集上传任务包 |
| 第二阶段 | 9-16 | 循环、条件与状态 | for、range、缩进、if、逻辑、while、能量 | 能量与危险关卡包 |
| 第三阶段 | 17-24 | 变量、函数与多目标任务 | 变量、计数器、函数、参数、返回值、列表 | 函数工具箱任务包 |
| 第四阶段 | 25-32 | 数据建模与多对象协作 | 字典、二维地图、数据驱动、多对象、等待同步 | 飞船协作任务包 |
| 第五阶段 | 33-40 | 搜索、排序与路径规划 | 搜索、排序、visited、DFS、BFS、路径还原 | 自动寻路任务包 |
| 第六阶段 | 41-48 | 综合算法与原创作品 | 贪心、反例、枚举、剪枝、动态规划入门、测试 | 毕业原创关卡 |

### 6.2 学生创作提交物

每次创作关都必须提交 6 件东西：

1. 关卡名：一句话说明关卡主题。
2. 地图：起点、目标、障碍、危险、工具和中继站位置。
3. 任务目标：学生需要完成什么。
4. 限制条件：最大步数、最大能量、必须使用的知识点或禁止使用的指令。
5. 参考解法：学生自己的通关程序或策略。
6. 调试记录：至少一次失败、失败原因和修改方式。

### 6.3 创作关评价标准

| 维度 | A 表现 | B 表现 | C 表现 |
|---|---|---|---|
| 规则清晰 | 目标、限制、成功条件都清楚，别人能独立试玩 | 目标基本清楚 | 需要作者解释才能试玩 |
| 地图合理 | 有挑战、有可行路线、没有无解陷阱 | 能跑通但挑战较弱 | 容易无解或规则冲突 |
| 知识使用 | 明确用到本阶段核心知识，并能解释原因 | 使用了部分核心知识 | 主要是堆动作 |
| 调试证据 | 有失败现象、原因、修改和结果 | 有简单失败记录 | 没有有效调试记录 |
| 表达展示 | 能讲清设计意图和解法取舍 | 能说明大致思路 | 表达依赖追问 |

### 7.3 调试系统

调试系统要从“日志列表”升级为“学习证据”。

最低要求：

1. 每一步显示步骤编号、指令、位置、朝向、能量、携带状态。
2. 失败时显示失败类型，而不是只显示失败文本。
3. 失败卡可保存到本节作品卡。
4. 单步执行能高亮当前指令。
5. 变量课程后，单步执行显示变量旧值和新值。
6. 搜索算法课程后，回放显示 visited、队列、前驱和路径。

失败类型建议：

```text
wall_hit
empty_collect
wrong_upload
energy_empty
hazard_without_shield
missing_target
tool_state_conflict
infinite_loop
invalid_condition
invalid_function
invalid_level_data
```

### 7.4 作品卡系统

作品卡不是装饰，而是课程闭环的一部分。

作品卡字段：

- 关卡名
- 我使用的知识点
- 我的路线或策略
- 第一次失败
- 失败原因
- 我修改了什么
- 最终结果
- 我觉得还可以优化哪里
- 同伴反馈

阶段作品卡额外字段：

- 作品截图或回放
- 参考代码
- 测试结果
- 展示讲稿
- 评分量规

### 7.5 创作工具

短期不必一次做完整地图编辑器，可以分三步：

1. 创作模板 v0：学生先在页面内填写关卡目标、限制和路线说明，地图由系统给定几个模板。
2. 地图编辑 v1：学生可以选择格子类型：空地、墙、危险、信标、中继站、起点。
3. 数据驱动 v2：学生可以保存、导入、试玩和分享自己的关卡。

最小可用创作工具需要：

- 选择地图尺寸。
- 放置起点。
- 放置信标和中继站。
- 放置墙和危险格。
- 设置最大步数或能量。
- 运行可行性检查。
- 保存关卡草案。
- 切换到试玩模式。

## 9. 课程验收标准

课程设计验收：

1. 48 节课均有主题、知识点、任务、产出和开发要点。
2. 每 4 节至少有一次创作或作品化任务。
3. 每 8 节形成一个阶段作品。
4. 知识点覆盖基础动作、坐标、调试、循环、条件、变量、函数、列表、字典、多对象、搜索、排序、图、路径和综合策略。
5. 每个阶段都有可展示成果，而不是只留下练习记录。

产品实现验收：

1. 每节课可以作为独立任务入口。
2. 每个任务有地图、允许指令、目标、限制、参考解法和失败提示。
3. 运行和单步执行能显示关键状态。
4. 失败可以转化为失败卡和作品卡记录。
5. 创作关可以保存学生的关卡规则和解法。
6. 阶段作品可以给同伴试玩或展示。
