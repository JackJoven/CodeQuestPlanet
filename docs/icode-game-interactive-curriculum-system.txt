ICode 游戏互动类课程体系设计
课程名：星际救援编程营
生成日期：2026-07-07

设计依据：前面已整理的 ICode 公开静态资源中可见的关卡流程、公开课程名、操作指令、知识点、失败提示和地图资源名。
使用边界：本体系用于学校教学设计，不包含登录后受保护关卡详情、官方答案或学生个人数据。

一、课程总目标
==============
- 让学生把编程理解为“控制角色解决问题”，不是死记语法。
- 用游戏任务带动观察、规划、编码、运行、调试、复盘的完整学习闭环。
- 从图形化/Blockly 逐步过渡到 Python 或 C++ 的程序思维。
- 让不同水平学生都能参与：基础学生能完成路线，进阶学生能优化算法，高阶学生能设计关卡。
- 把失败提示转化为调试线索，让学生愿意反复尝试。

二、核心游戏循环
================
- 1. 接任务：老师发布剧情目标，例如救援、收集能量、修复飞船。
- 2. 侦察地图：学生标出起点、目标、障碍、能量、工具和危险点。
- 3. 小队策略会：先画路线，不急着写代码。
- 4. 编码闯关：把路线变成指令、循环、条件、变量或函数。
- 5. 运行验证：观察 Neo、Spaceship、Flyer 等对象是否按预期行动。
- 6. 调试复盘：用失败提示定位问题，记录修改原因。
- 7. 升级展示：讲清楚算法，获得徽章，进入下一章。

三、游戏化机制
==============

能量晶体积分：完成任务得 1-3 颗能量晶体；清楚解释思路比单纯跑通更重要。建议比例：完成 40%，调试记录 25%，讲解表达 20%，合作 15%。

徽章技能树：把知识点做成徽章：方向感、路线规划、循环引擎、坐标大师、变量管家、逻辑守卫、函数工程师、关卡设计师。学生每拿到一个徽章，就在班级技能树上点亮。

小队职业系统：每组 4-5 人轮换职业：舰长定目标，导航员画路线，工程师写代码，调试官记录失败，讲解员做复盘。每节课轮换，避免固定强弱分工。

Boss 关卡：每 2-3 课设置一次 Boss 关卡，必须组合两个以上知识点。比如“循环 + 坐标”“变量 + 条件”“列表 + 函数”。

失败卡收藏：把失败提示变成可收藏的调试卡：步数出错、能量耗尽、红色能量、漏收集、不能通过、工具状态冲突。学生不是被扣分，而是获得一张“调试线索”。

学生出题权：到后期让学生设计小关卡。要求写清楚目标、限制、陷阱、参考解法和评分方式。出题会极大提高参与感。

四、8 章主线课程
==================

第 1 章：新兵入舱（第 1-2 课）
----------------------------------
剧情任务：飞船被陨石带迫降，学生成为 Neo 的地面指挥员，要先学会下达最基础的行动指令。
核心知识：
- 游戏规则
- 顺序执行
- 前进/后退/转向/等待
- 一步一格
- 成功与失败反馈
互动玩法：
- 真人地图：在地面贴 5x5 方格，一名学生扮演 Neo，其他学生只能用口头指令控制它。
- 指令拍卖：每组只有有限指令卡，必须买最少的指令完成路线。
- 预测挑战：运行代码前，每组先举牌预测 Neo 的终点和朝向。
课堂任务：
- 完成 3 条短路线：直线、转弯、绕开一个障碍。
- 写一张“我的第一份指令表”：每一步写出动作和预期位置。
学生产出：个人任务卡：路线图 + 指令序列 + 一句话复盘。
可授予徽章：首次点火徽章、方向感徽章

第 2 章：能源搜救（第 3-4 课）
----------------------------------
剧情任务：飞船能量不足，学生需要规划路线收集散落的能量块。
核心知识：
- 路线规划
- 数格子
- 步数优化
- 调试
- 能量遗漏检查
互动玩法：
- 能量竞速：同一地图比谁用更少步数收集全部能量。
- 调试侦探：老师故意给一段错误路线，学生根据失败提示找出第几步错了。
- 路线博弈：每组展示路线，其他组找可能的风险点。
课堂任务：
- 画出至少两条路线，并比较步数和可读性。
- 建立“失败原因表”：步数错、撞墙、漏能量、误吃危险能量。
学生产出：小组路线战报：最短路线、最稳路线、最容易讲清楚的路线。
可授予徽章：能源收集徽章、调试侦探徽章

第 3 章：循环引擎（第 5-6 课）
----------------------------------
剧情任务：飞船引擎可以自动重复动作。学生要发现路线中的重复规律，用循环节省代码。
核心知识：
- 重复执行
- for 循环
- range
- 循环次数
- 循环体
- 缩进
互动玩法：
- 找重复纹路：把路线贴在白板上，让学生圈出重复片段。
- 笨办法挑战：先用重复指令完成，再改写成循环，比较代码长度。
- 缩进剧场：学生站成不同缩进层级，老师朗读代码，学生判断谁会被循环执行。
课堂任务：
- 把连续 4 次以上的重复动作改写为循环。
- 解释循环体里每条指令总共执行了几次。
学生产出：循环改造单：原始代码、循环版代码、节省了多少行。
可授予徽章：循环引擎徽章、代码压缩徽章

第 4 章：星图坐标站（第 7-8 课）
----------------------------------
剧情任务：地图越来越大，靠肉眼记路线不够了。学生开始用坐标记录 Neo、物品和工具的位置。
核心知识：
- 坐标
- 对象位置
- Item 坐标
- Neo 坐标
- 坐标表
- 地图建模
互动玩法：
- 坐标寻宝：老师报坐标，学生在地图上找到能量点。
- 盲人导航：一名学生看不到地图，只能听队友报坐标和指令完成路线。
- 坐标接力：每组轮流补全一张能量点坐标表。
课堂任务：
- 为一张地图建立坐标表：Neo 起点、能量点、障碍点、终点。
- 用坐标解释为什么某一步要转向或等待。
学生产出：星图档案：地图草图 + 坐标表 + 路线说明。
可授予徽章：星图导航徽章、坐标大师徽章

第 5 章：变量能量舱（第 9-10 课）
----------------------------------
剧情任务：飞船需要实时记录能量、步数和任务状态。学生用变量保存会变化的信息。
核心知识：
- 变量
- 赋值
- 修改变量
- 变量计算
- 计数器
- 状态追踪
互动玩法：
- 变量记分员：每组指定一名学生只负责记录变量每一步后的变化。
- 能量账本：收集能量加分，走错路扣能量，把变量变化画成表格。
- 变量猜谜：老师展示变量变化表，学生反推发生了哪些动作。
课堂任务：
- 设计一个 count 计数器，记录收集到的能量数量。
- 用变量表追踪每一步后的步数、能量或坐标。
学生产出：变量追踪表：代码行、动作、变量旧值、变量新值。
可授予徽章：变量管家徽章、状态追踪徽章

第 6 章：危机判断室（第 11-12 课）
----------------------------------
剧情任务：地图出现红色能量、障碍和不确定路线。学生需要让程序学会判断。
核心知识：
- if
- if else
- elif
- 条件判断
- 逻辑运算符
- and/or/not
- 风险避让
互动玩法：
- 条件法庭：老师给出一个判断规则，学生辩论它是否足够安全。
- 红色能量避险：小组设计“能吃/不能吃”的规则卡。
- 逻辑拼图：把“前方可走”“还有能量”“不是红色”拼成复合条件。
课堂任务：
- 写出至少 3 条自然语言规则，再改写成条件语句。
- 比较 and、or、not 改变后会导致什么路线风险。
学生产出：安全协议卡：条件规则 + 示例地图 + 可能失败的反例。
可授予徽章：危机判断徽章、逻辑守卫徽章

第 7 章：任务清单与函数工厂（第 13-14 课）
----------------------------------
剧情任务：任务越来越复杂，学生需要用列表管理多个目标，用函数封装可复用技能。
核心知识：
- 列表
- 遍历
- 字典
- 函数
- 参数
- 返回值
- 复用
互动玩法：
- 能量点清单：每组把多个能量坐标做成列表，按顺序派发任务。
- 函数工厂：每组生产一个通用技能函数，其他组必须调用它完成任务。
- 参数盲盒：老师给不同参数，学生预测同一个函数会走出什么路线。
课堂任务：
- 用列表保存多个坐标，并说明遍历顺序。
- 写一个带参数的函数，例如 moveSteps(n) 或 collectLine(n)。
学生产出：函数说明书：函数名、参数、功能、示例调用、返回结果或执行效果。
可授予徽章：清单管理徽章、函数工程师徽章

第 8 章：飞船协作与终极救援（第 15-16 课）
----------------------------------
剧情任务：Neo 需要和 Spaceship、Flyer、Solar 等工具协作，完成综合挑战并设计自己的关卡。
核心知识：
- 对象
- 属性
- 方法
- 多对象协作
- 等待同步
- 综合算法
- 项目展示
互动玩法：
- 角色分工战：舰长负责目标，导航员负责路线，工程师负责代码，调试官负责失败记录，讲解员负责展示。
- Boss 关卡：老师设置一个综合任务，要求用路线规划、循环、变量、条件和函数至少三种能力。
- 学生出题：每组设计一张小地图，写出规则、限制和参考解法，让其他组试玩。
课堂任务：
- 完成一次综合挑战，并提交代码、路线图、调试记录。
- 设计一个原创关卡：目标明确、限制清楚、至少包含一个可调试陷阱。
学生产出：毕业项目包：原创关卡 + 解法说明 + 展示讲稿 + 同伴评审表。
可授予徽章：协作驾驶徽章、终极救援徽章、关卡设计师徽章

六、24 课时扩展版
====================
扩展原则：在 16 课时基础上增加“挑战课、创作课、展示课”。
- 第 17 课：循环迷宫挑战，重点训练嵌套循环。
- 第 18 课：变量与能量状态挑战，重点训练状态变化表。
- 第 19 课：红色能量避险挑战，重点训练条件与逻辑。
- 第 20 课：坐标列表挑战，重点训练列表和遍历。
- 第 21 课：函数工具箱挑战，重点训练参数化复用。
- 第 22 课：飞船/飞板协作挑战，重点训练对象协作和等待同步。
- 第 23 课：学生原创关卡工作坊，重点训练规则设计和测试。
- 第 24 课：星际编程展，学生展示原创关卡、讲解算法、接受同伴试玩。

七、每节课推荐结构
==================
- 5 分钟：剧情导入。用一句故事说明今天为什么要学这个知识点。
- 8 分钟：真人或纸面互动。先让学生用身体、卡片或路线图理解问题。
- 12 分钟：教师微讲。只讲本节课必需概念，不提前灌太多语法。
- 20 分钟：小队闯关。学生画路线、写代码、运行、记录失败。
- 8 分钟：展示与复盘。让学生讲“我改了哪里，为什么这样改”。
- 2 分钟：徽章结算。表扬具体能力，例如“你今天调试记录很清楚”。

八、课堂互动工具包
==================
- 指令卡：前进、后退、左转、右转、等待、重复、如果、函数。
- 地图格纸：用于学生先画路线再写代码。
- 失败卡：步数出错、能量耗尽、红色能量、漏收集、不能通过、飞板限制。
- 职业牌：舰长、导航员、工程师、调试官、讲解员。
- 徽章贴纸：方向感、路线规划、循环、坐标、变量、逻辑、函数、协作、创作。
- 复盘单：目标是什么、第一次失败在哪里、改了什么、学到了什么。

九、分层教学设计
================

基础学生
--------
- 目标：能读懂地图，完成短路线，愿意调试。
- 支持：提供半成品路线、指令卡、坐标提示、同伴导航。
- 评价重点：敢尝试、能说出失败原因、能完成一个小目标。

中等学生
--------
- 目标：能独立规划路线，使用循环、变量和条件。
- 支持：给开放地图，让他们比较不同方案。
- 评价重点：代码结构、调试记录、路线优化。

进阶学生
--------
- 目标：能使用列表、函数、多对象协作，并设计原创关卡。
- 支持：给附加限制，例如更少步数、更少代码、更强通用性。
- 评价重点：抽象能力、复用能力、讲解能力、出题能力。

十一、最能调动兴趣的课堂活动
============================
- 真人地图闯关：学生亲自扮演 Neo，比直接讲前进转向更容易兴奋起来。
- 调试侦探社：把错误变成案件，让学生找线索，而不是被错误打击。
- Boss 关卡挑战：每几节课来一次综合任务，让学生有升级感。
- 学生出题互坑：学生自己设计地图和陷阱，给同学试玩，参与感非常强。
- 徽章技能树：让每个孩子都能看到自己点亮了什么能力。
- 路线辩论赛：同一关不同解法，辩论哪一个更短、更稳、更容易读。
- 代码发布会：让学生像工程师一样讲自己的算法，而不是只交作业。

十二、教师使用建议
==================
- 不要一开始就追求最短代码。先让学生跑通，再讨论优化。
- 每次失败都要求写一句“失败告诉我什么”，把挫败感变成线索感。
- 小队角色要轮换，避免总是强学生写代码、弱学生旁观。
- 展示时不要只展示成功作品，也展示一次典型失败和修复过程。
- 每 4 课安排一次复盘墙：本月学会的指令、最常见错误、最喜欢的关卡策略。
- 如果课时紧，优先保留真人地图、调试侦探、Boss 关卡、学生出题四个活动。

十三、课程命名与班级氛围包装
============================
- 班级名称：星际救援编程营。
- 学生身份：Neo 指挥官、星图导航员、能量工程师、逻辑守卫、关卡设计师。
- 课程主线：从迫降飞船出发，收集能量，修复系统，穿越危机，最终设计自己的星际关卡。
- 结营仪式：每组展示原创关卡，其他组试玩并投票：最有趣、最巧妙、最清晰、最有挑战。

十四、一句话课程理念
====================
让学生先像玩家一样兴奋，再像工程师一样思考，最后像设计师一样创造。
